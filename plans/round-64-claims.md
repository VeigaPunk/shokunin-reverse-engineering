## Why this claim (evidence)

The rounds 50–63 spent their claims on receipt-corpus bookkeeping. The frontier this lane names in PROVINCE.md is `.jsc` → source mapping ("the next frontier is a View8/jsc2js-style mapper"). The merge package from shokuknow stages `jsc-mapper-cli-contract` (S125 in its registry, claim "approximate JavaScript"). Pre-freeze probes on 2026-11-03 (receipts in `.ufo/waves/round-64/l1/prefreeze-probe/`) showed three things that the staged claim does not state:

1. Electron 42.2.0 (V8 `14.8.178.14`, verified by reading the version string out of the downloaded Electron binary) and the jsc2js release `14.8.178.14` are the same V8 build. The matched d8 loads a cache generated by that Electron (`dump-ok`, 2882 bytes of SharedFunctionInfo text).
2. The same d8 crashes with SIGABRT (134) on the shipped Typora `atom.compiled.dist.jsc` (sha256 `6a0cb7b3…`), a cache whose version and flag-hash words match the probe. The crash is an artifact-level outcome, not a version mismatch.
3. View8's output on the probe dump is 213 bytes of Ignition pseudo-code (`ACCU = ConstPool[1:"add"](1, 2)`) and does not parse as JavaScript (`node --check` fails). "Approximate JavaScript" in S125 is therefore not a description of the output's syntax.
4. A same-minor neighbour build (14.8.178.1) also loads the probe cache, and the cross-minor build (14.7.173) segfaults (139) on it. The version lock is demonstrated across minors, not across build numbers.

## Claim R64-C1 — depth, capability acquisition

**Capability:** the `.jsc` route outcome triage v1 — a reproducible 18-run matrix (2 artifacts × 3 d8 builds × 3 repetitions) that records, per cell, the dump outcome, the View8 outcome and whether the reconstruction parses as JavaScript, with every binary and input pinned by sha256.

**Predicate (the same sentence in claims.json, the tool's PREDICATE constant and the receipt):**
R64-C1 is verified iff all 18 runs reproduce the frozen predicted label of their cell (dump|view8|check), with every input and binary sha256 equal to its pin.

**Counting command (paste-able):**
```
python3 tools/round-64/jsc-route-matrix.py --probe <probe.jsc> --typora <typora.jsc> \
  --d8-match ~/.local/share/kaidoku-jsc/d8-14.8.178.14 --d8-neighbour ~/.local/share/kaidoku-jsc/d8-14.8.178.1 \
  --d8-cross ~/.local/share/kaidoku-jsc/d8-14.7.173 --view8-dir ~/.local/share/kaidoku-jsc/jsc2js-src/View8 \
  --python ~/.local/share/kaidoku-jsc/venv/bin/python --node node --work <scratch>/matrix --out <receipt.json>
```
Exit 0 = verified (18/18). Exit 1 = any mismatch. Exit 2 = a pin or input is missing (could-not-evaluate).

The matrix therefore measures the reproducibility of the four observed cells (three repetitions each) and tests the two unobserved predictions, the View8 output class and the node-parseability claim in all dump-ok cells.

**Controls (scored before data):**
- do-nothing (no d8 run): `--skip-run` → 0/18, exit 1 (`.ufo/waves/round-64/l1/c1-before-donothing.json`). A do-nothing arm cannot reach the target.
- fake green (every run labelled dump-ok|view8-ok|node-pass): 0/18 (selftest `verdict-fake-green-count`).
- one-off mismatch in one repetition: 17/18, exit 1 (selftest `verdict-one-mismatch-count`).
- pins: a wrong or missing artifact or binary exits 2 before any run (selftest `pin-*` cases).

**Kill rule:** any single run whose label differs from its predicted label makes R64-C1 unverified. A failed pin is could-not-evaluate, never a pass. No predicted label is revised after a run; a mismatching cell is reported as a finding in the lesson and the SCORECARD.

**Target:** 18/18 runs matching, exit 0.

**Not claimed:** that the Typora crash is a defect of the Typora cache (the tool proves only that the matched d8 crashes on this artifact); that View8 output is a semantic reconstruction; any mapping of Typora's application code; any v8 version beyond the three builds named; any runtime behaviour of the Typora application.
