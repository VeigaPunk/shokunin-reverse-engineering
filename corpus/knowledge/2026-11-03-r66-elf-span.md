# Static virtual-span provenance, not loader simulation

[OBSERVATION] Source defines two separate origins for each LOAD segment: file offset and link-time virtual address. The initialized prefix has filesz bytes; any remaining memsz portion is conceptual zero-fill. Filesz cannot exceed memsz. Source also requires ascending LOAD addresses and power-of-two alignment/congruence when alignment exceeds1. No target page size is inferred from p_align.

[INFERENCE] A bounded byte query can cross file-prefix, zero-tail, gap and multiple segment boundaries. Partitioning at every relevant boundary prevents an endpoint-only or single-delta shortcut from silently inventing file provenance. The standalone reader deliberately preserves each covering segment ordinal; two candidates stay ambiguous even when their source bytes agree. That is a conservative provenance policy, not a specification assertion about loader precedence.

| Question | Decision | Scope |
|---|---|---|
| Exactly one LOAD covers the interval and it is inside its file prefix | offset=p_offset+(query_address-p_vaddr), hash only that source interval | File-backed observation, not executed bytes |
| Exactly one LOAD covers interval after its filesz endpoint | zero candidate, no file offset or hash | Conceptual initialization, not memory inspection |
| No LOAD covers interval | unmapped, no candidates | Never silently fill the gap |
| Several LOADs cover interval | ambiguous, all candidates in physical header order | Even equal bytes have separate provenance |
| Query crosses boundary | split interval; never coalesce redundant cuts | Preserves explainable derivation |
| Section metadata disagrees or is absent | ignore it in this declared profile | Does not establish full ELF validity |
| Runtime address supplied without load bias evidence | unsupported interpretation | CLI accepts link-time addresses only |

[UNKNOWN] Dynamic relocations, actual page mappings, ASLR/load bias, instruction meaning, permissions after loading, section correctness, processor-specific ABI validity and runtime acceptance are not established. phnum0 with nonzero phoff is tolerated by local no-table traversal policy although the source says phoff0 denotes no table.
