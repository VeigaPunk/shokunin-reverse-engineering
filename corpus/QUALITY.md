# kaidoku-shokunin — Quality bar

What good looks like in reverse engineering of shipped artifacts with REA on this Linux host — native ELF/PE through the Ghidra 12.1.4 provider, Electron/ASAR/JavaScript bundles, archives and packages, managed assemblies, firmware images and recorded crashes; evidence-first static analysis that keeps observation, inference and unknowns separate (LEARNING.md). Thin at mint and grown only from lessons:
every criterion cites the lesson that produced it. A criterion is replaced by a new row
naming the row it supersedes, never rewritten.

- **Row 151 (a registered gate row is run by its declared command, and the command must name the registered tool).** A SKILL instrument-registry row whose self-test command is not on the tool it registers is decoration. A counter that re-derives such a row must refuse a foreign command, and its verdict-map test must match the exit declaration, not a substring of it. Evidence: round-86 M86-2; `.ufo/waves/round-86/l1/sweep/g3-behavioural-red.txt` (a foreign `python3 -c` row is accepted at 5/5, so the clause is red on the frozen counter); `.ufo/waves/round-86/l1/scores/c2-at-integration.json`. - **Row 152 (a capability claim's cheap-rule controls include a heuristic variant of the claimed tool, scored before the freeze).** A do-nothing control and a token-replacement rule are not enough to show that a frozen counter forces the claimed technique: build the cheapest variant that keeps the claimed anchors but drops the costly step (here: the b_info chain walk), score it with the frozen counter, and commit the receipt with the declaration. Evidence: round-87 M87-3; `.ufo/waves/round-87/w1/CriticClaim/receipts/cheap-v4-checksum-lite-rea.json` (8/8 with REA, outputs byte-identical to the committed repair). - **Row 153 (a registry row names a document that was opened; a correction is not a source row).** A `corpus/SOURCES.md` row added or changed in a round carries a locator in its source cell, an ISO opened date, and no "no document opened" text; lane-internal corrections are recorded in the lesson, not as registry rows. Check: `python3 -I -B tools/round-87/registry-opened-check.py --root . --base <round base> --rev <tip>` exits 0. - **Row 154 (a tamper cell is "tolerated" only if the bytes actually changed).** An instrument that writes a fixed zero pattern into a field and reports `upx -t` rc 0 as "tolerated" conflates two states: UPX ignores the field, and the field was already zero so nothing was tampered. Every cell records the pre-tamper bytes and the instrument carries a `noop` class decided before the run; a no-op cell is never counted as a tolerated field and the receipt reports `effective_cells` beside the total. Round-88 case, judged by this row: `tools/round-88/field-tamper-matrix.py` labelled 5 of 68 cells (all `l_info.l_size`, plus `ph.filter` on a carrier with no filter) `tolerated`; `field-tamper-matrix-v2.py` labels them `noop` (63 effective of 68) — `corpus/lessons/round-88.md` M88-1.

- **Row 155 (a refusal vocabulary that meets a real message it does not know reports it, and the evidence arm counts it).** A classifier with a closed label set must emit an `other-refusal` class with the verbatim message rather than fold the cell into a neighbouring class, and a claim whose evidence is that matrix must state the unclassified count: zero unclassified is the target, and a nonzero count is reported, never dropped. Adding a class is an instrument revision with a re-taken before record, not a silent edit of the frozen bytes. Round-88 case: v1 left 5 cells `other-refusal` (`bad method 0 at 0x…` ×4, `IOException: bad seek` ×1); v2 added `bad-method` and `bad-seek` and the 68-cell receipt now reports 0 unclassified — `corpus/lessons/round-88.md` M88-2.

- **Row 156 (a routing-table row names the field its move applies to, and what happens to the other field under the same label).** A refusal label that covers two fields routes both cells to one move unless the row disambiguates: `upx -t` answers `b_info corrupted` for a zeroed `sz_unc` and for a zeroed `sz_cpr`, and only the second is recoverable from chain geometry — the first has no redundancy and the repair must refuse. Round-88 case, judged by this row: craft rule block 28's `b_info corrupted` row named both fields with one move (`corpus/lessons/round-88.md` M88-5); the correction lands as the next block revision, because the frozen C2 kill rule forbids editing block 28's text after the declaration.

- **Row 157 (a counter's target is an argument, not prose).** A counter that reports a number and a `met_target` derived only from "no unresolved item" cannot distinguish the base state from the claimed after-state: it exits 0 at both. The target count is a required argument (`--expect-blocks N`), `met_target` is `counts == target` on every arm, and the base arm plus a citation-only stub are red controls in the same selftest. Round-88 case: `tools/round-88/depth-blocks.py` reports `met_target true` with 27 blocks at base and with a one-line citation-only block at 28 (`corpus/lessons/round-88.md` M88-7).

- **Row 158 (a counter never places the answer in the repair's input directory).** A repair command scored on a tampered file must see only that file: a harness that writes the intact `packed` original, its own outputs or the repaired sibling beside the `--in` path lets a copy-only "repair" score the target. - **Row 159 (a claim declared causally separable cites only documents that exist at the base).** When a round says claim B is verifiable without claim A, B's landed artifact may cite only paths present at the base revision: a citation to a document A creates makes B's measurement depend on A. - **Row 160 (a cost bound is measured on a crafted worst case, not asserted).** A scan whose cost depends on an attacker-controlled count states its bound from a measured curve: the same input family at three sizes, the wall time, the exit and the refusal text. "Linear per item" prose that omits the item count is not a bound. Round-88 case: `tools/round-88/upx-chain-repair.py` costs 1.02 s / 14.22 s / 221.85 s at 800 / 3,200 / 12,800 crafted `l_info` candidates (25 KB to 400 KB), each refusing only after the scan (`corpus/lessons/round-88.md` M88-10).

- **Row 161 (a repair that supersedes an earlier one composes it, and the composition is a frozen arm).** A new capability that re-implements the previous round's path silently drops the class the previous round repaired: the first round-89 candidate scored `recovered 4 of 4` on its own class with every control true while the round-88 class regression arm was unmet (`recovered 0 of 4`), because it derived the field without running the round-87 anchor path first. - **Row 162 (an instrument's docstring states the rule its code applies, at the same revision).** A correction written into a lesson or a routed-defect list does not repair the docstring the next reader trusts: the round-88 repair's module docstring still described "the smallest offset above `block0 + 12` … requires `0 < sz_cpr <= sz_unc`" and preferred candidates whose `l_info` carries `p_filesize == u_file_size`, while the code keys on `(fits, total, -derived)` and treats that equality as a hard precondition — the rule M88-3 recorded as wrong, left standing in the file it was written for. - **Row 163 (a scored repair sees only the file it must repair).** A harness that writes the intact original, its own outputs or a repaired sibling into the same directory as the repair's input lets a copy-only "repair" score the target. Each invocation gets a private directory holding the tampered input alone, and the counter records the directory listing each invocation saw as an `isolation` control that `met` requires. Round-89 case: `tools/round-89/upx-field-battery.py` (`apply_repair` → one `mkdtemp` per call; control `isolation`), which makes the round-88 sibling-copy cheat (`w1/CriticClaims/receipts/cheat-c1-sibling-v2.json`) unscoreable.

- **Row 164 (a field class is defined by its value domain, not by the refusal string).** Two tampers that answer the same message are different classes when their value domains differ: a zeroed `sz_cpr` and an in-range wrong one both fail, but the first answers `CantUnpackException: b_info corrupted` and the second `Exception: compressed data violation` — the wrong value passes every bound the packer applies to the field and fails only at the payload stage. Round-89 case: `.ufo/waves/round-89/pre/c1-base-r88-repair.json` (`precondition.tail` per carrier) and `.ufo/waves/round-89/l1/scores/block29-cells.json`.

- **Row 165 (a field the packer tolerates is not a no-op, and "tolerated" is not "harmless to the lane").** `upx -t` answering rc 0 after a byte changed means the packer does not consult that field on that carrier, not that the change is inert: a tampered `l_info.version` or `l_info.format` passes `upx -t` (`Tested 1 file.`) yet breaks the lane's own locator, which cross-checks those bytes, so the repair refuses it. Report the cell as tolerated, name the consumer that does care, and never fold it into the `noop` class (whose definition is "the bytes were already equal"). Round-89 case: `.ufo/waves/round-89/l1/scores/block29-cells.json` (`l_info.version^=0xFF` and `l_info.format^=0xFF`, rc 0 on both carriers).

- **Row 166 (a class's refusal signature is stated per carrier when the gate that fires depends on the layout).** A routing table that gives one message per class is wrong when the packer's gate selection depends on the carrier: `sz_cpr = sz_unc + 1` answers `CantUnpackException: header corrupted` on jq, xxd and docker-init but `corrupt b_info` on the shared object, because the arithmetic check that fires first differs between the executable and shared-object unpack paths (S311). - **Row 167 (a repair's exit code means "I changed the field I own", not "the file is fixed").** A tool whose remit is one field returns 0 on a tamper in another field, because there is nothing in its remit to change: the round-89 repair exits 0 on a `b0.method` or `p_info.p_blocksize` tamper with the stored `sz_cpr` already correct, while `upx -t` still fails.
