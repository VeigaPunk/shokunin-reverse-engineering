# Round 4 lessons (2026-10-13) — audit + expansion + unlock wave

## From the audits (r3 claims re-verified)

- **`grep -c` counts lines, not occurrences.** Every recorded count verify on a
  minified file must be `grep -o … | wc -l`. The renderer-asar claims all held;
  two of its verify recipes were wrong as written. (QUALITY #13)
- **Re-synthesized carriers are shape-reproducible, not byte-identical.** The
  NSKeyedArchiver recipe yields 363B on re-run, not 365B; evidence ids differ.
  Pin claims to fixture bytes; recipes get "reproduces in shape". (#12)
- **Evidence ids are `f(content, path, params)`** — deterministic on same-path
  re-runs (`inspect-artifact`, `trace-application-feature`, `rea analyze`
  all re-minted identical ids), but the same bytes elsewhere mint a new id
  (revenger verifier `ev_8efa2368`→`ev_50038b96`; jadx mkdtemp per-run ids vs
  apktool deterministic). "Content-addressed" was shorthand, not the full
  domain. (#14)
- **`inspect` ≡ `analyze`** — byte-identical evidence hash on same input.
- Small drifts: EVM `bytecodeOffset` = jump-dest not PUSH4 site; typora ratio
  99.38%; list-* census 11 verbs + 3 MCP-only; resource-constraint census 29;
  weak dylib edges are `undetermined`, not omitted; AppImage bad-address
  envelope is `invalid_request` with `invalid_format` reason.

## From expansion

- **`.jsc` decompilation-adjacent recipe**: `ELECTRON_RUN_AS_NODE=1` with an
  electron whose V8 matches the target's (typora V8 14.8 → electron 42.2.0;
  host node V8 13.6 rejects the cached data) → `--print-bytecode` yields real
  Ignition disassembly. Source mapping remains frontier.
- **1Password** is a hardened thin shell (strict CSP, sandbox, killed network
  session) forwarding ~80 typed/GraphQL IPC commands behind a single `file://`
  prefix check to a 188MB unstripped Rust N-API core.
- **Provider-timeout is an internal ~900s session deadline**, not the outer
  `timeout` — 91.6MB ARM64 PE was still progressing at kill (RSS 2.36GB, not
  OOM). Envelope traced to `GhidraClient.js:607`.
- **Scale measurement under contention**: 3+ sibling Ghidra JVMs skew timing
  measurements — record fleet contention when benchmarking.

## From the unlock wave (operator-authorized installs)

- **The provider-gate diagnosis recipe**: `capability_unavailable` → find the
  env key → find REA's spawn wrapper in `dist/` → minimal repro outside REA.
  Wakaru's "OOM" was `prlimit --as=1GiB` vs a node shim that needs >1GiB to
  init V8; binding the `@wakaru/cli-linux-x64` ELF fixed it end-to-end.
- **Pacman artifacts aren't always REA-compatible**: distro `jadx.jar` lacks
  the MCP bridge classes — the specific `jadx-headless-mcp-0.7.1-all.jar`
  (sha256-pinned from upstream releases) is required.
- **unblob carves where binwalk sees nothing** (pacman .pkg.tar.zst 100%
  identified vs 0 signatures); each extractor has blind spots — keep both.
- **Two-tool managed map**: REA managed verbs cover `0x14c`/`0x8664` under a
  hardcoded 64MiB representation budget; `dnfile`+`dncil` covers everything
  including the REA-refused `0xfd1d` class (2,594/2,594 + 650/650 bodies).
- **adb has exactly 2 serial-free verbs**; dead-serial taxonomy mapped
  (`unsupported_target`/`unreadable_output`/VALIDATION_ERROR/`collect-
  adb-bugreport` blocks ~10min).
- **RISC-V is REA's own preflight gate**, not Ghidra's — `target_unavailable`
  on outer and carved EXECs while a RISCV processor module ships. Provider
  layer open ≠ deep analysis open.
