# Round 1 lessons — kaidoku-shokunin (2026-10-13)

Sixteen parallel curation lanes over REA/host surfaces. Evidence:
fleet `.ufo/waves/kaidoku-r1/*.md`; corpus entries `corpus/knowledge/2026-10-13-*`.

## Process lessons (how the lane learns)

- **Deliberate rejects are calibration assets.** Lanes 03, 09, 11 each recorded a
  falsified naive reading (`rea` on PATH because doctor lists an install path;
  ELF entry point = `main`; `asar extract-file` streams to stdout). Keeping
  rejects in the corpus is how discernment gets checked — never strip them.
- **`--schema` beats `--help` for catalog work.** Every REA verb emits a typed
  JSON-Schema contract (`required`, `enum`, `pattern`, defaults); help prose is
  the cross-check, not the source. (Wave 01, lesson candidate — admitted.)
- **Batch npx, don't per-command it.** `npx -y rea-agents@6.4.0` re-resolves the
  package per invocation; bulk cataloging should hold one shell or use
  `npx --package`. (Wave 01.)
- **Dispatch-scope beats ambient rules.** Lane 04 hit an injected AGENTS rule
  demanding a LOG.md entry while its dispatch forbade touching other files; it
  obeyed the dispatch and flagged the conflict. Correct call — the integrator
  owns LOG.md this round; future dispatches should name LOG.md explicitly.
- **`/tmp/rea-ghidra-*` is a shared namespace.** A concurrent `rea mcp` session
  held a live dir during round 1; a lane must never treat another session's
  dir as an orphan to clean. (Wave 10.)

## Domain lessons (what the lane now knows to watch)

- **`doctor healthy:false` ≠ surface-blind.** Overall health is driven only by
  unscoped `config_drift` checks (skill destination + 5 missing registrations);
  unconfigured providers are excluded and Ghidra alone clears the engine floor.
  Read `scope_checks[]`, not the top-level bool. (Wave 03.)
- **`skill: stale` can mean a missing per-client copy, not drift.** The shared
  `~/.agents/skills` copy is byte-identical v37; `canonical` spans every
  registered client's destination and `claude_code` maps to `~/.claude/skills`.
  (Wave 03.)
- **`asar extract-file` writes into cwd.** Not a stdout streamer — extraction
  must run inside a scratch dir. (Wave 11; enforced by weak-signal discipline.)
- **`file(1)` misses valid ASAR.** Obsidian's `app.asar` reports `data` while
  parsing fine; enumerate by glob + pickle header, not magic. (Wave 11.)
- **ASAR surveys must glob `*.asar.unpacked` too.** Native `.node` ELF modules
  live outside the archive — the ASAR surface has a Ghidra fringe. (Wave 11.)
- **Registration is a pinned npx invocation, not an installed binary.** The
  fragility: `npx` resolves via a session-scoped fnm shim under
  `/run/user/1000` — a client spawned outside an fnm-initialized shell can't
  launch the server. (Wave 04.)
- **`--snapshot` persists evidence, not the Ghidra DB.** Snapshot-loaded runs
  still pay full ~5s re-import; sessions are `mkdtemp` + `-deleteProject`,
  self-cleaning on close. (Wave 10.)
- **`inspect-binary-layout` is blocked on an operator-owned prerequisite.**
  `REA_PWNTOOLS_PYTHON` needs pwntools 4.15.0 + pyelftools 0.33 + Unicorn 2.1.2;
  REA never installs Python. Typed `provider_unavailable` in 0.66s. (Wave 10.)
- **`inspect_managed_artifact` rejects AnyCPU assemblies.** `unsupported PE
  architecture` on real `Microsoft.*.dll` — managed RE here is bounded to
  supported-arch assemblies; no SDK/decompiler on host. (Wave 13, 16.)
- **Verify-then-disassemble is the baseline.** Installed `/usr/bin/jq` is
  byte-identical to its signed pacman archive member (`pacman -Qkk` clean) —
  only divergent or unowned bytes (e.g. `~/.local/bin/jq`, unowned static
  shadow, same `jq-1.8.2` version) warrant lifting. (Wave 12.)
- **Crash evidence decays oldest-first.** systemd-coredump is the sole
  collector (174 zstd cores, ~4.0 GB); oldest COREFILE already `missing`.
  Time-boxed surface. (Wave 14.)
