# Round 3 lessons (2026-10-13)

Audit + expansion wave. Round 2 survived re-verification with only mechanistic
errata; the new operational knowledge below is what the expansion lanes learned.

## CLI argument patterns (verified r3)

- **Several verbs take positional args despite `--schema` listing them as
  properties**: `inspect-evm-interface <path> <raw|hex>` (no `--encoding`),
  `inspect-keyed-archive <path> [archive]` (no `--archive`),
  `read-bytes`/`address-to-file-offset`/`xrefs` (address positional).
  Passing `--flag` instead fails `Unknown flag` (exit 1). Always try the
  positional form first; the schema's JSON properties describe the *input
  object*, not argv.
- `search` requires a pattern: bare `--kind procedures` → `invalid_input`;
  use `--mode regex --pattern '.*'` for full enumeration.
- Workflow `inputJson` refuses `/dev/stdin` (`ENOTFILE invalid_request`) —
  pass a real file or inline JSON.
- `read-bytes` segment addressing is `<space>:0x<hex>` (e.g.
  `unallocated_0:0x0`); `:0000`/`::0x0` are `invalid_format`.
- `--token-limit` rejects structured-json output on huge results — use
  `--filter-output` or `--format toon` for big bundles.

## Addressing & evidence model (verified r3)

- **Ghidra rebase is +0x100000 relative to `nm` vaddrs** — confirmed on
  `.so` (libjq) AND `.node` (btime) and via `address-to-file-offset`
  (0x117070 → file offset 94320 = 0x17070).
- **Evidence ids are content-addressed and reproduce across sessions** —
  re-analyzing the same artifact mints the identical `ev_*` id (libjq
  `ev_bf0875fae37e…`, jq-shadow `ev_95ccd1f3…`, obsidian census identical).
- MCP retention is **epoch-scoped, cross-target**: `close`+`open` evicts
  prior-target records *unless* cited via `evidence_links` (a verdict that
  cites them keeps them pageable). `inspect_analysis_view` pages only
  `inspect_binary_layout`/`analyze_javascript_application`/`analyze_function`
  parents — refuses `binary_overview` parents with `unsupported_target`.
- `compare_bundles` `status:changed` requires ALL bundle members paired;
  partial pairing → `unknown` with `unresolved:N` (r3-14).

## Provider/failure semantics (verified r3)

- `capability_unavailable` and `provider_unavailable` BOTH exit 1 — the
  differentiator is `retryable:false` vs `true` (corrects r2 matrix claim).
- Exported-symbol internal calls are GOT-indirect: `objdump` direct-call grep
  finds zero callers where `xrefs` finds 23 GOT call-sites + 2 DWARF unwind
  refs — never claim "no callers" from objdump.
- `list-architectures` is Mach-O-only (clean `unsupported_provider` on ELF).
- `xrefs` is inbound-only; outbound = `function.outgoing_references`.

## Operational (verified r3)

- `pkill -f <flag-string>` self-matches the calling shell — use bracketed
  patterns (`[c]hromium`) or PID-exact kills for cleanup.
- Runtime-obs needs a bound debug port; the recipe is self-launch:
  `chromium --headless --remote-debugging-port=9222 --user-data-dir=/tmp/...`
  and `xvfb-run electron --remote-debugging-port=9223` (electron needs a
  display + synthesizes `~/.config/<appname>`).
- JS single files >~3.9MB OOM the semantic worker even at `--max-heap-mb
  8192` — coverage is budget-variable but the security surface was identical
  across budgets (deterministic surface). Workaround: extract +
  `--artifact-format directory` per-file, or `REA_WAKARU_COMMAND`.
- AppImage `--appimage-offset` = end of ELF section-header table
  (e_shoff + 32×entsize on this sample); REA sees ELF only, payload readable
  via `read-bytes` on the `unallocated_0` segment; `extract-artifact` has no
  ELF reader.
- Magic bytes false-positive: a 1.7KB bin with `0xCAFEBABE` was typed
  `mach-o-universal` in an APK graph — magic ≠ format.
