## F1 — FALSIFIED: exit 0 `clean` while a frozen path changed (replace refs)

`frozen-path-preflight.py:46-47` runs every git child as `git -C <root> …`; neither
`--no-replace-objects` nor `GIT_NO_REPLACE_OBJECTS` is set anywhere in the file.

Fixture (`fx/g2`, dir freeze): freeze commit with `tools/round-45/frozen.py = "v1\n"`;
next commit sets it to `"CHANGED-BY-REPLACE-TEST\n"`; then one command
`git replace <rev> <commit-tree <freeze-tree> -p <freeze>>` (rc 0, `git replace -l`
lists it).

```sh
python3 -I -B gate.py --root fx/g2 --freeze <FREEZE> --rev <REV> \
  --pathspec tools/round-45/ --freeze-path tools/round-45 --require-pathspec
# exit 0, {"verdict": "clean", "touched": [], "blob_changed": [], "restored": []}
```

Ground truth in the same repo, same tree:

| probe | with replace ref | `git --no-replace-objects` |
|---|---|---|
| `log -m --diff-merges=first-parent --name-status FREEZE..REV -- tools/round-45/` | *empty* | `M tools/round-45/frozen.py` |
| `rev-parse REV:tools/round-45/frozen.py` | `626799f…` (= freeze blob) | `8d95c62…` |
| `rev-parse REV^{tree}` | `0790824…` (= freeze tree) | `28d1cfa…` |
| worktree bytes of `tools/round-45/frozen.py` | `CHANGED-BY-REPLACE-TEST` | same |

This falsifies **both** arms that carry the claim: row 1 (`SKILL.md:586`, commit arm) and
row 3 (`SKILL.md:588`, "a frozen path's blob at REV differs from its blob at FREEZE → 1").
The blob *does* differ; `rev-parse` is reading a replaced object, so the arm sees freeze
bytes on both sides. The directory-tree backstop (`frozen.add(fp)` at `:114`) is defeated by
the same mechanism, because `rev-parse REV:dir` also honours the replacement.

Second instance, file freeze only (`h2`, `plans/claims.md`, no directory entry to fall
back on): exit **0 clean** (`475c0862b4e70eea`). So the blob arm on its own is replace-blind.

Severity **high** for the arm's guarantee, likelihood low-to-moderate: `refs/replace/*` is a
normal repo-local ref that one git command creates, and the party this gate is meant to
police (a non-author writer with repo write access — the M44-2 shape, `corpus/lessons/round-44.md:18`)
is exactly the party able to create it. Impact: a frozen instrument can be edited after the
freeze and still be reported admissible, which is the one thing R45-C1 claims to prevent
(`plans/round-45-claims.md:143-146`, "a score at `REV` is admissible only if no commit in
`FREEZE..REV` touches a frozen path"; the landed surface at `:41-44`).

**Smallest remediation — tested, not proposed on faith.** One line in `git()`:

```python
return subprocess.run(["git", "--no-replace-objects", "-C", root, *args],
                      capture_output=True, text=True)
```

Patched copy `gate-noreplace.py` (name in scratch only, never the frozen path):

| run | unpatched | patched |
|---|---|---|
| `--selftest` | 11 cases, 0 failures | 11 cases, 0 failures (`h0`, `9f03df6538de49b7`) |
| `fx/g2` (dir freeze + replace) | exit **0 clean** | exit **1**, `touched=[{commit:2beaec7, path:tools/round-45/frozen.py, status:M}]`, `blob_changed=[tools/round-45, tools/round-45/frozen.py]` (`h1`, `fcc6aa7b1e40e9d3`) |
| `fx/h2` (file freeze + replace) | exit **0 clean** | exit **1**, `touched=[{…plans/claims.md…M}]` (`h2b`, `5793292a40a579e0`) |
| real lane, `FREEZE..HEAD` | exit 0 | exit 0, `touched=[]` (`h5`, identical sha to `g4`) |

The patched gate must also gain a red case, or the fix is as untested as the hole:
`case("red-replace-ref", 1, ...)` building exactly `fx/g2`. `R45-C1` predicate clause 6
(`cases >= 11`) would then be met at 12.

## F2 — FALSIFIED: exit 1 `frozen_path_changed` on a tree where no frozen path changed

`--pathspec` is optional (`:290`, `action="append", default=[]`), and with no pathspec
`scope = []` (`:92`), so `git log --name-status FREEZE..REV` lists **every** path in every
commit; `touched` is then non-empty for any non-empty range and `ok` (`:142`) is false.

Fixture `fx/e9`: frozen dir `tools/round-45/` untouched; one commit changes only
`other.txt`; no `--pathspec`, no `--require-pathspec`.

```sh
python3 -I -B gate.py --root fx/e9 --freeze <FREEZE> --rev <REV> --freeze-path tools/round-45
# exit 1, {"verdict": "frozen_path_changed",
#          "touched": [{"commit": "aaf9ef2…", "path": "other.txt", "status": "M"}],
#          "blob_changed": [], "restored": [], "dirty": []}
```

This is a direct falsification of row 10 (`SKILL.md:594-595`): the row's trigger is "no
touch, no dirty file and every frozen blob equal" with exit `0`; all three of its conditions
hold here and the gate returns 1. Row 9's "all arms → 0" has the same exposure. The
docstring's `Exit codes: 0 clean; 1 violation` (`:22`) is therefore wrong for the documented
default invocation. It is also inconsistent with row 5's promise that "a whole-tree scan is
refused" (`SKILL.md:590`) — refused only when `--require-pathspec` is also passed.

**Smallest remediation:** when `pathspecs` is empty, filter `touched`/`blob_changed` to
entries under any `freeze_paths` prefix before computing `ok` (keeps row 9/10 true and keeps
the whole-tree scan useful), or make an empty pathspec a hard `2`. Either closes it; the
filter matches the rows as written.

## (a) Merge commits — holds, and the reason is a flag with no test

| fixture | shape | exit | evidence |
|---|---|---|---|
| `a1` | side branch edits frozen path, merged `--no-ff` | 1 | `touched` = merge + side commit |
| `a2` | side branch **tampers then reverts** before the merge; merge tree is TREESAME to parent 1 | 1 | `touched` = 2 side commits, `restored=[frozen/a.txt]` (`60d5a0bb9e9feaf1`) |
| `a3` | evil merge: the merge commit itself writes the frozen file | 1 | `touched` = merge only |
| `a5` | `merge -s ours` drops the side change; tip bytes == freeze bytes | 1 | `restored=[frozen/a.txt]` |
| `a4` | merge in range, nothing frozen touched | 0 | — (no false positive) |

`a2` is the attack: default `git log --name-status FREEZE..REV -- frozen/` prints **nothing**
(history simplification prunes the side branch as TREESAME to the merge result), so without
the chosen flags the gate would report clean. With the flags actually in `:93`
(`-m --diff-merges=first-parent`) both side commits are listed. Flag isolation on the same
fixture: `--diff-merges=first-parent` alone → both commits; `-m` alone → both commits;
neither → **empty**. So `--diff-merges` (not `-m`) is load-bearing, and dropping either is a
silent regression to clean.

| fixture | shape | exit | reason |
|---|---|---|---|

| `f2` | same, side commit touches nothing frozen | 2 | same — 2 is never a pass |

| `b5` | `--rev <sha>^{tree}` | 2 | `unknown rev revision` |

Grafts are safe *because* they break the ancestor guard; replace refs are not, because the
replacement keeps the freeze as an ancestor (F1). Controls `b1`/`b2`/`b3` are
descendant-branch cases (freeze **is** an ancestor) and behave correctly: 1, 0, 1 — they are
not sibling tests and are not offered as such.

## (c) Newline / tab / U+2028 pathnames — verdict holds, receipt is falsified

The log call at `:93-94` uses `--name-status` **without `-z`**, then splits lines at `:99`
and fields at `:100`. Git C-quotes any path containing a tab, newline, quote or backslash, so:

| fixture | exit | recorded path in `touched[]` |
|---|---|---|
| `c1` newline name | 1 | `"frozen/nl\nname.txt"` — the quoted string, not the path |
| `c2` tab name | 1 | `"frozen/tab\tname.txt"` |
| `c5` backslash name | 1 | `"frozen/bs\\name.txt"` |
| `c7` tab name added after freeze | 1 | same quoting, `status A` |
| `c3` tab name tampered then restored | 1 | quoted; `restored[]` is **empty** — the equality test `t["path"] == path` can never match a quoted string |
| `c4` U+2028 name, `core.quotePath=false` | 1 | `frozen/ls` — **truncated**, because `str.splitlines()` (`:99`) breaks on U+2028 as well as `\n` |

The verdict survives in all cases only because `ok` tests emptiness, not identity. Two
consequences are real: (i) the `restored` arm is dead for any path git quotes, so the row-2
guarantee (`SKILL.md:587`) does not extend to exotic names — it is masked by the commit arm,
not covered by the restored arm; (ii) the receipt is not a citable path. Fix: `-z` on the log
and split on `\x00` (`--name-status -z` emits NUL terminators and does not munge), which is
exactly what S141 describes and what the claim says the arm does.

**Record falsification (S141).** `plans/round-45-claims.md:167` states "`--name-status` with
`-z` uses NUL field terminators and does not munge pathnames; the commit arm parses that",
and the gate's own docstring says the same at `:32-33`. The commit arm does **not** pass `-z`;
`grep -n '\-z' tools/round-45/frozen-path-preflight.py` returns only `:137`, the `status
--porcelain -z` call in the dirty arm. S141 is therefore cited for a mechanism the commit arm
does not use — the source row is misattributed, and (c) is the observable consequence.

## (e) Parent pathspecs — falsified in the strict direction, safe in the unsafe one

`covers()` (`:62-65`) is a literal string test: `p.rstrip("/") == fp or p.startswith(fp + "/")`.
It does not normalise, and it does not understand git pathspec semantics.

| fixture | pathspec | git meaning | gate | expected |
|---|---|---|---|---|
| `e5` | `tools/round-45/` | covers | 1 (`touched` + `blob_changed`) | 1 |
| `e1` | `.` | covers (whole tree) | **2** `pathspec_required` | 0/1 |
| `e2` | `tools/` | covers | **2** `pathspec_required` | 0/1 |
| `e3` | `tools` | covers | **2** `pathspec_required` | 0/1 |
| `e4` | `./tools/round-45/` | covers | **2** `pathspec_required` | 0/1 |
| `f6` | `tools/round-45/` with `--freeze-path ./tools/round-45` | covers | **2** `pathspec_required` | 1 |
| `e6` | `tools/round-45/[f]rozen.py` (narrow glob) | matches the changed file only | 1 via `blob_changed=[tools/round-45]` | 1 |
| `e7` | `tools/round-45/[a]` (matches nothing) | matches nothing | 1 via `blob_changed=[tools/round-45]` | 1 |
| `e8` | same narrow glob + `--freeze-path tools/round-45/` | matches nothing | 1 via `blob_changed=["tools/round-45/"]` | 1 |
| `g1` | `tools/` + `:(exclude)tools/round-45/` | hides the dir | **2** `ls-tree at freeze failed` | 1 |
| `e11` | `tools/` without `--require-pathspec` | covers | 1, `blob_changed=[tools/round-44/older.py]` | 1, but attributed to a non-frozen path |

Two distinct defects:

1. **False refusal (e1–e4, f6).** Every one of those spellings covers the frozen directory and
   is refused with 2, so a legitimate landing is blocked. The first four collapse to the same
   verdict hash (`987f30d1c20c15eb`) — one predicate, four spellings. `f6` is the sharpest:
   the same directory spelled `./` in `--freeze-path` and normally in `--pathspec` is
   "uncovered", because `covers()` compares a non-normalised freeze path to a normalised
   pathspec.
2. **False attribution without the flag (e11).** `--pathspec tools/` puts every file under
   `tools/` into `frozen` (`:116-119`) — the pathspec is treated as the freeze scope — so a
   change to `tools/round-44/older.py` is reported as `frozen_path_changed` and lands in
   `blob_changed[]`. Same invocation plus `--require-pathspec` gives 2 instead. The two
   invocations disagree about the same tree.

No false clean was found through the pathspec: the narrow-glob cases are caught by the
directory-tree backstop (`e6`–`e8`), and negative pathspecs die at `ls-tree` (`g1`, 2). The
backstop is doing more work than the table says — row 3 mentions "a directory entry is its
tree oid" (`SKILL.md:588`), but no row says it is the *only* detector when the pathspec is
narrower than the freeze, which is the actual load-bearing property.

**Smallest remediation for (e):** in `covers()`, compare normalised components —
`p.lstrip("./").rstrip("/")` against `fp.lstrip("./").rstrip("/")`, and accept
`fp == p or fp.startswith(p + "/") or p.startswith(fp + "/")` (a pathspec that is a parent
covers; a pathspec below the freeze cannot be "uncovering" for the purpose of the check).
Explicitly reject leading `:` magic with `2` and its own reason, so `g1`'s `ls-tree` failure
is not reported as a git failure.

## F3 — record-level: the flag that carries attack (a) has no selftest case

All eleven cases in `selftest()` build a linear history; none creates a merge, and none
creates a replace ref. So the two code paths that decide the hardest shapes — the
`-m --diff-merges=first-parent` flags (`:93`) and the object-provenance assumption behind
every `rev-parse` (`:123-125`) — are exactly the two with no red case, while block 22's
doctrine says "each has a red selftest case; a new arm without one is untested"
(`tools/round-45/frozen-path-preflight.py:11`). `R45-C1` clause 6 (`cases >= 11`,
`failures == 0`) is met on paper at 11, but the case set does not reach the merge shape or
the replace shape. Add `red-merge-treesame` (the `a2` fixture, expect 1) and
`red-replace-ref` (the `g2` fixture, expect 1); both are written and passing in `scripts/`.

## What holds, and why (calibration notes for the L1)

- The **ancestor guard** (`:83-84`) is the strongest single line in the file: sibling REV,
  shallow clone, non-commit REV and both graft shapes all land on 2. It is what makes (b)
  hold and what makes grafts safe rather than dangerous.
- The **directory-tree comparison** (freeze paths seeded as literal strings at `:114`, then
  compared as tree oids at `:123`) is more load-bearing than the table admits: it is the only
  detector for a narrow pathspec (`e6`–`e8`), and it is defeated only by object rewriting
  (F1).
- The **clean-tree controls** are honest: `a4`, `c6`, `d1`, `d5`, `d6`, `b2`, `g4`–`g6` are
  all exit 0 on real fixtures, and on the real lane `FREEZE..HEAD` and `FREEZE..landing` are
  both clean (`979f38256c98fb0a`, `b453a506e792f7a0`). The gate is not red-by-default; F2 is
  specifically the no-pathspec invocation.
- `--check-dirty` is opt-in and the gate's own table says so; d7/d9 show it works when
  requested, d8 shows the `--dirty-pathspec` narrowing defeats it (already routed).
