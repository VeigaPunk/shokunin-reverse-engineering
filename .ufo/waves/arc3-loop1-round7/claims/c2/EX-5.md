- **REPRODUCED — noopt dispatcher.** Eight selector `PUSH4` immediates each form `PUSH4; DUP2; EQ; ISZERO; PUSH2; JUMPI`, a linear compare chain in this K8 runtime. Each REA `bytecode_offset` equals the selector's `PUSH4` PC + 12 and points to opcode `0x34` (`CALLVALUE`). Exact per-selector PCs and offsets are in `evidence/rederive.txt` and `evidence/offset-check.txt`.
- **REPRODUCED — codesize dispatcher.** The first literal `CODECOPY` at PC 12 reads a five-byte header from `0x012b`; the runtime tail is 61 bytes: header `01c3013008` plus eight 7-byte records (`selector[4]`, big-endian target[2], marker `0x25`). The eight targets all point to byte `0x5b` (`JUMPDEST`). The code uses arithmetic/dynamic code-data copying and one selector equality check rather than per-function `PUSH4` immediates. The independent table parser output is `evidence/codesize-records.txt`.
- **DISCREPANCY — codesize offsets are not per-handler locations.** All eight REA `bytecode_offset` values equal 65 (`0x41`, opcode `DUP1`), the shared dispatch block; none equals its record's distinct JUMPDEST target. The analyzer's offsets must not be described as individual handler entries for this result. Exact selector/offset/target pairs are in `evidence/offset-check.txt`.
