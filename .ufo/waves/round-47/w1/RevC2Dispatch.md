## 1. Findings by severity

### F1 — CRITICAL: a seats correction launders a false per-wave split (green with a false atom)

`- corrects seats round-9: 2 waves, 72 seats total` exempts **any** seats atom of round 9, whether
or not it agrees with the dispatch. `corrects()` checks only `(len(spawns), sum(spawns))`; it never
reproduces the atom's own per-wave claim.

- fixture `…/fx/sG-launder-false-split-sum`: dispatches `[40, 32]`, card says
  **`Waves: 40 + 0 = 72 seats`** (40 + 0 ≠ 72 and wave 2 is 32) plus the true correction →
  **exit 0**, `mismatches []`, `exempted [Waves: 40 + 0 = 72 seats]`.
- fixture `…/fx/sG2-launder-false-split-pair`: **`Wave 1: 40 seats; wave 2: 0 seats`** plus the true
  correction → **exit 0**, `exempted [Wave 1: 40 seats; wave 2: 0 seats]`.
- receipts `receipts/sG-launder-false-split-sum.json`, `receipts/sG2-launder-false-split-pair.json`;
  stdout sha256 `b3813d0159777ad5…`, `b64f52dfe6be64a5…`.

Mechanism: `record.py:330-341` — `exempt()` matches on `class` and `key` only; a failing atom is
moved to `exempted`, and the only re-derivation of the entry is the class-wide
`(waves, total)` check at `record.py:258-270`.

The claim says (predicates 1 and the repair paragraph) "no atom disagrees with committed state" and
"An exemption whose correction is false keeps the atom red". Both are false of this instrument: the
atom disagrees, the correction is *true*, and the counter is green. **The claim would have to say:**
a `seats` exemption is legal only when the correction reproduces the atom's own value — i.e. the
exemption predicate is `derive(atom) == corrected_value`, not `class+key` — either by parsing
`A + B` against `spawns[0], spawns[1]` or by restricting a correction to atoms it states verbatim.

`CORR = re.compile(r"^- corrects (seats|window|path|rev) (\S+):\s*(.+)$")` (`record.py:50`) has no

Predicate 3 defines "an `axes` correction must state `<resolved>/<total>`", and C2's own Before cell
names two axes mismatches. The only repair that works is editing the `## Owned axes` table itself, so
the claim's repair contract for the class it names is dead. **The claim would have to say:** `axes`
corrections do not exist (delete the clause from the predicate and the table) or add `axes` to

## 2. The four assigned scenarios, in one line each

1. **No dispatch file** → exit **1**, `corrections that do not re-derive: 1` with detail
   `no dispatch file for round 9`; the seats atom itself is silently exempted. Not 2.
2. **`counts.spawn` absent** → exit **1**, detail `…: unreadable counts`; same exemption. A string,
   float or bool `spawn` is accepted instead (F12).
3. **`w1`/`w3` gap** → the wave after the gap is never read: an understated claim
   (`Waves: 40 + 0 = 40 seats`, correction `1 waves, 40 seats total`) is **exit 0**; the honest
   `40 + 32 = 72` is **exit 1**. A non-`w<i>` filename matching the claim's `*-dispatch.json` glob is
   also dropped (F3).
4. **Results file contradicts the dispatch** → exit **0**; the counter never opens any results file.

## 3. Can a `2` be mistaken for a pass?

For the counting command as the claim states it, no: the Target is `failing == []` **and** exit 0,
and both measured `2` paths (`sF` fewer than two round sections; `sI` unhandled `OverflowError`, plus
the F13 `--json-out` refusal) carry no `met_target` key. But **the receipts on those paths contain no
`failing` key at all** — `receipts/sF-…json` and the `sI`/F13 outputs are `{"reason": …}` plus, for
`sF`, `rev`/`sections`. Any downstream reader that reconstructs the claim's Target as
`receipt.get("failing", []) == []` — which is a natural reading of "`failing == []`" — records a
**vacuous pass on a run that measured nothing**. Recommendation for the landing evidence: quote
`met_target is true` and the exit code, never a `failing` list alone; and make the `2` receipts carry
`counter`, `met_target: false`, and `failing: []` so absence cannot be read as success.

## 4. Residual risk and verification gaps

- **Not run by this seat** (other seats own them, or the contract forbids it): `tools/round-47/exact.py`
  and every R47-C1 clause; mutation of any frozen byte (read-only); the wave-2 dispatch case on the
  real lane (only `w1-dispatch.json` exists at the measured revision).
- **Battery coverage of the seats class is thin.** The three forgeries target a correction total, a
  window and a ghost path. None exercises F1 (false split with a true total), F2/F3 (dispatch-set
  shape), F4 (results), F5 (silent section) or F8 (historical carve-out). Those holes are invisible
  to clause 6 by construction.
- **Fixture determinism.** `drive.py` is deterministic (fixed identity and dates); the receipts and
  the commit-id-bearing fixture paths it produced are copied alongside. The fixture trees themselves
  were deleted with the scratch dir, per the contract.
- **Live state moved under measurement.** The lane advanced from `3186f69` to `1e2c310` to `caafeffa`
  to `07d2894` to `a631bba` while this seat worked; every claim above is pinned to the
  `record.py` sha256 in §Pins, which was identical before and after the 21-scenario run.
- **The correction heading is a round-47 literal.** `CORR_HEAD = "## Record corrections — round 47"`
  (`record.py:35`) and the section body stops at the next `\n## `. A `- corrects` line placed
  anywhere else in `SCORECARD.md` is unparsed, which is the mechanism A5 fixed inside the battery —
  it still applies to any hand-written repair line the L1 puts outside that section.
- **The instrument that would notice all of the above is the one under test.** `record.py` reads
  `SCORECARD.md`, dispatch files and git; it never reads `LOG.md`, `plans/`, `QUALITY.md`, results
  files or its own freeze state, so the "record is not false about its own round" claim is bounded
  by the atom classes it chose. That is the honest scope of R47-C2 and should be stated as such in
  the landing: it makes the last two round sections' *named* atoms re-derivable; it does not make the
  record exhaustive (F5) and it does not check execution against plan (F4).
