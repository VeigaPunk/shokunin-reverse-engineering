### F7. The `interpreter_sha256` pin is an identity, not a freeze — a refreshed pin is always green

Predicate 8 requires the block's `interpreter_sha256` to equal sha256 of
`tools/round-47/exact.py` **at the measured revision**. Both sides move together: the commit
that changes the instrument can rewrite the pin in the same tree, and the counter then agrees
with itself. Observed in one pair of commits:

- `f54b3b6d` (A6) rewrites `tools/round-47/exact.py`: `dcef54f1…` → `01a4bca7…`.
- `a0753786` rewrites block 24's pin to `01a4bca7…`.
- `exact.py --freeze <tip> --rev <tip>` → exit 0, `interpreter_sha256 == expected == 01a4bca7…`.

The `stale-mutations-digest` battery forgery catches a pin that was **left stale**; nothing
catches a pin that was **refreshed**. So the pin detects forgetfulness, not instrument change,
and it cannot substitute for the freeze discipline that F1 shows is degenerate. If the claim is
meant to bind "the prose describes these bytes", the pin as specified does that; if it is meant
to bind "these bytes were fixed before the data", it does not — and the round's own A1–A6 are
the counter-example.
