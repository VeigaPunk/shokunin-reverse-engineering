## The mechanism (installed man pages, systemd 261.2-1-arch)

**Observation.** `man systemd-run`: a transient service runs detached,
with the service manager as its parent, and `systemd-run` returns after
the command has begun. A `--scope` command is executed by `systemd-run`
itself as parent, inherits the caller's environment, and `systemd-run`
does not return until the command finishes. `man systemd.scope`: those
processes generally remain children of the process that forked them.
`man logind.conf` `KillUserProcesses=`: if true, logout terminates the
session scope and every process inside it; processes under the user
manager can outlive login sessions when lingering is enabled.
`KillUserProcesses=yes` breaks `screen`/`tmux` unless they are moved out
of the session scope.

**Observation, this host.** Effective `KillUserProcesses` is false
(`busctl` property `b false`). `Linger=yes`. The logout-kill form is
not armed here. Record both settings; do not copy another host's.

**Inference.** The coupling that does not depend on that setting: a
`--scope` workload is a descendant of the dispatcher, and the dispatcher
blocks in `systemd-run` until the command ends. An agent that tears down
its process tree stops the scope. A named transient user service is
parented by the user manager. Prefer that form when the run must outlive
the dispatching turn. **Unknown:** survival past an actual caller kill
was not tested on this host. Do not write "proven" for that sentence.

1. **Long run, short dispatcher → transient user service, not `--scope`.**
   `systemd-run --user --unit=NAME` (no `--scope`), with `MemoryMax` /

   failed exec must fail the start. [AMENDMENT-A2 — added clause:] Switching

   `Type=simple` reports start success
   at `fork`, before `execve` (`man systemd-run`); that caveat is from
   the man page, not from the round-6 exit (that exit was recorded).
2. **Do not explain a unit death as caller-teardown unless the caller
   exited first.** Require a `Stopping`/`Killing` line, or a dead
   launcher, before the unit's result. An `exit.txt` written by the
   launcher after `systemd-run` returns is evidence the caller was alive.
   Round 4 is the counterexample: memcg OOM, launcher still writing.
3. **Record `KillUserProcesses` and `Linger` with the recipe.** Service
   mode outlives logout only while the user manager stays up. On this
   host linger is on and session-kill is off; a host with the opposite
   pair needs both the service form and linger, or the "independent"

4. **Service mode is not a result.** It does not raise the memory cap,

   the caller" for an OOM (a) invents a defect, (b) hides the memory
