## CLAIM
The universal `f(content, path, params)` claim is not supportable: direct comparisons establish path-insensitivity for `analyze_function` and for tested `analyze`/`inspect`; the recorded path-sensitive verifier example does not identify a REA verb family. No named family is proven caller-input-path-sensitive by the cited evidence.

## METHOD
Read-only `git show HEAD:<path> | nl -ba` and `git grep ... HEAD`; no REA/MCP/network probes. Counted only same-content, changed-path comparisons as caller-path evidence. Same-path reruns and internal staging paths are kept distinct.

## FINDINGS
| Family | Adjudication | Corpus evidence |
|---|---|---|
| `analyze_function` | **Path-insensitive, proven:** copied glibc at a renamed path has the same ID; ID hashes content+params while `subject` differs. | `corpus/knowledge/2026-10-14-r9-02-queue-a-ops-2.md:146-169` (comparison); `:173-178` (verification output). |
| REA `analyze` / `inspect` | **Path-insensitive in the tested case:** byte-identical patched RISC-V input at a different path yielded identical IDs; do not generalize beyond tested inputs/params. | `corpus/knowledge/2026-10-13-r5-01-riscv-bypass.md:83-86`. |

## THREATS
The r2/r3 aggregate sensitivity summaries do not identify the verifier operation (`r2-evidence-bundle-schema.md:244-250; r3-mcp-session.md:152-158`). JADX’s temporary staging path can be mistaken for sensitivity to the caller’s artifact path (`r4u-02-jadx-decode.md:143-156`). The r5 `analyze`/`inspect` result is explicitly bounded to its tested identical bytes and parameters (`r5-01-riscv-bypass.md:83-86`).

## VERDICT
FINDING: Universal path-sensitivity is contradicted; no identifiable named REA family is verified path-sensitive on caller input path in these sources.
