The committed envelopes `.ufo/waves/round-40/w1/artifacts/R40SrcReaOps/envelopes/out-{rizin,objdump,evm}.json` all carry `operation`/`provider.id` and a `normalized_result` (keys `stdout,stderr,exit_code,…` for rizin/objdump; `artifact,bytecode,…` for evm), so the entry sentence is false as written if the four are counted. [INFERENCE] the evm difference is the missing mode argument, not a contradiction of REA. Effect on the rule: none visible (the v2 guard keys on `operation`+`provider.id`, which S123 supports) — the defect is the entry's absolute "only", a calibration error in a landed knowledge entry. **D2 — S123 anchor does not locate its own `teaches`.** The row is `kind: code`, but "exit 0 … and carry none" is a runtime observation; none of the seven code locators in the anchor shows it.
