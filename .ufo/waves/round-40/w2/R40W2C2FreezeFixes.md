## 5. Defects found (none moves the C2 score)

- **D1 — the pin's recorded cause is misattributed and seed-specific (calibration, low).** The dry run necessarily predates the freeze commit whose hash is the held-out seed, so it cannot have run at seed `7fce3086…`; its "zeroed single-block xz file extracted clean" observation is about a placeholder seed (the comment cites "dry run df4fef39 H22") [INFERENCE on the seed identity; the precedence is structural]. At the actual frozen seed I measured the **un-pinned** xz H22 (`c214b2ed…`) producing a valid partial envelope (§2) — so the pin was not necessary for the frozen data; it is robustness insurance. The frozen comment's mechanism claim ("an all-zero block is never a gzip stream") and the `corruption_partial` docstring are false in the large-compressed-block regime on both compressors (MH-4's h1-gzip-00: silent clean, corrupt published file). The pin works for the frozen seed only because its zeroed gzip blocks are short (37 B / 26 B — measured). Failure direction is safe: a future silent-clean carrier would make C2 score 25/26 (honest stop), never a false pass.
- **D2 — `row_decisions_consistent` is looser than the predicate for the no-match pair (low).** `(None not in v or k == NOMATCH_PAIR)` accepts *any* single reported row for the `('unclassified','none')` pair, while the predicate says the no-match pair maps to **no row**. A table resolving the ood envelopes to a real `(unclassified, none)` row would keep this binding true (and could score met if that row matched both ood envelopes and no other pair shared its row). Unreachable at this freeze — `v2_table_identical` pins the table bytes and the interpreter is in `FROZEN` — but a future re-freeze should use the strict form `v == {None}` for `NOMATCH_PAIR`.
- **D3 — the 42-case battery does not exercise the new branches (low).** The selftest's synthetic manifests map `unclassified` carriers to arm `before` with action `report-only` and the stub table carries an `unclassified` row (`c2-counter.py:863-882,1015`), so no case runs arm `ood` and no case exercises the NOMATCH row-`None` acceptance; the branches are exercised only by the real held-out scoring. My wave-1-counter run supplies the red direction empirically; a battery case for each branch would close this.
- **D4 — the counter's frozen-path gate omits a claims-declared frozen C2 path (low-medium, pre-existing).** `FROZEN = (INTERP, GEN, COUNTER, CLAIMS)` (`c2-counter.py:75`) does not include `tools/round-39/gen-squashfs.py`, which the claims' Frozen-paths section declares for C2. A post-freeze writer change would not trip `frozen_path_changed`: regen materialises the freeze blob and `writer_matches_manifest` compares the freeze blob to the manifest declaration, both stable under a working-tree/REV-side mutation. The fix touched the adjacent `DEFAULT_WRITER` lines and could have extended `FROZEN` in the same hunk. Verified clean today (`freeze..HEAD` empty for that path); wave-1 `FROZEN` was identical, so this predates the fixes.
