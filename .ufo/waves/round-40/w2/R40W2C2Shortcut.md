## 2. Smallest v2-grammar table that reaches 26/26: 21 cells (−48 cells, −70 %)

(`min2.py`, `lattice.py`), with the interpreter's own `rule_matches` semantics, then confirmed by
running the **frozen interpreter**: `.ufo/waves/round-40/w2/artifacts/R40W2C2Shortcut/min-v2-table-21cells.md`

`symlink removed` 4, `published files` 4, `provider` 0.

Three of its 11 rows are **one-cell rules**: `-be=no → wrap-extractor-be`,
`dependencies=sasquatch-v4be → install-extractor-be`, `dependencies=sasquatch → install-extractor-le`.

column in the table, is optional for this envelope set.

for 21 cells. So the minimum is "one domain cell + 5 outcome columns"; the committed table spends

## 3. Is there a trivially leaked key? A *signature* leak (plus an unreachable id leak)

- No held-out envelope contains its class name (`grep -l 'clean-empty\|avm-marker\|dep-missing\|…'
  heldout/H*/envelope.json` → empty), **but every envelope carries its own id `H01…H26`** in
  `subject.local_path`, `parameters.path` and the `raw_result` task paths (e.g.
  `…/c2/heldout/H01/carrier.sqsh`, `…/rea-H01/out`), and the manifest maps id → class → `(label,
  action)`. The v2 grammar cannot reach those fields — `features()` reads only `operation`, `provider`,
  `normalized_result` chunks/gaps/diagnostics, and sasquatch `command` strings (whose paths are never
  compared) — so no class-name key exists *today*. It is one added column away from being one: any
  future feature that reads `parameters`, `subject.local_path` or a task path turns the held-out set
  into an id lookup.
- The leak is structural: each class is a fixed recipe, so the 13 signatures are pairwise disjoint.
  **12 of the 78 class pairs differ in exactly one feature** (`-be`, `published files` sign, endianness,
  `symlink removed`, `gap kinds`) and the rest differ in 2–6; the histogram over 78 pairs is
  `{1: 12, 2: 16, 3: 22, 4: 19, 5: 7, 6: 2}`. 26/26 therefore asks the table to cut 11 near-neighbour
  edges, not to model SquashFS outcomes.
- `published files` is the one feature the grammar deliberately collapses: the envelope carries the exact
  count (3, 4, 5, 8, 697, 2147 …) but only `0`/`>0` is expressible. Exact counts would not decide the set
  anyway — the values recur across classes (5 in clean-be, in-tree, mixed, partial; 3 in clean-be,
  escaping, partial) — and replicates must map to one row, so an exact-count key would break
  `row_decisions_consistent`. The 2-replicates-per-class rule does force real abstraction, but only over
  the axes the generator declares (`compression`, `tree-shape`, `endianness-where-the-class-allows`): it
  forces rows to span both endiannesses in `clean`, `clean-empty`, `escaping`, `in-tree`, `mixed` (each
  has 2 signatures after the `P` collapse) and to ignore file-count magnitude. Nothing else.
- The closest thing to a "trivial-feature" table that still passes: `min6-v2-table-23cells.md`, which
  deletes `dependencies` — the only column that names the root cause — and keys the two dependency rows
  on the handler's endianness instead. 26/26, 23 cells.

## 4. Held-out vs dev: the split adds no discrimination (measured)

Scoring the seven committed control tables on the **held-out** envelopes gives exactly the recorded
dev scores: `CTL-0 0`, `CTL-1 4`, `CTL-2 18`, `CTL-3 2`, `CTL-4 24`, `CTL-5 24`, `CTL-6 24`
(`probe4.py`). Held-out and dev are the same 13 signatures drawn from a different seed, so every table
that passes on dev passes on held-out and vice versa — my 21-cell table scores 26/26 on both. The
held-out split + `v2_table_identical` prevents *post-hoc tuning of the table to the data* (real value);
it does not add evidence about generality. Effective sample size for discrimination is **13 signatures,
not 26 envelopes**: replicates are outcome-identical except for compression/tree/file count.

Margin over the strongest control is **one class** (24/26 = 11 of 13 classes already correct). A binary
26/26 target cannot distinguish "the two rows that matter" from "the model of the domain".

## 6. What 26/26 proves, and what it does not

Proves:
1. On the committed 26 envelopes the frozen interpreter, reading the frozen table bytes, returns the
   generator's 13 assigned `(label, action)` pairs; carriers regenerate byte-identically; the manifest
   ordering and seed bindings hold. The score is reproducible (exit 0, both mine and the receipt).
2. The 13 signatures are separable inside the v2 grammar with ≥6 columns and as few as 21 cells, and the
   landed rows are (therefore) sufficient for this closed class set.
3. Rows are invariant to compression, tree shape, file-count magnitude and — in the 5 classes that vary
   it — endianness.

Does not prove:
1. **Depth of understanding.** A 21-cell lookup meets the same target; the counter's `matched` cannot
   tell it from the 69-cell table (`matched 26`, only `v2_table_identical` differs). 33 committed cells
   are individually inert; the `dependencies` column, the most domain-specific one, is removable with the
   score fixed.
2. **Generalization.** The 26 envelopes are 13 recipes; every control scores identically on held-out and
   dev; no envelope carries two gap kinds or a structural gap; no envelope has an out-of-set provider
   other than the single frozen out-of-domain class.
3. **Correct advice on real outcomes.** All four round-40 C1 receipts (and 5/6 synthetic shapes) get
   `unclassified`/`none`.
4. **Row-level correctness.** `cause` is unscored prose: my 21-cell table's one-cell rows pass with
   reasoning that only holds because the class set is closed. 26/26 is a statement about 11 strings, not
   about 11 reasons.

## 7. Impacted axes and the smallest safe correction

- **depth (this claim's axis):** the observed signal is dominated by separability of 13 fixed
  signatures; the target has a 1-class margin over the best control and is satisfiable at 30 % of the
  committed cell budget. The `depth` credit should be read as "a frozen 11-decision table exists and is
  tamper-evident", not "a SquashFS triage model was validated".
- **coverage (shared, negative spill):** the table's blind spot is exactly the round-40 C1 evidence
  shape (`depth-limited`, multi-gap). Cross-claim reading: C1 builds genuine AVM-layout coverage; the
  C2 craft block would send an operator to `none` on those very receipts.
- **calibration:** 24/26 controls already reach 11/13 classes; 26/26 vs 24/26 is one class, so the
  target's granularity is coarser than the table's row count.

Smallest safe correction (no re-freeze of the landed claim, no predicate change):
1. Since the C2 predicate is met and reproducible, keep **MET**, but add to the landing's disclosed
   limits — measured, with these receipts — the three sentences: (i) 26/26 is reachable with 21 of 69
   cells and one domain column plus five outcome columns, and the counter's `matched` is 26 for that
   table too; (ii) 33 committed cells are individually inert on the held-out set and `dependencies` is
   removable; (iii) no held-out envelope carries more than one gap kind, and the table returns
   `unclassified`/`none` for every round-40 C1 receipt.
2. A single follow-on test that costs no new tooling and closes the real hole: one round-41 held-out
   class with the C1 shape (`gap kinds = depth-limited+unpublished-entry`, `SR=no`, `P>0`, expected
   `count-gap`-class action) or, if the writer cannot emit a depth-limited gap, an envelope-level class
   whose `normalized_result` carries that gap set. [INFERENCE] `depth-limited` is an REA/unblob-side gap,
   not a writer-side one, so the envelope-level route is the cheap one; either way the table must stop
   answering `none` to its own round's receipts.
3. If row-level semantics should be scored at all, require each row to be distinguished by ≥2 semantic
   cells, or score `cause` against the firing cells — otherwise one-cell rules stand as "depth".
