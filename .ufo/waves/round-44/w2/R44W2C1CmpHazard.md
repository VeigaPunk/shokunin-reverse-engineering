## 3. Size ladder — one differing byte per pair, stdout to a pipe

| size | `cmp -l` | `cmp -s` | `cmp` | differing bytes |
|---:|---:|---:|---:|---:|
| 15 | 1 | 1 | 1 | 1 |
| 255 | 1 | 1 | 1 | 1 |

| 4097 | 0 | 1 | 1 | 1 |
| 8191 | 0 | 1 | 1 | 1 |
| 8192 | 0 | 1 | 1 | 1 |
| 8193 | 0 | 1 | 1 | 1 |

| 65536 | 0 | 1 | 1 | 1 |
| 1048576 | 0 | 1 | 1 | 1 |
| 4194304 (separate run) | 0 | 1 | 1 | 1 |

`-s` and plain `cmp` were correct at **every** size measured, including 4 MiB. The threshold is
exactly 4096 B and the false zero persists above it — it is not a 4096-B boundary artefact.

Flag variants at 4096 B (one-byte difference): `-l` → **0**; `-b` → 1; `--print-bytes` → 1;
`-l -s` → 2 (usage error). `/usr/bin/cmp --help` on this host lists `-b, --print-bytes` (print
differing bytes) and `-l, --verbose` (output byte numbers and differing byte values) as separate
output-format switches and says nothing about `-b` implying `-l`; `-b` therefore reports the
correct status here, and the defect is confined to the `-l` output path rather than to long or
multi-line output generally.

The same help text states the tool's contract: "Exit status is 0 if inputs are the same, 1 if
different, 2 if trouble." The measured `-l` result at ≥ 4096 B breaks that documented contract —
the instrument reports "same" for inputs it simultaneously prints as differing. That is why the
prohibition, not a careful reading of the manual, has to be the operative rule.

Identical 4096-byte pair: `-l` 0, `-s` 0, `cmp` 0. So at ≥ 4096 B `cmp -l` carries **no
discriminating signal at all**: differing and identical inputs are indistinguishable by exit code.

## 4. The stdout condition (30 repetitions per destination, 4096 B one-byte difference)

| stdout destination | exit codes over 30 runs | correct? |
|---|---|---|
| `/dev/null` | `1` × 30 | yes |
| regular file | `0` × 30 | **no (false equal)** |
| pipe (`subprocess` capture) | `0` × 30 | **no (false equal)** |
| `/dev/full` (writes fail ENOSPC) | `0` × 1 | **no (false equal)** |

Deterministic in every cell. The hazard therefore is not "exits 0 for differing inputs of 4096
bytes or more" — it is "exits 0 for differing **equal-length** inputs of 4096 bytes or more whenever
stdout is a pipe, a regular file, or `/dev/full`; only `/dev/null` returns the correct 1".

**This falsifies the wave-1 causal explanation.** `w1/R44Simplify.md:215-217` states "the 0
appears only when `cmp`'s stdout actually receives bytes". `/dev/null` receives the same bytes and
returns 1; `/dev/full` receives (failing) writes and returns 0. The "receives bytes" condition is
not the discriminator. I did not establish the mechanism; it is **unexplained** and recorded as
such ([INFERENCE] only: the null device may short-circuit the `-l` output path). Any future note
should state the observed matrix, not a guessed cause.

## 5. The equal-length condition (new)

| case | sizes | `cmp -l` | `cmp -s` | `cmp` |
|---|---|---:|---:|---:|
| equal, one differing byte | 4096 / 4096 | **0** | 1 | 1 |
| equal, identical | 4096 / 4096 | 0 | 0 | 0 |
| equal, one differing byte | 8192 / 8192 | **0** | 1 | 1 |
| unequal, difference in shared prefix | 4096 / 8192 | 1 | 1 | 1 |
| unequal, no difference in shared prefix | 4096 / 8192 | 1 | 1 | 1 |
| unequal, difference in shared prefix | 4096 / 4097 | 1 | 1 | 1 |

The false equal requires **equal length** on both sides. Unequal-length pairs — including a
one-byte truncation at the 4096 boundary — are reported correctly even by `-l`.

This matters because every binding class the claim cares about compares *same-length* blobs: a
carrier against its frozen pin, the same path at FREEZE and REV, a rubric script against its
pinned digest. A one-byte, length-preserving mutation is exactly the freeze-violation shape of
M44-2, and it is exactly the shape `cmp -l` cannot see.

**D1 — `plans/round-44-claims.md:69-73`: the hazard sentence omits the stdout condition.**
The line reads "`/usr/bin/cmp -l` exits **0** for differing inputs of 4096 bytes or more".
Command: `/usr/bin/cmp -l a4096 b4096 >/dev/null; echo $?` → **1** (30/30 runs); the same command
with `> o.txt` → **0** (30/30). The sentence is true only for pipe / regular-file / `/dev/full`
stdout. A reader who discards stdout as the obvious sanity check concludes the instrument is
sound. Required text (round 45): state the observed destination matrix, not an unqualified claim.

**D2 — `plans/round-44-claims.md:71-72`: "the boundary case" understates the regime.**
The text continues "All four target carriers are exactly 4096 B — the boundary case."
Command: the size ladder (`probe.py`) → `-l` = 0 at 4096, 4097, 8191, 8192, 8193, 16384, 65536,
1048576, 4194304. It is a size *regime*, not a point. Also missing: the false equal needs
**equal-length** inputs (4096 vs 4097 → 1, 4096 vs 8192 → 1). On the scored surface this is not
hypothetical — `corpus/evidence/round-44/c1/v2le/after.json` is 18009 B,
`v1le/after.json` 15838 B, `v2le/unblob.log` 5531 B, all inside the false-zero regime had any
binding used `cmp -l`.

**D3 — verification shell ≠ counter runtime (shadowing).**
Command: `type cmp` in the agent shell → `cmp is a shell builtin`; `cmp --version` →
`cmp (pi-shell) 17.2.11`; bare `cmp -l a4096 b4096` → exit **1**. Command:
`bash -c 'command -v cmp'` → `/usr/bin/cmp`; `shutil.which('cmp')` → `/usr/bin/cmp`;
`/bin/sh -c 'cmp -l a4096 b4096'` → exit **0**. A seat verifying the instrument in its tool shell
gets the correct number; every counter subprocess gets the false one. Required action: any future
`cmp` prohibition must name the absolute path and must be checked in the counter's execution
context, never in an agent's interactive shell.

**D4 — `corpus/lessons/round-44.md:81-83` (`R44-CL6`) carries D1 into the durable record.**
The row states "`/usr/bin/cmp -l` exits 0 for 4096-byte differing inputs on this host; all four
carriers are exactly 4096 B" with the same omissions as D1/D2. This is the row a future round will
