はじめに

前回は SIMD 命令を見ました。最終回となる今回は、コンパイラの出力ではなく「すでにあるバイナリ」を逆アセンブルして読む練習をしてみます。

これまでの5回で身につけた知識——レジスタの使い方、呼び出し規約、スタックフレーム、syscall——がどこまで実戦で使えるかの腕試しです。

道具の準備

objdump

GNU Binutils に含まれる逆アセンブラ。ほぼすべての Linux 環境に入っています。

objdump -d binary           # .text セクションを逆アセンブル
objdump -d -M intel binary  # Intel記法（x86_64 で見やすい）
objdump -s -j .rodata binary # .rodata（文字列定数など）を表示

llvm-objdump

LLVM 版。macOS では xcrun llvm-objdump で使えます。

llvm-objdump -d binary
llvm-objdump --disassemble-symbols=main binary  # 特定の関数だけ

readelf

ELF バイナリのヘッダやセクション情報を読むツール。逆アセンブルの前に全体像を把握するのに使います。

readelf -h binary   # ELFヘッダ（アーキテクチャ、エントリポイント）
readelf -S binary   # セクション一覧
readelf -s binary   # シンボルテーブル（stripされていなければ）

実例：小さなプログラムを逆アセンブルする

ソースコードと準備

// greet.c
#include <stdio.h>
#include <string.h>

int is_special(const char *name) {
    return strcmp(name, "root") == 0;
}

int main(int argc, char **argv) {
    if (argc < 2) {
        puts("Usage: greet <name>");
        return 1;
    }
    if (is_special(argv[1]))
        printf("Welcome back, %s.\n", argv[1]);
    else
        printf("Hello, %s!\n", argv[1]);
    return 0;
}

gcc -O2 -o greet greet.c
strip greet   # シンボルを削除

strip でシンボルテーブルを削除すると、関数名やラベルが見えなくなります。実際のリバースエンジニアリングはこの状態から始まります。

Step 1：バイナリの素性を調べる

file greet
# greet: ELF 64-bit LSB pie executable, x86-64, ...

readelf -h greet | grep 'Entry point'
# Entry point address: 0x1060

ELF の x86_64 バイナリで、エントリポイントが 0x1060 だとわかりました。ただしこのアドレスは main ではなく _start（CRT のエントリ）です。

Step 2：逆アセンブルしてエントリポイントを見る

objdump -d -M intel greet | head -40

0000000000001060 <.text>:
    1060:  xor     ebp, ebp
    1062:  mov     r9, rdx
    1065:  pop     rsi              ; argc
    1066:  mov     rdx, rsp         ; argv
    1069:  and     rsp, -16         ; スタックを16バイトアラインメント
    106d:  push    rax
    106e:  push    rsp
    106f:  ...
    1080:  lea     rdi, [rip+0x...]  ; main のアドレスを渡している
    1087:  call    ...               ; __libc_start_main

これは _start で、libc の初期化コードです。lea rdi, [rip+0x...] で main のアドレスを第1引数として __libc_start_main に渡しています。ここの飛び先を追えば main が見つかります。

Step 3：main を特定する

_start の中で rdi に設定されるアドレスを追います。PIE（Position Independent Executable）なので rip 相対のアドレスです。

; main と思われる関数
    1149:  push    rbx
    114a:  mov     rbx, rsi          ; argv を rbx に退避
    114d:  cmp     edi, 1            ; argc <= 1 ?
    1150:  jle     1180              ; Usage表示へ
    1152:  mov     rdi, [rsi+8]      ; argv[1]
    1156:  lea     rsi, [rip+0x...]  ; "root" の文字列アドレス
    115d:  call    ...               ; strcmp
    1162:  mov     rsi, [rbx+8]      ; argv[1]（printf の第2引数）
    1166:  test    eax, eax          ; strcmp の結果が 0 か？
    1168:  je      1190              ; 0 なら "Welcome back" へ
    116a:  lea     rdi, [rip+0x...]  ; "Hello, %s!\n"
    1171:  xor     eax, eax          ; printf の可変引数のため al=0
    1173:  call    ...               ; printf
    1178:  xor     eax, eax          ; return 0
    117a:  pop     rbx
    117b:  ret

ここで、これまでの知識が役に立ちました：

  1. 呼び出し規約: edi = argc（第1引数）、rsi = argv（第2引数）
  2. test eax, eax + je: strcmp の戻り値（eax）が 0 かどうかのイディオム
  3. xor eax, eax: 戻り値 0 のイディオムであると同時に、printf の前では「浮動小数引数が0個」を示すための規約
  4. [rsi+8]: argv[1]。ポインタ配列の2番目の要素（8 = ポインタサイズ）

Step 4：文字列定数を確認する

objdump -s -j .rodata greet

Contents of section .rodata:
 2000 726f6f74 00000000 57656c63 6f6d6520  root....Welcome
 2010 6261636b 2c202573 2e0a0048 656c6c6f  back, %s...Hello
 2020 2c202573 210a0055 73616765 3a206772  , %s!..Usage: gr
 2030 65657420 3c6e616d 653e00             eet <name>.

"root"、"Welcome back, %s.\n"、"Hello, %s!\n"、"Usage: greet <name>" がすべて .rodata セクションに見えます。逆アセンブリ中の lea rdi, [rip+0x...] がこれらの文字列を参照しているわけです。

パターン認識のコツ

strip されたバイナリを読むときに手がかりになるパターンを整理してみます。

関数の境界

; 関数の開始パターン（x86_64）
push    rbp               ; または push rbx, push r12 など
mov     rbp, rsp          ; -O0 の場合
sub     rsp, 0x...        ; スタック確保

; 関数の終了パターン
xor     eax, eax          ; return 0 の場合
pop     rbp               ; または pop rbx など
ret

-O2 では push rbp / mov rbp, rsp が省略され、代わりに callee-saved レジスタの push だけが見えることが多いです。ret の直前に pop の連続があれば関数の末尾です。

文字列参照

lea     rdi, [rip+0x...]   ; 文字列のアドレスをロード
call    ...                 ; puts, printf, strcmp など

lea rdi, [rip+offset] → call のパターンは、文字列を引数に取る関数呼び出しの定番です。rdi は第1引数なので、lea の飛び先を .rodata と照合すれば何の文字列かわかります。

分岐の構造

test    eax, eax    ; if (result == 0)
je      ...         ; then
                    ; else はフォールスルー

cmp     edi, 1      ; if (argc <= 1)
jle     ...         ; then（異常系）
                    ; else（正常系はフォールスルー）

コンパイラは「ありそうなパス」をフォールスルー（ジャンプなし）に、「例外パス」をジャンプ先に配置する傾向があります。

ライブラリ関数の特定

PLT（Procedure Linkage Table）経由の call は動的リンクされた関数への呼び出しです。

objdump -d -j .plt greet

PLT のエントリを見ると strcmp@plt、printf@plt、puts@plt といったシンボルが残っていることがあります。strip されていても PLT のシンボルは残る場合があるので、ここが最初の手がかりになりました。

AArch64 で同じバイナリを読む

docker run --rm -v $(pwd):/work -w /work --platform linux/arm64 gcc:14 \
  sh -c "gcc -O2 -o greet_arm greet.c && strip greet_arm"

; main と思われる関数（AArch64）
    7c0:  stp     x29, x30, [sp, #-32]!  ; フレームポインタとリンクレジスタを退避
    7c4:  mov     x29, sp
    7c8:  stp     x19, x20, [sp, #16]    ; callee-saved を退避
    7cc:  mov     x19, x1                 ; argv を x19 に退避
    7d0:  cmp     w0, #1                  ; argc <= 1 ?
    7d4:  b.le    810                     ; Usage表示へ
    7d8:  ldr     x0, [x1, #8]           ; argv[1]
    7dc:  adrp    x1, ...                ; "root" のページアドレス
    7e0:  add     x1, x1, ...            ; "root" のオフセット
    7e4:  bl      ...                    ; strcmp
    7e8:  ldr     x1, [x19, #8]         ; argv[1]
    7ec:  cbz     w0, 820               ; strcmp 結果が 0 なら Welcome へ
    7f0:  adrp    x0, ...               ; "Hello, %s!\n"
    7f4:  add     x0, x0, ...
    7f8:  bl      ...                   ; printf
    7fc:  mov     w0, #0
    800:  ldp     x19, x20, [sp, #16]
    804:  ldp     x29, x30, [sp], #32
    808:  ret

x86_64 との違い：

  • stp/ldp でレジスタをペアで退避（第3回で見たパターン）
  • cbz w0, ... で「strcmp の結果が 0 ならジャンプ」を1命令で（第1回で見た cbz ）
  • adrp + add で PC 相対アドレスを構成（x86_64 の lea [rip+...] に相当）
  • [x1, #8] で argv[1] にアクセス（x86_64 の [rsi+8] と同じ構造）

読み進めるためのワークフロー

実際にやってみて、以下の流れが効率的でした。

1. file / readelf で素性を把握
       ↓
2. .rodata の文字列を確認（プログラムの目的を推測）
       ↓
3. PLT で使われているライブラリ関数を特定
       ↓
4. _start → __libc_start_main → main を追跡
       ↓
5. main から呼び出し規約を手がかりに読む
       ↓
6. 分岐構造とループを図にする

最初から全命令を追わず、文字列と外部関数の呼び出しから全体像を掴み、気になる部分だけ詳細に読むのがコツでした。

まとめ

知識 どこで使ったか
呼び出し規約（第1回〜） edi = argc, rsi = argv の特定
test eax, eax イディオム（第1回） strcmp 結果のゼロ判定
スタックフレーム（第3回） 関数の境界（push/pop）の認識
syscall の知識（第4回） _start の CRT コードの理解

strip されたバイナリは最初は何も見えない気がしましたが、呼び出し規約と文字列参照を起点にすると構造が浮かび上がってきました。これまで5回にわたって別々に見てきた知識が合流する感覚があり、素振りを続けてきてよかったと感じています。

シリーズを終えて

全6回で以下を辿ってきました。

回 テーマ 得られたこと
