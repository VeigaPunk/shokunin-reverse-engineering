# CR-2 — Independent audit of arc3 EVM entries

Audit target: `corpus/knowledge/2026-10-19-arc3-r1-evm-real-solc.md`, `2026-10-19-arc3-r3-evm-optimizer-shapes.md`, and `2026-10-19-arc3-r4-evm-vyper-leg.md`, plus their relevant append-only errata. The verdicts below concern the retained repository evidence, not claims about a live Core registry.

**Verdict key:** VERIFIED = reproduced from retained artifacts; CORRECTED = a stated byte count, digest domain, or interpretation needs correction; UNVERIFIABLE = the necessary primary evidence is not retained or is outside the permitted repository scope.

## Method

`evidence/rederive.py` independently decoded local hex/raw assets, SHA-256 hashed the file and decoded-byte domains separately, compared observed selectors with the retained planted/ABI sets, instruction-swept dispatcher opcodes and offsets, and checked creation/runtime byte inclusion. `evidence/supplement.py` re-hashed source/ABI files, checked creation digest domains, Vyper ABI/method-id sets, Carrier-A immediates, and representative envelope scope fields. Outputs are retained at `evidence/rederive.out` and `evidence/supplement.out`. The scripts parse shipped files and sealed JSON; no REA target execution was performed, and no external Ghidra installation was inspected.

The retained `.bin` file is 1,370 ASCII-hex bytes with SHA-256 `530efc7b…`; decoding yields 685 bytecode bytes with SHA-256 `08299f31…`. Thus 685 B describes decoded bytecode, while the cited digest identifies the ASCII-hex file, not those 685 bytes. `evidence/rederive.out:12-13`; `evidence/supplement.out:28`.

Its runtime code ends at offset 1,890; the 53-byte trailer contains `16ee4b79` at offset 1,901. The append-only r1 erratum correctly records this distinction (`2026-10-19-arc3-r1-evm-real-solc.md:31`). See `evidence/rederive.out:14-15,42-43,53-55` and `evidence/supplement.out:25-28`.
