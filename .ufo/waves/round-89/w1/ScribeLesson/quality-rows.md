- **Row 161 (a repair that supersedes an earlier one composes it, and the composition is a frozen arm).** A new capability that re-implements the previous round's path silently drops the class the previous round repaired: the first round-89 candidate scored `recovered 4 of 4` on its own class with every control true while the round-88 class regression arm was unmet (`recovered 0 of 4`), because it derived the field without running the round-87 anchor path first. The regression arm belongs in the claim's frozen predicate, not in a separate no-harm sentence, and the pre-freeze candidate run is the instrument that catches it. Round-89 case, judged by this row: `.ufo/waves/round-89/pre/c1-candidate-first-run.log` (`recovered 4 of 4 … met=False exit=1`) and the composed repair's selftest case `magic-class-composed` (`corpus/lessons/round-89.md` M89-1).

- **Row 162 (an instrument's docstring states the rule its code applies, at the same revision).** A correction written into a lesson or a routed-defect list does not repair the docstring the next reader trusts: the round-88 repair's module docstring still described "the smallest offset above `block0 + 12` … requires `0 < sz_cpr <= sz_unc`" and preferred candidates whose `l_info` carries `p_filesize == u_file_size`, while the code keys on `(fits, total, -derived)` and treats that equality as a hard precondition — the rule M88-3 recorded as wrong, left standing in the file it was written for. Check the docstring against the code before the instrument is frozen again. Round-89 case: `tools/round-88/upx-chain-repair.py:13-18` versus `:70-78,:136` (round-88 spot-check D1) (`corpus/lessons/round-89.md` M89-2).

- **Row 163 (a scored repair sees only the file it must repair).** A harness that writes the intact original, its own outputs or a repaired sibling into the same directory as the repair's input lets a copy-only "repair" score the target. Each invocation gets a private directory holding the tampered input alone, and the counter records the directory listing each invocation saw as an `isolation` control that `met` requires. Round-89 case: `tools/round-89/upx-field-battery.py` (`apply_repair` → one `mkdtemp` per call; control `isolation`), which makes the round-88 sibling-copy cheat (`w1/CriticClaims/receipts/cheat-c1-sibling-v2.json`) unscoreable (`corpus/lessons/round-89.md` M89-4).

- **Row 164 (a field class is defined by its value domain, not by the refusal string).** Two tampers that answer the same message are different classes when their value domains differ: a zeroed `sz_cpr` and an in-range wrong one both fail, but the first answers `CantUnpackException: b_info corrupted` and the second `Exception: compressed data violation` — the wrong value passes every bound the packer applies to the field and fails only at the payload stage. A class definition must state the tamper's domain and the arm that decides it; a repair keyed on the refusal string would miss the recoverable class. Round-89 case: `.ufo/waves/round-89/pre/c1-base-r88-repair.json` (`precondition.tail` per carrier) and `.ufo/waves/round-89/l1/scores/block29-cells.json` (`corpus/lessons/round-89.md` M89-6).

- **Row 165 (a field the packer tolerates is not a no-op, and "tolerated" is not "harmless to the lane").** `upx -t` answering rc 0 after a byte changed means the packer does not consult that field on that carrier, not that the change is inert: a tampered `l_info.version` or `l_info.format` passes `upx -t` (`Tested 1 file.`) yet breaks the lane's own locator, which cross-checks those bytes, so the repair refuses it. Report the cell as tolerated, name the consumer that does care, and never fold it into the `noop` class (whose definition is "the bytes were already equal"). Round-89 case: `.ufo/waves/round-89/l1/scores/block29-cells.json` (`l_info.version^=0xFF` and `l_info.format^=0xFF`, rc 0 on both carriers) (`corpus/lessons/round-89.md` M89-7).

- **Row 166 (a superseding instrument may not drop the predecessor's input guards and refusal contract; the guard set is part of the frozen predicate).** A repair that re-implements an earlier one in a new file inherits its predecessor's *guards* and not only its logic: the round-88 repair refused a non-regular `--in` (`refused: --in is not a regular file: fifo`, rc 2), refused a directory `--in` with the same typed rc 2, and converted the round-87 module's own `Refused` exception into its own typed refusal (rc 2). The round-89 repair drops all three: a FIFO `--in` hangs the tool (no exit within 20 s), `/dev/zero` raises `MemoryError` from an unbounded `fh.read()`, and the round-87 `Refused` escapes as an uncaught traceback (rc 1) because the new module defines its own `Refused` class and never converts the upstream one. The control that was supposed to catch this — `N1-refuse-plain` — passes on the *crash*, not on a refusal: the battery records `refused: n1["rc"] != 0`, and the receipt shows `rc 1` for the round-89 repair against `rc 2` for the unchanged round-88 repair. A refusal control must distinguish a typed refusal from a crash: it asserts the exit code it declares and the refusal text, not merely "non-zero". Round-89 case: `.ufo/waves/round-89/pre/c1-candidate-at-declaration.json` (`N1-refuse-plain` rc 1 on all four carriers) versus `.ufo/waves/round-89/pre/c1-base-r88-repair.json` (same arm, rc 2 on all four); `tools/round-89/upx-field-value-repair.py:243-252` against `tools/round-88/upx-chain-repair.py:243-256` (`corpus/lessons/round-89.md` M89-8).

- **Row 167 (an isolation control must observe the invocation, not a snapshot taken before it).** A counter that lists the repair's input directory *before* the repair runs reports the listing it prepared, not the listing the repair saw, so it certifies nothing about what the repair read or wrote. The round-89 counter's `isolation` control is exactly that: `before = sorted(os.listdir(box))` is captured at `tools/round-89/upx-field-battery.py:180`, before the child process starts, and the recorded `box` is that snapshot (`:197`). A repair that reads the pinned carrier path out of band and writes a marker into its own invocation directory during the run therefore scores the target with every control true and `met_target true`, exit 0. The isolation control must be taken *after* the child exits (the directory listing plus the set of paths the child opened), and the counter must additionally check the repair's open-file set or forbid any read outside `--in`. Round-89 case: `.ufo/waves/round-89/w1/ReviewerC1/receipts/attack-carrier-read.json` (`met_target true`, `exit 0`, `controls_ok` all true, `repair_cmd …/cheat-carrier-read.py`, which reads and sha256-hashes `/usr/bin/jq` and writes `carrier-read.marker` into the box) (`corpus/lessons/round-89.md` M89-9).

- **Row 168 (the `u_len` accounting bound is a preference, not a filter: a candidate may not claim more than `u_len`, but a candidate that claims more must be reported, not silently dropped).** The chain law's accounting bound reads `u_len` as the packer's own declared uncompressed total, so a candidate whose walk accounts for more than `u_len` bytes is impossible *as a description of this file*. The round-89 repair implements the bound as a sort key — `key = (total <= ph["u_len"], total, -derived)` at `tools/round-89/upx-field-value-repair.py:95` — so an over-`u_len` candidate is not rejected, only ranked last, and the receipt does not record that it was over. A bound that is a preference is a weaker bound than the word "bound" claims: a carrier whose only candidate exceeds `u_len` (or whose two candidates straddle `u_len`) is decided by an unexamined tie-break. The receipt must carry, per candidate, `total` and `u_len` and the `fits_u_len` verdict, and the law must state whether an over-`u_len` candidate is discarded or merely outranked. Round-89 case: `tools/round-89/upx-field-value-repair.py:95` (the key) against `:97-99` (`rec` records `uncompressed_accounted`, `u_len`, `fits_u_len` but the *chosen* candidate only; the round-88 predecessor at `tools/round-88/upx-chain-repair.py:132-136` computed `fits` the same way) (`corpus/lessons/round-89.md` M89-10).

- **Row 169 (a refusal vocabulary must be closed over the refusal texts the tool itself emits, and the exit code is part of the class).** A class key built from the packer's message is only sound if the tool emits that message for every member of the class, and the same message is not two classes. Round 89 measured both ways: the same tamper class answers `header corrupted` on three carriers and `corrupt b_info` on `libz` (`b0.sz_cpr:=sz_unc+1`), so a message-keyed router mis-routes one carrier of every class; and the repair's own exit code is not a recovery signal — `b0.method^=0xFF` and `p_info.p_blocksize^=0xFF` both exit 0 with class `intact` on a file `upx -t` still refuses. A class key must be a (tamper domain, deciding arm) pair and must name the exit code it is judged by: rc 0 is not recovery, and a message that varies by carrier is not a key. Round-89 case: `.ufo/waves/round-89/w1/ExecMatrix/matrix.json` (48 cells, `unclassified []`, `met_target true`) — `b0.sz_cpr:=sz_unc+1` answers `header corrupted` on jq/xxd/dinit and `corrupt b_info` on libz; `b0.method^=0xFF` and `p_info.p_blocksize^=0xFF` repair rc 0 with `repaired_tests_clean false` (`corpus/lessons/round-89.md` M89-11).
