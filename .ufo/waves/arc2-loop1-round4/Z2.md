Mechanism (read from the gate source, not guessed): `Tree.lines()` runs
`git_show()`; on error it adds the target to `self.reported` (`:119-122`) **but
files no finding** — the comment assumes the snapshot classes already filed
one. `check_entry` then reads `if target not in tree.reported:
findings.add("citation_file_absent", …)` (`:157-164`), sees the target marked,
and skips. So an in-repo resolution failure is marked-and-swallowed, never
filed. With a bad root or a dead rev every target fails that way → zero
findings → `clean`. The empty-table case (`{}`) trivially has no entries. The
snapshot path does file (`pointer_table_unreadable`/`snapshot_missing`/
`snapshot_tampered`, `:126-151`), which is why those two controls still exit 2.
A run that graded nothing therefore exits 0 — the declared map's worst case.
