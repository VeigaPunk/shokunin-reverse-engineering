### 5.2 The three edits (diff: +72/−9 lines)

1. **`rev_resolves(root, rev)`** — a new guard called from `run_check` before
   any entry is graded. It runs `git -C <root> rev-parse --verify --quiet
   '<rev>^{commit}'`; on failure it files `rev_unresolvable` and returns. This
   is the edit that closes the false green.
2. **`rev_unresolvable` and `gate_error` added to the could-not-evaluate class
   set** in `Findings.verdict()`.
3. **`run_main()`** — wraps `main()`; any uncaught exception prints
   `CITATION_DRIFT: gate_error entry=<uncaught> <Type>: <msg>` plus a
   `CITATION_DRIFT_VERDICT: could-not-evaluate findings=1 exit=2` line and
   returns 2. `__main__` now calls `run_main()`.

A side effect worth recording: the wrapper caught a real fault during my own
first selftest attempt (the `/tmp` quota wall, §8) and reported it as
`could-not-evaluate exit=2` with a one-line cause instead of a traceback. The
class is closed, not just the two instances R3 named.

### 5.3 The two new self-test cases

`expected.json` gains `rev_unresolvable` (exit 2, finding `rev_unresolvable`)
and `gate_error` (exit 2, finding `gate_error`). Both assert the **outer**
contract, so the self-test runs them through `sys.executable <script>` as a
registry consumer would, not through `run_check` — otherwise they would test
the inner functions and never exercise `run_main()`. This is what the selftest
