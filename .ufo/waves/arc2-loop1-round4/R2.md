## 3. The probe/gate boundary vs PROTOCOL:363-364

```console
$ sed -n '360,364p' /home/vgpnk/Projects/shokunin/PROTOCOL.md
## Gate standard

A **gate** is a committed, re-runnable verdict script a lane owns: it reads surfaces, compares them
against expected values persisted in its own repo, and returns a verdict. A tool that cannot fail is
a **probe**, and is registered as one.
```

The definition is a biconditional in effect: *cannot fail* ⇒ probe. This artifact
can fail (rc=1, `failed`, 10 findings — §2.4). Therefore:

- **As a gate.** It meets the definition (committed, re-runnable, compares
  against `pointer-table.json` + `expected.json` persisted in-repo, returns a
  verdict), and it meets the Self-test (:370-374), Two-evidences (:375-382, modulo
  the unread `frozen_run`), Scope (:392-396) and verdict-map (:365-369) clauses.
  `kind=gate` is the honest label, and the row fields at :387-388 fit as written.
- **As a probe.** The label is available only by removing the failure path — i.e.
  always exit 0 while printing the findings (the shape CR4 recommended for
  E23's instrument, `CR4.md:366-373`, whose exit expression excludes
  `pointer_drift`). A probe that exits 1 is a gate wearing a probe's name, and
  the row's own verdict-map column would then be false.

**What "must still hold" under either label.** The claim's list (self-test,
frozen digests, declared exits) is, strictly, the *gate* clauses; the Self-test
clause binds "every gate" (:370) and a probe has no verdict to map. Keeping all
three is cheap and I recommend it — but the decisive clause is the definition
above, and it is the one the claim's `kind=probe` contradicts. Declaring exits
remains necessary regardless, because an undeclared nonzero code reads as
`could-not-evaluate` (:365-367) and a consumer cannot tell a probe's diagnostic
exit from a gate's failure.

**Closure consequence, for the parent's round notes** (:397-402): a red gate is
a conformance defect routed to its owner, status-neutral; the integrator verifies
committed evidence (self-test tally, frozen-run verdict, the revision measured)
and does not execute a sibling's gate. So the `frozen_run` block being unread is
not merely cosmetic — it is the artifact the integrator would check.
