## 4. Probe/report semantics — text the parent may land VERBATIM

```text
CITATION-DRIFT PROBE — semantics (seat E17, arc2-loop1-round4; candidate, not yet landed)

WHAT IT IS. A reporter, not a gate. It reads a pinned pointer table and prints
what it finds; it cannot fail a round. PROTOCOL.md:363-364 reserves the word
"probe" for exactly this: "A tool that cannot fail is a probe, and is
registered as one."

OUTER CONTRACT (exit codes).
  0  reported            a report was produced. Drift findings are content,
                         never a red verdict.
  2  could-not-evaluate  a configuration/input error made the report
                         impossible: unusable root or revision, unreadable
                         table or expected file, unrecognized table schema,
                         missing/tampered/unpinned snapshot, absent citing file.
  Exit 1 is NEVER used. Under the protocol's undeclared-code rule any other
  nonzero code reads as could-not-evaluate.

FINDING CLASSES (the report vocabulary).
  drift_reported         an ASSERTING pointer names a target line or range
                         that does not hold the claimed content. This is the
                         class the lane cares about.
  drift_recorded         a RECORD-OF-DRIFT pointer names a dead line. The line
                         exists to record that the pointer died; reporting it
                         is completeness, not defect. Never a red.
  citation_moved         an anchor entry's content survives at a line other
                         than the pinned one.
  citation_historical_ok a stamp-qualified pointer that no longer resolves; its
                         own text names the revision it was accurate at.
  symbol_resolved        a content-anchor row for an operator-owned file: the
                         section was found and the value matched inside it; the
                         resolved line is printed for the record and is NOT
                         graded, because that file's line numbers are not
                         pinnable values (measured: the rea stanza moved
                         :1284 -> :2938 -> :3225 -> :3296 -> :3155 while the
                         pinned value rea-agents@6.7.0 never changed).

RECORD CLASSIFICATION. A dead pointer is classified as a record when any of:
the row carries `"record": true`; the nearest preceding heading matches
/errata/i; or the citing line matches a record marker (superseded, "do NOT
re-point", "held the ... stanza", "earlier pointers", "kept as history", ...).
The classification reason is printed with the finding as [record: ...] so the
call is auditable, and an asserting control on the same fixture reads
drift_reported instead.

WHY THE CLASS EXISTS. The lane's append-only errata deliberately name dead
line numbers. A checker that counts them as defects reddens the lane's own
correct repair — measured: E15's base draft on the round-3 errata fixture
returns "failed findings=6 exit=1"; this probe on the same fixture returns
"reported drift=2 recorded=4 findings=6 exit=0".

FAIL-CLOSED SCHEMA. A table with no `entries` or `pointers` list, an empty
list, or any row whose kind is outside {extracted, exact, anchor, line,
symbol} is `table_schema_unrecognized` (exit 2). "Checked nothing" must never
read as "found nothing" — measured defect: the committed e16-table.json
(51 `pointers` rows) read as zero entries and printed a clean run before this
rule was added.

CROSS-CHECK ROLE. Registered as a probe, it reports the citation family
round-over-round; it gates nothing and no round outcome depends on its output.
The round-3 errata fixture is its standing acceptance test: the four
errata-internal dead tokens must come back drift_recorded, the two asserting
controls drift_reported, exit 0.
```
