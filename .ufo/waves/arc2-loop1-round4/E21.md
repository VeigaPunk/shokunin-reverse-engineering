### 2.5 Why — the mechanism, read from the instrument

`classify()` (`c1-census-v9.py:266-283`) drops any block that matches
`REA_GATE` (`:110`) but yields no *occurrence*:

```
273   occ.append(("pin", …))            # rea-agents@(\d+\.\d+\.\d+)
278   occ.append(("bare", …))           # (?<![\d.])6\.\d+\.\d+
279-281 if not occ: … ptr …             # ((?:~|/)[\w./+-]+\.(?:json|toml|ya?ml)):(\d+)
282-283 if not occ: continue             # block is skipped entirely
```
Confirmed by direct regex probe on the candidate lines: the clean block
`REA_GATE=True PIN=False VER=False PTR=False`; the rooted-pointer block
`PTR=True`. So the clean wording *does* match the gate (its stanza key
`[mcp_servers.rea]` contains `mcp_servers`) yet contributes nothing, because
the occurrence test — not the gate test — decides whether a block becomes a
locus. A control variant with the stanza key removed entirely
(`REA_GATE=False`, no occurrence) also reads `loci=2`, isolating the cause.

Note the PTR test is only reached when there is no pin and no bare version, so
a block carrying both a pin and a pointer is counted once, as a pin.

## 5. Conclusions, labeled

**Observations** (ran/read this session): the instrument's re-extraction and
sha256 match `213fe679…` / 429 lines (§2.1); the pre-pair shape gate 6/5/1 and
`sha256sum -c` 5/5 rc=0 (§2.2); the HEAD baseline `FAIL undeclared=2` with the
two SCORECARD loci and `SKILL loci=2` (§2.3); the eleven rule-#11 variants and
their exit codes/loci (§2.4); the instrument's `REA_GATE`/`PIN`/`VER`/`PTR`
definitions and the `if not occ: continue` drop at `c1-census-v9.py:279-283`
(§2.5); command A at real HEAD `10/10, 10.0/10.0` and the four surrogate
revisions (§2.6); the re-key-only FAIL, the two-edit PASS (exit 0), and the
round-4-records re-break with both green routes (§3).

**Inferences** (from those observations):

1. The census's PROVINCE/SKILL reading is insensitive to rule #11 *by
   construction*, not by luck: the craft section is outside every declared
   SKILL range, and a block becomes a locus only if it yields a pin, a bare
   `6.x.y`, or a rooted `path.ext:NNNN` occurrence. Any wording that avoids
   those three occurrence classes cannot move the verdict.
2. Because the new bullet's own subject is "never cite bare line numbers into
   operator-mutable files", the tempting illustrative form — a concrete
   `~/.kimi-code/config.toml:3298` — is exactly the form that creates a third
   UNDECLARED locus. The rule can be written, and is best written, without
   naming any live pointer: the churn chain as bare `:NNNN` tokens and the
   stanza key are both invisible to the instrument.
3. The re-key is not a one-line change: the instrument asserts DATED markers
   (G15) and demands receipt language for `current-ok` loci (G11), so declaring
   the round-2 records blocks exposes two further pre-existing gaps that the
   `undeclared=2` failure was masking. C3's stated measurement ("census PASS at
   the work commit") is reachable, but only with the companion `SCORECARD.md:731`
   edit.
4. The instrument being fence-only means C2's plan to commit it under
   `.ufo/gates/` is what makes the re-key landable at all; a re-key that exists
   only inside a round-2 report's fenced block is not a durable fix.

**Unknowns**:

1. Whether the parent prefers the round-4 records block to be declared in the
   re-key or simply written without a bare version token — both are verified
   green, and the choice affects only the re-key's range list.
2. Whether round 4 appends further records blocks after this seat runs (later
   seats' reports, a LOG entry, the round section); each new block with a bare
   `6.x.y` will need the same treatment. The two rules from §3-F3 are the
   general fix, but I did not test a block appended after the re-key is applied.
3. Whether the parent wants `SCORECARD.md:731`'s wording changed at all — the
   G11 fix requires the literal word "receipt" (or `2026-10-18`, `SHA-256`,
   `re-grepped`) in that block; the edit I verified is minimal but it does edit
   a landed round-2 record, which is a parent call.
4. Whether the census's occurrence-first drop should itself be recorded as a
   defect class (a gate-matching block with no occurrence is silently skipped).
   It is the reason this seat's answer is "no change", but it also means the
   census does not read prose — I did not judge whether that is intended.
