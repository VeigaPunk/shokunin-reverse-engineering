## A. C1 shortcut — pass all five arms without an ordered post-probe check

**Command.** Two independent shortcut counters were generated by exact-string patch of the frozen
file (never an edit of the frozen file), then run:

```
$P -I -B <scratch>/S_A1.py --verify --repo <lane> --work <scratch>/S_A1-work-verify --out out/S_A1-verify.json
$P -I -B <scratch>/S_A2.py --verify --repo <lane> --work <scratch>/S_A2-work-verify --out out/S_A2-verify.json
```

**Exit.** `0` for both. **Observed.** `passed 5 / 5`, `ok true`, for both
(`evidence/S_A1-verify.json`, `evidence/S_A2-verify.json`).

Diffs (`evidence/S_A1.diff`, `evidence/S_A2.diff`):

* `S_A1` — *no post-probe scan anywhere*, and the a2 fixture plants the cache before the scan and
  runs the probe **guarded**:
  ```
  -    post_cache = mod.cache_entries(root)
  +    post_cache = pre_cache  # SHORTCUT: no post-probe scan
  ...
  +    (fx2 / "__pycache__").mkdir()
  +    (fx2 / "__pycache__" / "fixture_mod.cpython-315.pyc").write_bytes(b"planted\n")
  ...
  -                        fixture_probe(mod, args.python, fx2, guarded=False),
  +                        fixture_probe(mod, args.python, fx2, guarded=True),
  ```
  a2 still passes: `ok false`, `cache_present` names the `.pyc`, `probe.ok true`. The a2 condition
  is only `ok is False and bool(named_pyc) and probe.ok is True` — it never reads *which* probe
  ran, so the arm named `a2-unguarded-fixture-red` is green for a counter whose probe ran **with
  `-B`**, contradicting the predicate's own words ("the same probe without -B or the bytecode env
  makes closure.ok false").
* `S_A2` — the ordered post-probe scan is kept, but the a2 probe wrapper runs guarded and then
  manufactures the cache:
  ```
  +def planted_probe(mod, python, root):
  +    def run():
  +        ok, msg = fixture_probe(mod, python, root, guarded=True)()
  +        if not ok: return ok, msg
  +        (root / "__pycache__").mkdir()
  +        (root / "__pycache__" / "fixture_mod.cpython-315.pyc").write_bytes(b"planted\n")
  +        return True, "ok"
  +    return run
  ...
  -                        fixture_probe(mod, args.python, fx2, guarded=False),
  +                        planted_probe(mod, args.python, fx2),
  ```
  Its a2 detail is **byte-identical** to the frozen counter's a2 detail
  (`evidence/frozen-verify.json` vs `evidence/S_A2-verify.json`, dict equality `True`):
  `{"cache_present": ["__pycache__", "__pycache__/fixture_mod.cpython-315.pyc"],
    "findings": ["cache present after probe 2: …"], "ok": false,
    "probe": {"message": "ok", "ok": true}}`.
  The only difference between the two counters is their source, and the source is what the freeze
  pins — the receipt cannot tell them apart.

`S_A1`'s receipt does carry one extra tell (a second finding, `cache present before probe`), but no
arm condition reads `findings` and the a2 detail recorded by `run_verify` does not even include
`cache_before`, so the tell is not load-bearing.

**Verdict — counter fails (as a witness).** The five frozen arms do not distinguish an ordered
post-probe check from a pre-scan plus a plant. The frozen counter itself *does* implement the
order (read at `closure_state`, `post_cache` after `probe_fn()`), and its `--verify` is legitimately
5/5 — but 5/5 does not establish the C1-F1 repair, because a counter lacking it scores the same.

**Impacted axis.** depth (R66-C1). The defect is in the claim's evidentiary link, not in the frozen
file's behaviour.

**Smallest safe correction.** Make a2 witness provenance, not just the file's existence:
(a) record the probe argv/env the counter itself chose in the arm detail and require
`"-B" not in argv` and `PYTHONDONTWRITEBYTECODE` absent; (b) require `st2["cache_before"] == []`
as an arm condition (the field exists, is emitted by `closure_state`, and the arm does not test
it); (c) add the discriminating mutant to `--selftest`: *guarded probe + planted `.pyc` must leave
a2 false* — exactly `S_A1`, which today reports 5/5.

## B. C1 escape — an arm that depends on a value the counter writes rather than reads

**Command.**

```
$P -I -B <scratch>/S_B.py --verify   --repo <lane> --work … --out out/S_B-verify.json
$P -I -B <scratch>/S_B.py --skip-run --repo <lane> --work … --out out/S_B-skip-run.json
```

`S_B` leaves `skip_run_receipt` untouched and changes only `main`'s emission
(`evidence/S_B.diff`):

```
     if args.skip_run:
         result = skip_run_receipt(args)
+        result["closure"] = {"ok": True}
+        result["closure_claimed"] = True
         emit(result, args.out)
```

**Exit.** `--verify` → `0`, `passed 5 / 5`. `--skip-run` → `1` while emitting
`{"closure": {"ok": true}, "closure_claimed": true, "verified": false, "exit": 1}`
(`evidence/S_B-skip-run.json`).

**Observations.**

1. a5 is a pure literal self-assertion. `skip_run_receipt` returns the constants
   `closure: None, closure_claimed: False`; the arm compares `skip_run_receipt(args)` against those
   same constants. It never spawns `--skip-run`, never reads the emitted JSON, and so cannot fail
   for any argument, any environment, or any CLI drift. Here it passes while the actual
   `--skip-run` emission **claims a closure with `ok: true`** — precisely the Q5 defect the repair
   exists to remove. The arm is blind to it.
2. a1's `count_ok` clause is an identity, not a read. `entries = len(manifest) + 3` and
   `expected_count = len(FIXTURE_RELS) + 3`, with the manifest built from `FIXTURE_RELS`; the two
   sides cannot differ. Direct call on the frozen module:

   ```
   closure_state(mod, fixture, …, manifest={}, expected_count=3, probe=lambda: (True, "synthetic-ok"),
                 external_pins=fixture_pins(fixture))
   → {"entries": 3, "count_ok": true, "missing": [], "ok": true, "findings": []}
   ```

   An **empty manifest** reports a green closure. a1's count clause adds nothing; the real count
   assertion lives only in a3/a4 (against `COUNT = 30`). a3's `count_ok` is likewise an identity on
   `len(mod.CLOSURE) + 3 == 30`, though there the manifest is an external read, so it is defensible.

**Verdict — counter fails (on a5).** Any arm whose inputs are the counter's own literals is not a
boundary test. a5 cannot detect the failure mode it is named for.

**Impacted axis.** depth (R66-C1), clause a5.

**Smallest safe correction.** a5 must observe the emission: run the `--skip-run` mode as a
subprocess (or capture `emit`'s text) and assert `closure` is absent/`None` and no `ok` is claimed
in the *emitted* object. For a1, either drop the vacuous count clause or compare against a fixed
external count independent of `FIXTURE_RELS`.

## C. C2 equivalence escape — agreement outside `RECIPE_A_KEYS`

**Command.**

```
$P -I -B tools/round-66/coverage-selfcheck.py --root <lane> --equiv --rev 7b63dd5d… \
    --work <scratch>/C/work --out out/C-equiv-head.json
```

**Exit.** `0`. **Observed.** `recipe_a_equivalent true`, `recipe_a_diffs {}`,
`recipe_a_block_keys` = exactly the nine `RECIPE_A_KEYS`
(`evidence/C-equiv-head.json`). The committed block's `print(json.dumps({…}))` emits nine keys and
nothing else, at both the base (`--equiv --rev 311079d8…`, exit 0, `diffs {}`, nine keys:
`evidence/C-equiv-base.json`) and HEAD. So at the base and at the freeze **no key outside
`RECIPE_A_KEYS` exists**, and the escape the question asks for is not realisable here. (The landing
revision is not yet measured; the recipe-A block is not a claim target and no claim edits it.)

The mechanism is nevertheless closed-world and silently tolerant. `recipe_a_equivalence` computes
`diffs = {k: … for k in RECIPE_A_KEYS if theirs.get(k) != ours.get(k)}` — it never inspects keys
present in `theirs` but absent from the tuple. Injected into the extracted block body by importing
the frozen counter and substituting `extract_recipe_a_block` with a wrapper that rewrites the body
(it rewrites only the extracted heredoc, not any file; `recipe_a` itself is untouched, so this
measures the comparison, not a transcription change). With `'policy': 'invented'` added to the
printed dict and `mapped` unchanged, `recipe_a_equivalence` returned:

| block mutation | `recipe_a_equivalent` | `diffs` | block keys |
|---|---|---|---|
| none (control) | `true` | `[]` | 9 |
| extra key `policy` = `"invented"` | **`true`** | `[]` | 10 (includes `policy`) |
| in-set `mapped + 1` | `false` | `["mapped"]` | 9 |

**Named key and consequence.** `policy` — i.e. any field outside the nine. If a later revision's
recipe-A block emits a tenth field (a filter flag, a policy, a mode), `--recipe a` will disagree
with the committed block in that field while `recipe_a_equivalent` stays `true`; the claim's
"recipe A verbatim" would then be false in exactly that field, undetected. The missing-key
direction is safe (`theirs.get(k) → None` produces a diff). Mitigation already present: the receipt
records `recipe_a_block_keys`, so a reviewer can see a tenth key — but no atom reads it.

**Verdict — counter holds at base and freeze; latent escape named.** This attack failed to
falsify C2 today; it did not fail because the mechanism is sound, but because the block happens to
emit exactly the nine compared keys.

**Impacted axis.** calibration (R66-C2), the `recipe_a_equivalent` clause.

**Smallest safe correction.** Add `extra = sorted(set(theirs) - set(RECIPE_A_KEYS))` to the
equivalence result and make equivalence false (or a finding) when `extra` is non-empty; equivalently
assert `sorted(theirs) == sorted(RECIPE_A_KEYS)`.

## D. C2 atom escape — `mismatches == 0` without repairing the row

**Fixture.** A scratch git repo (`D/fixture`, 149 tracked files: `corpus/knowledge/*`,
`corpus/README.md`, `SKILL.md`, `SCORECARD.md` exported from HEAD `7b63dd5d`), one commit per row
variant; `git rev-parse --show-toplevel` asserted to equal the fixture before every add/commit.
Scored by the **counter CLI**, not by an in-process stub:

```
$P -I -B tools/round-66/coverage-selfcheck.py --root <fixture> --selfcheck --rev <commit> \
    --work <scratch>/D/w-<label> --out <out>/D-<label>.json
```

**Observed.**

| row variant | exit | mismatches | A1 | A2 claimed → observed |
|---|---|---|---|---|
| `R1` honest repair: `145/145 knowledge files mapped at the landing` | 0 | 0 | true | [145,145] → [145,145] |
| `R2` `145/145 …; the round-53 142/142 knowledge files receipt is retained` | **0** | **0** | true | [145,145] → [145,145] |
| `R3` `142/142 … at the landing; the stem recipe says 145/145 knowledge files` | 1 | 1 | true | [142,142] → [145,145] |
| `R4` `9.79 → 9.72 → 10.0` + `145/145 …` | **0** | **0** | true | [145,145] → [145,145] |
| `R6` no fraction at all | 2 (no receipt) | — | — | could-not-evaluate |

`recipe_a_equivalent` is `true`, `recipe_a_hidden_count` 3 in every scored case (the fixture's block
is unchanged). Receipts: `evidence/D-R1…R4.json`; R6's stderr is
`could not evaluate: coverage row cites no '<mapped>/<files> knowledge files'`.

**R2, the escape.** The committed row text is

```
| coverage | 9.72 → 10.0 | 145/145 knowledge files mapped at the landing; the round-53 142/142 knowledge files receipt is retained | `corpus/README.md` Coverage map; command A | 66 |
```

The counter exits **0 with `mismatches 0`** while the row still asserts `142/142 knowledge files`.
`parse_row` uses `re.search(r"(\d+)/(\d+) knowledge files", row)` — the **first** occurrence — so a
correct fraction prepended to the stale one hides the stale one. This is not a theoretical shape:
the real row already carries `142/142 knowledge files` in its prose, and the natural repair is to
prepend the new fraction and leave the history in place. The qualification ("receipt is retained")
is invisible to the parser.

**R4, second escape.** `parse_row` takes `score_cell.rsplit("→", 1)[1]` — the text after the
**last** arrow. A row whose score cell is `9.79 → 9.72 → 10.0` scores A1 true while retaining two
false baseline claims in the same cell.

**Bounds.** The correct value must appear first/last respectively; the stale-first ordering (R3)
and a wrong fraction (R5, `145/146`) are caught, and a row with no fraction is a clean
could-not-evaluate (R6, exit 2, no receipt) rather than a pass.

**Verdict — counter fails.** `mismatches 0` does not certify that the self-assessment row is
repaired; it certifies that the first recognized fraction and the last arrow's number are current.
A landed row can keep the stale `142/142` claim and still pass.

**Impacted axis.** calibration (R66-C2), the after-arm ("this round repairs the `## Owned axes`
coverage row"). The L1 must read the landed row text; the counter cannot do it.

**Smallest safe correction.** A2 must collect **every** `n/m knowledge files` occurrence in the row
and require all of them to equal stem (or require exactly one occurrence and reject extras);
A1 must require exactly one arrow, or validate every segment against the recorded history.

* `mismatches 1`, `ok false`, `recipe_a_equivalent true`, `recipe_a_hidden_count 3`,

the row cites `142/142`, the stem recipe observes `145/145`.

At HEAD the identical run also exits `1` with the same atom pair (`evidence/E-selfcheck-head.json`):
the row has not yet been repaired, as expected before the landing. The base-arm clause of R66-C2 is
honest; the after-arm remains to be measured at the landing.

**Verdict — counter holds.** This attack failed to falsify the base arm.
