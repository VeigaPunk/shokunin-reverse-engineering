# E4 — heavy decompile analyzer registry names (Ghidra 12.1.4 PUBLIC)

## Verdict

The live disable list is wrong on the third name, and that single mismatch aborts the whole pre-script before any analyzer is disabled. For this install the canonical `Analyzer.getName()` strings are:

- `Decompiler Parameter ID` — class `DecompilerFunctionAnalyzer` (matches the live list)
- `Decompiler Switch Analysis` — class `DecompilerSwitchAnalyzer` (matches the live list)
- `Call Convention ID` — class `DecompilerCallConventionAnalyzer` (the live token `Decompiler Parallel Convention Analysis` is not a registry name)

`analyzeHeadless` has no `-disableAnalyzer` flag. REA disables by passing those `getName()` strings to `ReaGhidraAnalysisOptions`, which requires `AutoAnalysisManager.getAnalyzer(name) != null` and an analysis-option key equal to that same string.
