### 2.3 What is real about `--scope` vs service mode

`man systemd-run` DESCRIPTION (this host, read 20:51Z):

- Service (default): "clean and detached execution environment, with the service manager as its parent process"; `systemd-run` "start[s] the service asynchronously … and return[s] after the command has begun execution".
- `--scope`: "executed by systemd-run itself as parent process and will thus inherit the execution environment of the caller"; "Execution in this case is synchronous, and will return only when the command finishes."

`man systemd.scope`: scope lifecycle is bound to "the existence of at least one process in the scope", not to one main PID; processes "generally remain children of the original process that forked them off".

**OBSERVATION:** the lifetime difference is in the man page. Scope mode makes `systemd-run` the parent and blocks until the command ends. Service mode detaches and returns.
**INFERENCE:** killing that blocked `systemd-run` *would* be a way to stop a scope. That mechanism was not the round-4 terminal event (§2.2).
