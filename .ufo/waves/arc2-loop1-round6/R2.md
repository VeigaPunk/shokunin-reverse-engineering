### Inference

The r5 miss is a missing rev preflight, not a wrong drift rule. Closure is: if `git rev-parse --verify --quiet --end-of-options <rev>^{tree}` is nonzero, emit `revision_unresolvable` and return before `Tree` / the entry loop. That id must be in the CNE tuple (`:72-74`) so both probe and `--strict` exit 2 (`:69-76` checks CNE before the strict branch). Do not change `git_show` or add `citation_file_absent` to the CNE set.

`^{tree}` accepts commits, abbreviated commits, and trees (current clean path) and rejects dead hex, absent names, empty `--rev` (today a false clean), and blobs (same misreport as deadbeef). `^{commit}` rejects the tree path that is clean today — that is a new failure, and it violates the claim's "all other behaviors byte-stable." `--end-of-options` was in the scratch copies; the stable set stayed byte-identical on git 2.55.0.

Check after `root_ok` and after the table-load `return`, not before JSON load. Bad root stays `root_unreadable` (measured, including bad root + dead rev). Missing table stays `pointer_table_unreadable` even if `--rev` is also dead.

One selftest case is enough: the predicate is rev-parse failure, so short `deadbeef`, absent names, and `''` are the same branch. Pin the case on the 40-hex string so a fixture commit cannot abbreviate-match `deadbeef`. Append to `expected.json` `selftest`; do not reorder; do not touch `frozen_run` or `pointer-table.json`.

def rev_ok(root, rev):
    """True iff --rev peels to a tree. A dead, absent, empty, or non-tree

        ["git", "-C", root, "rev-parse", "--verify", "--quiet", "--end-of-options",
         "%s^{tree}" % rev],
        capture_output=True)
    return proc.returncode == 0
