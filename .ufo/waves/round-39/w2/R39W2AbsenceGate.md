## 7. Structural finding: the selftest's exit signals are self-referential

Every `want_code` in `selftest()` is the same `ABSENT`/`PRESENT`/`EXIT_ERROR` constants the code under test uses; the only numeric pin is the `'"exit_code": 0'` substring in `json-shape` (ABSENT, JSON mode only). Consequences, demonstrated:

- Constant drift on `EXIT_ERROR` (m10) or `PRESENT` (m16) passes 18/18.
- m15 (full swap `0,1,2 → 1,0,2`) makes every case "pass" symbolically; only the `json-shape` literal fails (`"exit_code": 1` vs wanted `0`) — and the selftest **still exits 0**, because its failure return value is `PRESENT`, which the swap turned into 0 (`out/st-m15-constants-swapped.txt`: `SELFTEST cases=18 pass=17 fail=1`, process rc 0). An rc-based CI harness sees green on a mutant that inverts both documented verdicts; the demonstration receipts (rc 0/1) or parsing the `pass=` line are what catch it.

Recommendation for the integration owner (not applied — frozen artifact): pin each documented exit code with at least one numeric literal assertion, and make the selftest's own failure signal independent of the constants under test.
