- **SquashFS `extract-firmware` outcome triage (round 39).** An REA 6.5.0 `extract-firmware` envelope on a SquashFS v4 input resolves to one of seven classes from three features — the extraction-gap `kind`, the gap's `dependencies` name (`sasquatch` for little-endian, `sasquatch-v4be` for big-endian), and whether the recorded sasquatch argv carries a standalone `-be` token — because unblob 26.6.4 drops `-be` exactly when `bytes_used == mkfs_time` and the AVM-BE format stores the same value in both fields (`corpus/knowledge/2026-10-26-r39-sqfs-outcome-triage.md:23-34`). A failed extraction and an intact AVM-BE image therefore look alike — `extractor-failure`, zero files — and only the `-be` cell separates an AVM-marker drop (image intact, give the flag back) from body damage (do not retry): never the file count (`corpus/knowledge/2026-10-26-r39-sqfs-outcome-triage.md:36-53`). Symlinks split the same way — an in-tree target stays metadata as exactly one `unpublished-entry` gap, an escaping target is removed as `MaliciousSymlinkRemoved` with no gap, and neither is a failure (`corpus/knowledge/2026-10-26-r39-sqfs-outcome-triage.md:54-59`). Rows are tried top to bottom and the first row whose every condition cell matches names the class; a malformed condition cell makes the table unevaluable, never a silent non-match.
