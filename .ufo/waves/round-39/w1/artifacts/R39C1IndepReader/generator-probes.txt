## P2 inode ref block field is a block count, not a byte offset
L-le-gzip (300 one-byte files): inode table 10836 bytes, first block payload 8192, second block header at 8590
  stored root_inode ref = 0x0000000000010a30 (block field 1, offset 2608)
  the second metadata block starts 8194 bytes after the inode table start, so the ref must be 0x0000000020020a30; the generator stored the block *count* (1) instead, and the reader looks at inode_table_start+1
  contrast: K1 root_inode ref = 0x15c (block field 0, offset 348) and K1 fits one inode block, so count and byte offset coincide
  sqfs-list exit 2: sqfs-list: metadata block at 397: decompression failed: Error -3 while decompressing data: invalid stored block lengths
  unsquashfs exit 1: FATAL ERROR: read_inode: failed to read inode 397:2608
