## Verdict

**NOT READY to freeze as drafted.** The freeze-integrity rule is not enforced identically by the two counters, and neither counter binds its own executing bytes or the `--freeze` argument to the frozen record.

- C1 (`c1-counter.py`) **admits** changes that the plan's rule refuses: any *newly added* file under `tools/round-49/` (plain add, nested add, or add via merge), and any post-freeze edit of a frozen file whose name git quotes. C2 refuses every one of these.
- Neither counter catches: (a) an altered copy of the counter run from outside the lane (C2 altered copy reads `mismatches 0`, exit 0, at the freeze; C1 altered gate reads past `frozen_path_changed`); (b) history substitution by `refs/replace` (default git config) or `.git/info/grafts`; (c) a squash that removes the touching commits; (d) an operator-chosen `--freeze` commit.
- Pre-freeze must-fix set (in priority order): **F1, F4, F2**; then **F5 mitigation, F7 binding**; F3 is a plan-text scope fix; F6 is a disclosed-limit sentence.

Coverage: 30 matrix rows (about 25 distinct manoeuvres plus 5 probes: replace-off, mitigation, squash, grafts, altered counters) run through both counters' freeze walks; see `CritFreeze/results/matrix.md`. Calibration: walk-level results are direct observations; full-counter acceptance (exit 0) for an admitted manoeuvre was **not run** (host load 53.3 on 32 cores, 5 GiB available; the controls positive arm was not run by me).
