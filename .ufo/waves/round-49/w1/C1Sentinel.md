# R49 wave 1 — C1Sentinel (security review of the C1 after-freeze runner, pre-freeze draft)

Scope: `tools/round-49/c1-run.py` and `c1-run.sh` (draft, read-only) and the unblob tee they generate; plus the counter's exec and provenance surfaces where they touch the same evidence. Data procedure NOT run. Every reproduction used a stub REA (`--fake-rea`) or a dry run, inside `/fast/scratch/hyaku/kaidoku-r49/C1Sentinel` (removed after copying receipts). Nothing was written to the lane, the fleet repo, or any path outside scratch.

## Verdict

**Not freeze-ready as drafted.** Four runner defects reproduced (F1–F4), each fixable before the freeze in `c1-run.py` alone with no plan change: carrier-id path traversal (with `--force` it deletes arbitrary directories, including the evidence root's parent), a `--fake-rea` guard bypass into the committed evidence root, a non-fatal copy failure that still reports `ok`, and the top-level receipt-name collision that writes through a symlink. Two counter-side facts are calibration issues the L1 must decide before the freeze: the counter binds **no committed tree byte** (so the "verbatim" copy and its symlinks are unscored), and `oracle_tool_ok` executes `oracle.tool` before its hash verdict. Nothing found lets the runner or counter execute content taken from an extracted tree.

## Checked and not exploitable

- **REA argv / cid injection:** REA spawns with `shell: false` (`ProviderProcess.js` L53) and the runner uses `subprocess.run(argv)` without a shell. `REA_UNBLOB_COMMAND` must be absolute and REA `realpath`s and sha256s it (`FirmwareCommand.js` `resolveFirmwareCommand`). A shell metacharacter in an id reaches argv as a literal (F12 is display-only).
- **Tee:** a constant string (`TEE_SOURCE`) written into the scratch run dir, `set -u`, forwards argv unchanged, copies only the `--log` path REA supplies, exits with unblob's code. No write path of its own. (Note `unblob_path()` is `~/.local/bin/unblob` while `tool_pins` resolves via the fixed PATH; both are the same binary on this host (`/usr/bin/unblob` absent, `command -v -a` lists `~/.local/bin/unblob`), so latent only.)
- **Executing extracted content:** the runner executes only `unblob --version`, `sasquatch -version` (fixed PATH) and REA. The counter executes `node xpin-attribute.mjs` on envelopes it wrote into `work`, `git`, the REA rerun on carrier bytes, and `oracle.tool` (F8). None executes a path from `firmware.bin_extract/`.
- **Symlink-following in snapshot:** `snapshot_tree` checks `islink` before `isfile`, and `os.walk` does not descend symlinked dirs. `shutil.rmtree` is symlink-safe. Run-dir cleanup cannot escape through a link.
- **Counter receipt provenance binding for the counter's own reads:** `show()` reads committed blobs via `git`, so the counter never follows a working-tree symlink.

## Calibration notes for the L1 fold

1. Fold before freeze (runner only): F1 (validate `cid` against `^[a-z0-9][a-z0-9-]*$`, realpath `outdir`/`run_dir` under their roots, refuse otherwise, exit 2), F2 (refuse `--force` unless realpath(outdir) is strictly inside evidence root and is not the root; never rmtree an id with `..`), F3 (exit 2 for `--fake-rea` with `--data-run` or with a committed root), F4 (carrier `ok` requires `copied_verbatim` to be non-failed; an un-copyable tree is a failure), F6 (write receipts with `O_NOFOLLOW`, or refuse when a receipt name exists as a symlink after the copy), F11 (map `OSError`/`shutil.Error` to exit 2).
2. Freeze decision (L1): F5 is an unscored binding. Either add a counter clause that reads `firmware.bin_extract/` at REV and compares it to `extract-tree.tsv` and the census, or state the limit in the plan's "Disclosed limits" (it is currently absent). F13 must be either bound (add the clause) or removed from the docstring. F14: drop the `receipt` override in the counter.
3. F7 (kill process group + sweep `REA_PROCESS_RUN_ID` descendants) and F8 (hash-before-exec) are small code changes; F9 and F10 are informational.
4. Not run: the data procedure, any real REA extraction, the counter's rerun, and any `npx` install. No tool was installed. Only the `c1-run.py`/`c1-run.sh` bytes at review time are cited (sha256 `f9161ff3afa2ded9553ea77dc31432add67ca6f6a02e98b3eb22c74da33a46fb` and `5ebb453f6197a8d2fc7790e80ae3d357e0053e8bf9191cdb95d946ee78c0d366`).
