```text

        [relationship_coverage only when non-null], locations, evidence_links
```

`digestCanonicalValue` (`…/dist/domain/canonicalDigest.js`) is a streaming
SHA-256 over RFC 8785 canonical JSON (keys sorted, `JSON.stringify` values).
Recomputing the projection from the **r6 mid-rung envelope** with REA's own
hasher:

```text
$ node /var/tmp/arc2-l10r10-Z1-scratch/evid.mjs /var/tmp/arc2-l6r6-E9-mid/stdout.json
  recorded: ev_8b688ce7b54ef1d08823734fda2f062fd19dfa2ca9f4023c329cbae22f726986
  computed: ev_8b688ce7b54ef1d08823734fda2f062fd19dfa2ca9f4023c329cbae22f726986
  match: true
```

**Domain consequence (new, and it changes the recheck recipes):** `subject.name`
and `subject.local_path` are excluded, so for `analyze` the id is **path-free** —
`TMPDIR`/scratch path cannot perturb it (this is why the big leg's differing
`TMPDIR` was harmless, V6). And because the projection includes
`normalized_result`, the id is keyed on **results**, not only on the request.

**Rendering caveat (new).** The CLI's default output (no `--format json`) is an
*annotated rendering*, not a round-trippable object: `parameters` renders as
`null` where the hashed value is `{}`, and keys carry count annotations
(`limitations[10]`, `disabled_analyzers[3]`, `segments[9]{…}`). Recomputing the id
from the committed r7 receipt is therefore **impossible**; my own attempt yields a
consistent but wrong digest for both YAML envelopes while the JSON one matches.
Anyone wanting to re-derive an id from a committed envelope must re-run or
re-commit with `--format json`.
