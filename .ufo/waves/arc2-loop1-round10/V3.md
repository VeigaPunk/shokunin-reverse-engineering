## 4. Observation / inference / unknown

**Observation**
- The wave's bytes at verification time carry no C2 table edit and no `C2.md`
  (round-10 dir = 2 receipts, 901 B). Any "table extends to r7/r8 + SHONEN"
  statement is therefore a *plan*, not a landed measurement, at this position.
- The frozen run's `verdict: "failed"` reproduces **only under `--strict`**;
  default probe semantics report `findings=5|6 exit=0`. The pinned
  `expected_findings: ["citation_dead"]` is satisfied as a *member* of the
  finding set (2 `citation_dead` rows with the r6 table, 3 with the HEAD table),
  not as the whole set.
- `expected.json`'s `frozen_run` block is **never read** by the probe
  (`grep -c frozen_run citation-drift-probe.py` → `0`; the only key read from
  `expected.json` is `"snapshots"`) — reconfirming CR7 (arc2-loop1-round3 §3.2).
  So "frozen-run re-verified" is a **manual re-run against a record**, not a gate
  assertion; the record can drift silently.
- `SHONEN.md:6`'s range `SKILL.md:81-243` overshoots: the craft section's last
  content line is `:239`, `:242` is the next heading (`## Config custody …`).
  The `13/13` count in the same sentence **is** exact — the craft span `:81-241`
  holds exactly 13 bold rule bullets (`:86,108,118,137,151,162,170,175,187,196,207,219,233`).
- The probe reads the **table from the filesystem** but its **targets from Git
  objects at `--rev`** (`citation-drift-probe.py:91-100`). Consequence: the C2
  table edit can be pre-flighted *before* it is committed (as done in §2d),
  while the text it grades cannot be graded until committed.
- The `r7wall-r6-class-cite` pointer is *resolvable but weak*: `r7-pe-wall.md:11`
  cites `r6-pe-midrung.md:19` for "the same target that refused" by *class*, and
  `r6:19` is the scale-ladder line (it names the 91.6MB wall, not the refusal).
  The needle I propose pins what `:19` does say; a reviewer wanting the refusal
  itself should cite `r6-pe-midrung.md:11,13` instead.
- Repo hygiene for the integration `git add`: an untracked
  `.ufo/gates/__pycache__/c1-census-v10.cpython-314.pyc` (23,796 B, mtime
  20:59) now exists in the tree — bytecode residue from some seat *importing*
  the census module. It is not mine (I only executed scripts as `__main__`, which
  writes no cache) and it must not be committed. `git status --porcelain` today
  shows exactly two untracked entries: that dir and `.ufo/waves/arc2-loop1-round10/`.
- Independent corroboration of §2a: seat `E21.md:108` (same wave) also censuses
  the table as holding **13 entries**, and `E15.md:98`/`E23.md:231` both describe
  the C2 table rows as still to be filled — consistent with "unlanded".
