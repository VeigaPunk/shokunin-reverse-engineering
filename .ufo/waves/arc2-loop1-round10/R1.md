## 1. Verdict

**PASS WITH REQUIRED AMENDMENTS — the rerun is the right instrument and it worked, but as specified it tests a
different law than the one cited, its decision map has no row for the outcome leg 2 produced, and leg 2 as
launched was not the recipe it claimed to repeat.**

- **The rerun answered the question, in the strongest available form.** `arc2-r10-big` sealed `Result=success`
  / exit 0 with an envelope **byte-identical** to the r7 receipt (same sha256 `a77ebee8…`, `diff` clean):
  `evidence_id ev_a4aa9b0d…` reproduced, counts 9 / 75,218 / 137,345 reproduced. That is more than id
  equality — the whole canonicalized result reproduced at 91.6MB scale, so the r7 entry's last named unknown
  ("rerun id-stability", `corpus/knowledge/2026-10-18-arc2-r7-pe-wall.md:7,19,37`) closes on the equality
  branch. Wording constraint: this is **one repeat (n=2, same host, same recipe)** — "reproduced once", never
  "ids are stable".
- **The law cited is not the law tested.** `QUALITY.md:25` (criterion #15) says analyze ids are
  "content+params-keyed". The installed code shows the analyze `evidence_id` is `ev_` + SHA-256 over REA's
  canonical *semantic projection of the Evidence*, which **includes `normalized_result`** (segment table,
  `segment_count`, `procedure_count`, `string_count`) and excludes only the display subject
  (`local_path`, `name`). A rerun therefore does not test "did the same command hash the same"; it tests
  **whether the canonicalized analysis result reproduces** — a determinism test, and a stronger instrument
  than the corpus text claims. The corpus recheck wording ("only if the request bytes match", "a re-run needs
  the identical request bytes") is wrong as a sufficiency claim, and the observed pair confirms the code read:
  the two runs differ in wall (1438.082 s vs 1424.663 s) and peak (7.8G vs 7.9G) while the id is identical —
  neither timing nor memory is in the preimage.
- **"Different id" is not self-interpreting.** The claim's two-branch map ("equal → law confirmed at two
  scale points; different → stability boundary mapped") is under-determined: a differing id with differing
  counts *confirms* content keying (the finding is analysis nondeterminism); a differing id with identical
  counts is the only outcome that *refutes* the law for this verb. The counts are already free in the
  envelopes, so the discriminating observation costs nothing and must be pre-registered.
- **Leg 2 produced the map's missing third outcome, and its premise was false.** `arc2-r10-mid` is
  `Result=oom-kill` at **53.178 s**, 9G/1G-swap peak, with **zero `evidence_id`**. Its env matches r6's
  values, but it adds `MemoryMax=9663676416` + `MemorySwapMax=1073741824` — the **r7** leg's containment,
  not r6's: r6's own leg ran under a bare `/usr/bin/timeout` with **no memory cap**
  (`/var/tmp/arc2-l6r6-E9-mid/run-leg.sh:66`), and r6's own sampler shows the same analysis crossing
  9,437,184 kB of tree RSS at **t=+47 s** (193/486 samples over, peak 19,149,984 kB at t=767 s). The r10
  kill at 53.2 s is cap-induced and reproducible by construction; a re-run with the same cap fails the same
  way, so this is a **recipe defect, not a debt that time resolves**. The r6 mid-rung id is still untested.

**Inference**
- The rerun is the only instrument that can observe result reproduction at scale; at n=2 it is high-power to
  falsify and weak to confirm, which is why the equality result must be phrased as one observation.
- Equality landed in its strongest form (whole-envelope byte equality ⟹ id equality), which is itself evidence
  that the result content — not the request text — is what the id tracks.
- "Different id" is ambiguous until counts are compared; the claim's two-branch map was under-determined.
- Leg 2's kill is cap-induced and will recur under the same cap (r6's log crosses the same cap 6 s earlier
  than the r10 kill); host contention is an unresolvable co-factor this wave. Either way leg 2 is a recipe
  defect, not a debt.
- Because the preimage excludes the path, a second-path rerun would be strictly more informative per leg than
  an identical rerun (block (d)).

**Unknown**
- Whether the preimage contains any run-scoped field outside the printed envelope — undecidable without a run
  that yields a differing id (branch 2 of the decision rule).
- Whether r6's true cgroup-equivalent demand exceeded 9G (tree-sum overcounts shared pages; the uncapped r6 leg
  has no cgroup accounting).
- Whether the 17.7MB rung's `ev_8b688ce7…` reproduces at all: untested, and untestable under the cap the

  gone.

  host state at seal is not the host state at start).
