This is a line-addressed, not content-addressed, pointer class: insertions before the stanza move the target line down; deletions/rewrites can move it back up. A scratch-only behavioral check exercised the instrument’s `ptr_check` against a synthetic `config.toml` with the same pin: one harmless line inserted before the pin invalidated the old line and moved the valid target by one. The real config was not edited.

```text

after +1 inserted line, old line 4126: ('stale', "line holds no rea-agents pin: '# synthetic filler'")
after +1 inserted line, shifted line 4127: ('ok', 'pins 6.7.0')
```

The observed backup snapshots also show non-monotonic movement (3298 → 3157), so re-counting the target is necessary; applying a fixed offset is not valid.
