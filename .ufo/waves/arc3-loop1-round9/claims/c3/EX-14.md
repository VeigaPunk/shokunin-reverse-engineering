## Drift-class characterization and limits

- The gate derives each configured pin with a first-match `re.search` (`.ufo/gates/c1-census-v10.py:324-334`). The independent count above finds one Kimi match today, but **the gate does not enforce uniqueness**; if a second match appears, its live anchor remains the first match.
- The pointer check reads the cited line, looks for a `rea-agents@<version>` token, and compares that version with the client anchor (`.ufo/gates/c1-census-v10.py:466-482`); `ok` maps to `current-ok` (`:538-544`). It does **not** verify the cited line's enclosing `[mcp_servers.rea]` stanza. Uniqueness and stanza membership therefore remain outside this instrument's pointer assertion.
- A line pointer is perishable under edits that change the number of preceding lines; it is not a stable key. The scratch experiment measures this behavior without changing operator-owned config. I did not re-derive the historical sequence of earlier line positions.
