# Round 20 wave outcome recording — QUALITY #22

## Observations

- [O] `corpus/QUALITY.md:32` requires each wave-status claim to name its observation cutoff, distinguish terminal failures from seats not yet returned at that cutoff, and be reproducible from a retained per-seat record. Each seat without a report needs either its retained terminal error line plus transcript/result pointer, or `cause unknown` with what was tried. Later reclassification must be appended with its own cutoff; a headline count alone is inadmissible.
- [O] The generator interface is `--registration REG --report-dir DIR --causes CAUSES --out OUT [--selftest]` (`.ufo/waves/round-19/tools/wave-outcomes.py:50-52`; `.ufo/waves/round-19/w1/WaveOutcomesTool.md:28-30`). Registration is the `members`-keyed registry; R20 W1 currently names `.ufo/waves/round-20/wave1-registration.json`, schema `ufo-swarm-registry-v1`, and report directory `.ufo/waves/round-20/w1` (`.ufo/waves/round-20/wave1-registration.json:2-8`). Bind each wave to its own registration and report directory; R20 W2 should use its own registration and `w2/` directory when available.
- [O] Report presence means `<report-dir>/<seat>.md` is a regular file with size > 0; zero-byte files, directories and dangling symlinks are absent (`.ufo/waves/round-19/w1/WaveOutcomesTool.md:32-35`). Causes may be a flat map, `{"wave": ..., "causes": {...}}`, or `{"wave": ..., "seats": [...]}`; entries resolve by registered seat name or `agentId`, and blank cause text is not a cause (`.ufo/waves/round-19/w1/WaveOutcomesTool.md:36-50`; tool implementation `.ufo/waves/round-19/tools/wave-outcomes.py:232-289`). Use object entries with both `cause` and `source` so the generated `cause_sources` retains the pointer (`.ufo/waves/round-19/tools/wave-outcomes.py:328-350`). The tool does not require or validate that a source points to the actual terminal line; #22 still requires that evidence review.
- [O] The generated record has per-seat `name`, `role`, `report_present`, and `cause`, hashes and counts; its schema has no cutoff or terminal-state field (`.ufo/waves/round-19/tools/wave-outcomes.py:312-353`). Its documented deterministic output carries no timestamp (`.ufo/waves/round-19/w1/WaveOutcomesTool.md:51-53`). Therefore the generator result alone cannot establish the cutoff or separate terminal failures from not-yet-returned seats; retain a companion terminal snapshot.
- [O] The R19 pattern does this in `evidence/wave-outcomes/w1-terminal.json` and `w2-terminal.json`: top-level `cutoff`, then per-seat report presence, stop reason, cause, timestamp and source pointer. W1 says “2026-10-20 round-19 resumed L1, after all W1 seats terminated” and its first row retains an aborted cause and transcript line (`.ufo/waves/round-19/evidence/wave-outcomes/w1-terminal.json:1-13`); W2 says “all 72 wave-two reports present, pre-final-verification” (`.ufo/waves/round-19/evidence/wave-outcomes/w2-terminal.json:1-13`). W1's causes input separately records per-seat terminal text and source pointers (`.ufo/waves/round-19/evidence/wave-outcomes/w1-causes.json:1-8`); W2's causes input is `{}` (`.ufo/waves/round-19/evidence/wave-outcomes/w2-causes.json:1`). The corresponding R19 W2 outcome record reports 72/72 reports, zero missing, and `wave: null` (`.ufo/waves/round-19/wave2-outcomes.json:1-24`), showing the cutoff and wave identity are not supplied by that output when absent from the causes wrapper.
- [O] R19 also retained a red/green test pair for R18 W2. With four missing reports and an empty causes map, the red run had four uncaused seats and exited 1 (`.ufo/waves/round-19/evidence/wave-outcomes/r18-w2-red.stdout:1-4`, `.ufo/waves/round-19/evidence/wave-outcomes/r18-w2-red.exit:1`). With four causes, the green run had zero uncaused seats and exited 0 (`.ufo/waves/round-19/evidence/wave-outcomes/r18-w2-green.stdout:1-4`, `.ufo/waves/round-19/evidence/wave-outcomes/r18-w2-green.exit:1`). These are checker outcomes, not evidence that the four cause texts were independently authenticated.
- [O] R20's shared contract explicitly requires D6e: a seat literally named `causes` must not collide with the wrapped-map key, with selftest case `seat_named_causes` (`.ufo/waves/round-20/contract.md:68-69`). The current R19 parser checks for top-level `"causes"` before flat-map keys (`.ufo/waves/round-19/tools/wave-outcomes.py:237-243`), so a flat map containing that literal seat is ambiguous today. Until the D6e fix and selftest are verified, encode such an entry in the accepted `{"seats":[...]}` list form; do not rely on the wrapped-map interpretation.

## R20 recording recommendation [INFERENCE]

1. Bind W1 to `--registration .ufo/waves/round-20/wave1-registration.json`, `--report-dir .ufo/waves/round-20/w1`, `--causes .ufo/waves/round-20/evidence/wave-outcomes/w1-causes.json`, and `--out .ufo/waves/round-20/wave1-outcomes.json`. The registration and report directory are observed at `.ufo/waves/round-20/wave1-registration.json:2-8`; the causes/output filenames are recommendations. For W2, use the corresponding `wave2-registration.json`, `w2/`, `evidence/wave-outcomes/w2-causes.json`, and `wave2-outcomes.json` once its registration and reports exist. Retain separate per-wave outputs. Keep input path spelling stable across reruns because the tool records argv paths verbatim as well as content hashes (`.ufo/waves/round-19/w1/WaveOutcomesTool.md:51-53`). Include the wave identifier in the causes wrapper if using the wrapped form; otherwise the outcome's `wave` remains null.
2. Beside each generated output, retain an immutable per-seat terminal snapshot with an explicit `cutoff` containing the actual UTC observation instant and phase (for example, integration or pre-final-verification), plus the per-seat returned/report status and terminal state. Use distinct cutoff-specific filenames or append a new snapshot for each later reclassification; do not overwrite or fold a later result into the earlier count. The R19 cutoff strings are useful phase labels, but W20 should make the instant unambiguous as well. The shared contract says evidence timestamps must be taken from the clock at write time (`.ufo/waves/round-20/contract.md:33-34`).
3. Populate one cause entry for every reportless seat. Preserve the exact terminal error text and a transcript/result path plus line/locator in `source`; if no cause can be recovered, write `cause unknown` and record the concrete retrieval attempts and their sources. Keep reportless-but-still-pending seats separate from terminal failures at that cutoff. A non-empty placeholder such as `unknown` only clears the generator's cause check; it does not satisfy QUALITY #22 by itself.
4. Capture stdout and exit code beside each run. Exit 0 means no reportless seat is uncaused; exit 1 means at least one is; exit 2 means unusable input/refusal (`.ufo/waves/round-19/w1/WaveOutcomesTool.md:38-40`). Preserve a red/green test only as a checker test, not as a substitute for the live per-seat cause record.
