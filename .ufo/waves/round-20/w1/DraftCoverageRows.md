## Findings (calibration and gaps for the L1)

1. Subject-sha256 clause cannot be met literally for `list-objdump-architectures`. Claims require "each counted target verb's entry carries an ev_ id and subject sha256" (`.ufo/waves/round-20/claims.json`, C2 `before_after`), but the CLI passes no path, so Evidence subject is `undefined` (`dist/cli-runtime/cli.js:38010,38238`). The draft names the provider binary sha256 as identity and labels it as such. L1 decision: accept that wording or drop the verb from the counted set. [INFERENCE: the counter reads only `ev_` and the path; it does not parse the subject — C2 `verb-coverage.py` is not on disk at this check.]
2. Name-token gap. `verb-coverage.py` matches names by token (hyphen or underscore). Existing `inspect_with_objdump` entries (`corpus/README.md:67-68,152-153`; `corpus/knowledge/2026-10-16-l8-01-6p4-symmetry-battery.md:12`) do not count for `list-objdump-architectures`, though the CLI maps that name to the same MCP tool (`dist/cliCommandNames.js:175`). The new entry must spell `list-objdump-architectures` literally (the draft does).
3. Rizin is unrestricted, not a sandbox. The tool description says commands can "execute foreign code, mutate files, access the network, and read files outside the selected artifact" (`dist/mcp/toolContracts-BW05wpcr.js:11645`). `PROVINCE.md:103-105` puts non-REA dynamic analysis outside the lane. The draft therefore restricts the probe to static commands and asks for a pre/post sha256 equality check (`dist/cli-runtime/cli.js:38235-38241`). Any mutation or network probe must stay out of the corpus. [INFERENCE: `-N -q` does not block writes; the write-test is a proposal, not run.]
4. Rule conflict risk. `corpus/README.md:9` forbids writing a row before its file exists, and coverage-map integrity (command A) must stay 100% (claims `falsified_if`). Coverage rows that name entries not yet written would break it. Land Section A only in the same integration as Section B's files.
5. CLI/MCP parity. The CLI `inspect-wasm-artifact` has no `detail` option (`--schema` output; `dist/cli/wasmCommands.js:33-42`), while the MCP contract offers `detail: "summary"` (`dist/contracts/wasm/wasmToolContracts.js:8-9`). The Knowledge row must not claim summary-mode coverage from a CLI run.
6. Harmony needs a two-step chain. The projection rejects raw paths (`dist/domain/artifactInventoryEvidence.js:23`), so the run is `inspect-artifact` then projection on that Evidence; the projection's own Evidence carries the inspect Evidence id(s) in `parameters.inventory_evidence_ids` (`dist/application/InventoryProjectionEvidence.js:24-27`) and its subject is the root (`:15-19`). No HarmonyOS carrier exists on this host (not searched); a synthetic HAP/HSP/App Pack root with a `module.json` or `config.json` path is [INFERENCE] until built and inspected (`dist/domain/harmony/harmonyApplication.js:104-108,63`).
7. Compare requires `scope` (no default; `dist/contracts/wasm/wasmComparisonContracts.js:10-11`) and both sides must share the subject identity check (`WasmInterfaceComparisonService.js:18-21`). Recipes must retain both inspection Evidence files as JSON inputs; the lane's `evidence/c2/` path must exist at REV for the counter to count it.
8. Env wiring. `REA_WABT_BIN_DIRECTORY` and `REA_RIZIN_COMMAND`/`REA_OBJDUMP_COMMAND` are absent from `~/.bashrc` (O7). Each run must export them explicitly, and the Evidence should record the exported value (`dist/cli-runtime/cli.js:2654-2655`).
9. Timestamps. `verified-at` cells must come from `date -I` at write time (C2 timestamp rule; `.ufo/waves/round-20/contract.md:33-34`). The placeholders above are not dates.
