The CLI registers nonempty `path` and `command` strings and forwards them to `service.executeRizinCommand` with cancellation/cleanup (`dist/cli/reverseEngineeringCommands.js:114-125`). The service applies the stricter `rizinInputSchema`: nonempty path and command, no CR, LF or NUL, no extra object keys; schema failure returns `AnalysisInputError` (`dist/domain/reverseEngineering.js:22-31`; `dist/application/reverse/ReverseEngineeringService.js:105-111`).
- Provider/argv: `createReverseEngineeringCommandPort` selects `environment.REA_RIZIN_COMMAND ?? The command builder returns `[-N, -q, -c, input.command, resolve(input.path)]` (`dist/rizin/RizinCommand.js:7-14`). The environment is copied into a service snapshot (`dist/composition/reverseEngineering.js:22-28`). On POSIX the owner spawns the executable and argv array with `shell: false` (`dist/process/ProviderProcess.js:52-60`).
- Timeout/output: fixed timeout is **120,000 ms** and combined stdout+stderr capture budget is **16 MiB** (`dist/application/reverse/ReverseEngineeringService.js:12-15,185-195,524-528`). The process supervisor retains the earliest bytes up to the shared limit and marks truncation once bytes exceed the remaining combined budget (`dist/process/ProviderProcess.js:341-363`); the owned-command loop treats budget exhaustion as `output-limit` (`dist/process/OwnedCommand.js:79-100`). It captures bytes, decodes with UTF-8 replacement behavior, and separately flags invalid UTF-8 (`dist/process/ProviderProcess.js:378-407`). Timeout, output exhaustion, signal, and capture errors can leave partial output/completion unknown (`dist/application/reverse/ReverseEngineeringService.js:255-277,315-328,371-379`).
- Raw result: the service constructs a result object containing `stdout`, `stderr`, `exit_code`, `signal`, truncation/completion status, and before/after artifact digest fields (`dist/application/reverse/ReverseEngineeringService.js:371-379`), then passes that same object as both `rawResult` and `result` (`:447-461`). Evidence normalization stores `rawResult` as `raw_result` and `result` as `normalized_result` (`dist/domain/evidence.js:279-285`). Thus `raw_result` is the complete decoded observation object containing stdout—not bare stdout or original byte buffers.
- Refusal/effects: there is no command-text allow/deny-list on the traced CLI → schema → service → builder path. Validation refuses empty/multiline/NUL commands; launch/access/timeout/output-limit/cancellation failures can also fail the operation. Nonzero process status is deliberately preserved as an observation, not treated as a forbidden command (`dist/application/reverse/ReverseEngineeringService.js:389,470-472,513-560`; `dist/process/OwnedCommand.js:101-110`). The tool contract warns that commands and retained plugins may execute foreign code, mutate files, access network and read outside the artifact; external inputs are not evidence-bound (`dist/contracts/reverseEngineeringToolContracts.js:39-50`). Effects metadata marks the operation non-idempotent and able to mutate target/session, write files, access network, launch processes, discard data and execute foreign code (`dist/contracts/toolEffects.js:85-94`).

## Divergence, confidence, limits

- **Observed divergence:** CLI-level command schema checks only nonempty string (`dist/cli/reverseEngineeringCommands.js:116-122`), while service schema additionally rejects CR/LF/NUL and extra keys (`dist/domain/reverseEngineering.js:23-31`). Consequently a command string admitted by the CLI argument schema can still be rejected when the service validates it.
- **In-package invariant:** admitted input is passed as one `-c` value plus the resolved artifact path; output and nonzero exit status are preserved in Evidence. No historical prior version was compared, so this is not a claim about an earlier last-known-good revision. Rizin command semantics themselves are delegated to Rizin/plugins.
