## Reconstructed contract

- **Observation — input:** `harmonyApplicationProjectionInputSchema` is exactly `{ inventory_evidence: Evidence[] }`, array min 1 and strict top-level shape (`dist/domain/mobileApplicationGraphProjection.js:13-15`; alias `dist/domain/harmony/harmonyApplication.js:11-12`). Each element must authenticate as Evidence; accepted operations are `inventory_artifact`, or `inspect_artifact` whose `normalized_result.substeps[0].evidence` is used (`dist/domain/artifactInventoryEvidence.js:13-27`; Evidence ID recomputed/checked by `dist/domain/evidence.js:133-140,181-190`). Inventory subject must be non-null and match manifest root SHA-256 and format (`dist/domain/artifactInventoryEvidence.js:41-47`). Root format must be exactly `hap`, `hsp`, or `app-pack`; other formats throw (`dist/domain/harmony/harmonyApplication.js:104-108`). Multiple pages are merged only when manifest, coverage declaration, and integrity contradictions agree; complete graphs also undergo graph-identity validation (`dist/domain/artifactInventoryEvidence.js:56-94,181-226`).
- **Observation — result:** the projection outputs root hash/format and source Evidence IDs, `packaging_model`, six component buckets, unavailable components, App Pack child paths, runtime-family hints, bridge hypotheses, coverage, and limitations (`dist/domain/harmony/harmonyApplication.js:14-42,80-102`). The service wraps it as inferred, analyst-inference Evidence linked to its inventory source (`dist/application/InventoryProjectionEvidence.js:6-41`). This is explicitly execution-free and reports paths/hashes, not Harmony manifest semantics (`dist/domain/harmony/harmonyApplication.js:43-46,62-66`).
- **Observation — packaging heuristic:** any inventoried manifest path matching `(?:^|/)module\.json` case-insensitively makes the model `stage`; only if none exists does a matching `config.json` yield `fa`; neither yields `unknown`. If both exist, Stage wins (`dist/domain/harmony/harmonyApplication.js:110-117`). `pack.info` is classified as a manifest but does not affect this model. The code does not inspect file contents.
- **Observation — component kinds:** entries become components only for non-root occurrences with authenticated artifact nodes (`dist/domain/mobileApplicationGraphProjection.js:46-61`); each component is `{path, artifact_id, sha256, format}` (`:16-22`). Buckets are path/format filters (`dist/domain/harmony/harmonyApplication.js:119-126`): manifests = basename `module.json|config.json|pack.info`; bytecode = `.abc|.pa`; resources = basename `resources.index`, `resources/...`, or `assets/<one segment>/resources/...`; native libraries = format `elf` or `.../libs/<segment>/<filename>.so`; JavaScript = format `javascript-bundle` or `.js|.mjs|.cjs`; signing = root `META-INF/<one filename>.(p7b|sig|cer|crt|pem|provision)`. Unauthenticated-content occurrences are instead retained with null artifact/hash in `unavailable_components` (`dist/domain/mobileApplicationGraphProjection.js:23-31,63-72`).
- **Observation — related hints:** `.abc|.pa` implies `ark`, format `elf` implies `native`, `.js|.mjs|.cjs` implies `javascript`; exact library/framework path segments may add React Native/Flutter/Unity (`dist/domain/harmony/harmonyApplication.js:128-142`; `dist/domain/nativeConvention.js:1-29`). For App Pack only, any inventoried `.hap|.hsp` suffix becomes an `app_pack_children` path; contents are not recursively inventoried (`dist/domain/harmony/harmonyApplication.js:67-72,89-91`). `coverage.status` is complete only with complete `container-entries` coverage and complete projection budget/no unavailable components; `inventory_complete` separately reflects graph member counts (`dist/domain/mobileApplicationGraphProjection.js:38-45`; `dist/domain/artifactInventoryEvidence.js:112-115`).
