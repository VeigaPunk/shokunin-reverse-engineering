## Observations

- The named target `dist/domain/wasm/wasmArtifact.js` is the strict input/output contract, not the subprocess implementation. Input requires an explicitly selected absolute local `path`; optional `glue_paths` and `candidate_paths` default to empty and each allow at most 16 (`REA/dist/domain/wasm/wasmArtifact.js:11-16`; `REA/dist/application/wasm/WasmArtifactService.js:27-47`). Successful output carries artifact `{path, sha256, bytes}`, `validation: "valid"`, sections, WAT, imports/exports, tool profile, candidates/glue, and literal `not-performed` execution/fetch markers (`wasmArtifact.js:5-10,17-75`).
- **Gate and executable set:** caller supplies an absolute `REA_WABT_BIN_DIRECTORY`; the provider resolves, checks executable access, and hashes exactly `wasm-validate`, `wasm-objdump`, and `wasm2wat` (Windows adds `.exe`) in that order (`REA/dist/wasm/WabtArtifactProvider.js:71-88`). Each runs first with `--version`; admission requires stdout trimmed exactly to `1.0.42` and empty stderr (`:110-142`). The admitted upstream release/source commit is `1.0.42` / `ff0ef7e0009402740c805a9744c09b05be063e48`; profile records resolved paths, SHA-256, banners, argv, timeout and output budget (`REA/dist/wasm/WabtRelease.js:1-12`; `REA/dist/domain/wasm/wasmArtifact.js:39-54`). The package states this banner gate does not authenticate publisher provenance; WABT is BYO, with no implicit install, and `wat2wasm` is fixture-only (not a runtime prerequisite) (`REA/third_party/wabt/README.md:1-18`).
- **Actual argv and order:** `wasm-validate --enable-all module.wasm`; then, only on exit 0, `wasm-objdump -h -x module.wasm`; then `wasm2wat --enable-all module.wasm`. The same argv is schema-enforced in that order (`WabtArtifactProvider.js:84-87,181-245`; `wasmArtifact.js:93-105`). Before these runs, the selected bytes are copied as read-only-mode `module.wasm` into a private runtime root; the snapshot digest and each tool's digest are rechecked around execution (`WabtArtifactProvider.js:89-108,110-134,174-179`). Nonzero validation returns an input error with partial observed Evidence/diagnostics and stops before later tools (`:186-222`).
- **Sections vs imports/exports:** sections come from `wasm-objdump` stdout, parsed as WABT section rows (`kind`, hex `start/end/size`, description); parser checks row arithmetic, 2–6 byte section headers after the 8-byte preamble, end within selected file size, custom-name inventory agreement, and final coverage through file end. It retains header/detail text (`REA/dist/wasm/WabtOutput.js:4-60`). This is parsing the admitted WABT text, not an independent raw-binary section decoder. Imports/exports instead come from `wasm2wat`: `parseWabtWat` scans balanced WAT strings/comments and collects exact top-level `(import ...)` / `(export ...)` forms; it does not split names on punctuation. It also passes top-level type/rec/import/export/func/table/memory/global/tag forms to typed decoding (`REA/dist/wasm/WabtWat.js:37-146`; schema comment `REA/dist/domain/wasm/wasmArtifact.js:17`).
- **Typed interface:** entries preserve direction, decoded import module/name (export module is null), kind, nullable index/signature, exact `wat_form`, and per-entry issue. Kinds: func/table/memory/global/tag/unknown; function/tag params/results use admitted scalar/vector/reference types; table/memory include limits and memory page size; globals include value type/mutability (`REA/dist/wasm/WabtInterface.js:112-211,213-294`; `REA/dist/domain/wasm/wasmInterface.js:2-74`). Unsupported signature/index semantics remain an entry with null signature and an issue; inventory remains complete. Only representation-capacity exhaustion changes interface state to partial and records the issue (`WabtInterface.js:292-307`).
- **Evidence subject:** provider binds the selected artifact's exact path, `format: "file"`, and selected-byte SHA-256 as the execution subject (`REA/dist/wasm/WabtArtifactProvider.js:281-289`). The service emits `inspect_wasm_artifact` Evidence with that subject/provider, full report, `confidence: "observed"`, artifact-path location and limitations; it rejects subject path/hash/format mismatch (`REA/dist/application/wasm/WasmArtifactService.js:53-75`; `REA/dist/domain/wasm/wasmArtifact.js:116-119`). Provider identity is `wabt-artifact`, `REA WABT artifact adapter`, `wabt@1.0.42` (`REA/dist/wasm/WabtRelease.js:2-6`).
- **Limits:** each selected artifact, candidate and glue file is read under the 8 MiB `inputBytes` cap; each WABT executable is bounded at 64 MiB; each subprocess has a 30,000 ms timeout and 32 MiB combined output budget, with oversized output failing rather than succeeding truncated (`REA/dist/wasm/WabtRelease.js:7-12`; provider reads at `WabtArtifactProvider.js:78,96,144,154,163`, limitations at `:246-252`). Thus up to 16 explicit candidate paths plus the selected artifact are considered (deduplicated), and up to 16 glue files. Typed-interface representation has a separate 32 MiB conservative charge, based on strings and signature expansion, not a WAT-byte cap (`REA/dist/domain/wasm/wasmInterface.js:75-88`; `REA/dist/wasm/WasmInterfaceBudget.js:3-11`).
- Glue matching is AST-observed static `.wasm` string literals or expression-free template literals. Exact local path matches are preferred, otherwise basename candidates are retained; unresolved/ambiguous references are not resolved into runtime loading/data-flow claims (`REA/dist/wasm/WasmGlueAdapter.js:5-52`; provider limitations `WabtArtifactProvider.js:246-252`). Tool contract permits `detail: "summary"` for smaller delivery while retaining the complete original Evidence; detail selection does not alter analysis/identity (`REA/dist/contracts/wasm/wasmToolContracts.js:6-17`).
