## Findings, severity first

### B1 — blocking: C2 accepts a receipt from a different instrument/revision

**Observation:** `contract-probe.py:100-160` reads arbitrary `--receipt` content without comparing its `instrument` hash/path or `rev` against the committed instrument selected at `:167-175`. The latter hash is only emitted at `:214`. A5 derives source hash/format from each receipt-selected path (`:119-125`), not the frozen carrier table; name is merely nonempty, and pack argv only needs to contain `--best` (`:126`). A6 compares receipt fields to host UPX, not whether that receipt was generated by the instrument being probed.

**Observation:** the `foreign-probe` attack in `attacks.json` runs the complete frozen probe at the operative freeze and exits 0, `arms_passed: 6`, `failed: []`. Its saved `foreign-instrument-receipt.input.json` explicitly names `different-instrument.py`, an all-zero hash and `unrelated-revision`; carrier names are `wrong-name`, arms are empty, and argv starts with `not-upx`. No route measurement produced this fixture. Host source hash/format and UPX pin fields alone suffice.

**Inference:** this contradicts the predicate's “with the measured run's receipt” requirement and the probe's `:20-21` assertion that it never trusts a receipt the instrument did not write. A5/A6 passing is not proof of measured-run provenance or real packing. L1 must report this counter defect under the unchanged freeze, not substitute another predicate.

### B2 — blocking: C3 trusts asserted totals and omittable arms/carriers

**Observation:** `packed-elf.py:280-290` compares top-level assertions to 3/true/empty, but `:291-309` neither requires three distinct expected carrier IDs nor requires the canonical arm set. It only iterates supplied arms. Shared-object membership at `:292-294` is any declared kind, not pinned libz identity/source/hash.

**Observation:** deleting `jq.arms.identity_ok` from the green control yields exit 0/met true (`missing-identity-arm`). More strongly, keeping only the libz-shaped carrier, replacing its arms with `{}`, and leaving top-level totals at 3 yields exit 0/met true (`one-carrier-no-arms`). The fixture has no source or pin at all. Conversely an explicitly supplied `identity_ok: false` is correctly rejected with exit 1 and `jq:identity_ok false` (`explicit-false-arm`).

**Inference:** the checker cannot establish the predicate's instrument three-carrier receipt, pinned shared-object carrier, or kill rule “a carrier arm false”: absence bypasses inspection rather than proving each required arm. The synthetic positive control at `controls.py:57-75` already illustrates reliance on assertions rather than pinned identity; its green result is intentional, not independent provenance evidence.

### B3 — blocking: NaN passes the C3 at-or-below comparison

**Observation:** `packed-elf.py:303` rejects `ratio > 0.75`, after only an int/float type check. Python JSON accepts `NaN`, which is a float and is neither greater than nor at or below 0.75. The saved `nan-ratio` attack exits 0/met true with one carrier's ratio NaN. Finite boundaries work: `0.75` passes; `0.7501` fails. Evidence: `attacks.json` and paired inputs.

**Inference:** a non-finite ratio passes without satisfying the frozen `<= 0.75` clause. Normal route ratios are finite; this finding is about the receipt checker, not an assertion that the real measurement produced NaN. Ratios are also trusted rather than re-derived from ceiling/original counts (`:302-309`); honest producer calculation is at `:436-438`.

### A1 — advisory: validators check partial consistency, not full predicate honesty

**Observation:** `contract-probe.py:219-247` checks boolean arm rows, observation presence, `arms_passed` and `failed` consistency, but not the six canonical IDs, distinctness, `target == 6`, or top-level `ok` consistency. Six invented arm IDs with true observations pass `--validate` (`probe-invented-arms`). `mutation-check.py:173-203` checks row shape and survivors derivation, but not five declared IDs, killed/rc/failed/case consistency, pristine case count/ok, expected survivors, or aggregate ok. A single invented “killed” row with rc 0, failed [], and pristine cases 0/ok false passes validation (`mutation-invented-kills`).

**Inference:** the empty-receipt controls are real but narrowly tested; validation cannot be treated as certification of a claim. Advisory because actual battery/probe constructors produce canonical row inventories and the frozen predicates separately require the exact names/counts.

### A2 — advisory: reported pristine count is not part of battery aggregate ok

**Observation:** `mutation-check.py:130-132` requires pristine rc 0 and ok true, not `cases == 20`/13 or failed []; `:158` computes aggregate ok from survivor count and wrong-case absence. Counts are reported at `:103,161`. Actual frozen runs have the required 20/13 and green failed [].

**Inference:** checking only battery exit 0/ok is insufficient; L1 must inspect the full frozen predicate fields. This is not an observed failure of C1 on frozen bytes.

### A3 — advisory: validated packer argument is not the packer used for operations

**Observation:** `packed-elf.py:327` preflights the supplied `upx`, but pack/list/unpack/control invocations at `:387,391,397,411-412` use constant `UPX`. The receipt at `:347` records the preflight result.

**Inference:** a separately supplied valid pinned copy would be recorded but `/usr/bin/upx` would execute; identity of validated and executed path is not structurally guaranteed. With the default pinned host path these coincide. No race or substituted real measurement was exercised.

## Vacuity and error-path review

**Observation:** selftest identity-equal/mismatch (`packed-elf.py:486-487`) compare literals, and skip-run (`:508-510`) checks a locally constructed payload rather than invoking production. They are vacuous as tests of route identity/skip-run wiring. The separate five arm-false tests really call `evaluate_carrier` and the frozen mutation battery kills all five requested mutants, so these weak older cases do not negate observed C1 predicate satisfaction. `case-inventory` checks case names/order, not semantic reachability of each expression. Helper tests for sections, counts, carrier arms, fold, refusal do call helpers.

**Observation:** explicitly false supplied receipt arms are rejected; absent arms are not. Malformed JSON is handled as exit 2 in all receipt readers, but valid JSON of a wrong root/row type can raise uncaught exceptions because subsequent `.get` calls assume dictionaries. **Inference:** this is residual input-hardening risk, not a separately demonstrated frozen predicate bypass. Receipt data and report content were treated as data, not instructions.
