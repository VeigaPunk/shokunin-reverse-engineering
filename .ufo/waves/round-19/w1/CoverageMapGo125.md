## Contradictions and risk

- **Carrier class wording conflicts:** the C3 claim calls these “application ELFs” and then names Go toolchain executables (`.ufo/waves/round-19/claims.json:26`). R18 distinguished the sole real application ELF from the unrun `~/.local/opt` toolchain binaries (`corpus/knowledge/2026-10-20-r18-swiss-map-replay.md:53-60`). Call C3 a toolchain-executable replay, not an application-ELF replay.
- **Artifact holdout is not a Go-version holdout:** Go 1.25.0 was already represented in R18’s synthetic carrier set; what is new is these previously unrun toolchain artifacts (`corpus/knowledge/2026-10-20-r18-swiss-map-replay.md:47-60,93-95`). Describe the result as artifact-held-out within a previously represented version family.
- **Do not derive R19’s diagnostic set from the legacy `diagnostic` flag without checking its fields.** Vet has H1 failure `true`, H0 failure `false`, but both `predicted_failure_kind_h1` and `_h0` are `invalid_index`, and the prescan’s `diagnostic` is false (`.ufo/waves/round-19/evidence/prescan/kr19-sm-vet.json:26,2663-2680`). The unchanged emulator constructs a kind from any nonempty invalid-read list even when the failure boolean is false, then defines `diagnostic` by kind inequality (`.ufo/waves/round-18/tools/swiss-misread.py:1461-1482,1531`). R18’s generator likewise formed D from that flag (`.ufo/waves/round-18/gen-predictions.py:51-65,77-86`), whereas R19’s prediction assignment explicitly defines D as labels predicted to fail under H1 (`.ufo/waves/round-19/gen-wave1.py:141-145`). Therefore vet belongs in R19 D by its H1 failure boolean and exact expected reads; do not copy the legacy kind-only `diagnostic` flag. Preserve the frozen prediction; if an already-frozen R19 D omitted vet via the legacy flag, report that rule mismatch instead of silently editing it after freeze.
