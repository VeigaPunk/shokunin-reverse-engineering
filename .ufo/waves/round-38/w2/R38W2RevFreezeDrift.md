### Defects
- **HIGH — trust contract**: `git log` returncode is never checked. With an unreadable tree object (direct git: rc=128, "fatal: loose object … Permission denied"), the tool printed `"verdict": "clean"` and exited 0 (fx-p5.json vs p5git.err in artifacts). Any unevaluable git-level failure — corrupt/missing objects, a git too old for `:(glob)` pathspec magic, unsupported pathspec syntax — is reported as the gate's *strongest* signal. For a gate whose zero-commits output licenses scoring, silent-clean on failure is the worst mode. Fix: check `log.returncode` → `verdict: unevaluable`, exit 2, include stderr in `reason`.
- **LOW — silent literalization of user pathspec magic**: the unconditional `:(glob)` prefix corrupts user-supplied magic paths: `:(glob):(icase)PLANS/CLAIMS.md` returns rc=0 with no match and no error (P4; the `:(icase)` text becomes part of the literal pattern). Combined with T5 (nonexistent path → clean exit 0), any unmatchable user path yields `clean` with no signal. The JSON echoes the user argument, not the effective prefixed pathspec (fx-t4.json `paths` shows `:(icase)plans/claims.md`), so the receipt does not reveal the substitution.
- **LOW — `--json-out` into a missing directory**: FileNotFoundError traceback, exit **1** (P3) — collides with the drift exit code instead of the unevaluable code 2. A consumer scripting on exit codes would misread it as drift.
- **INFO**: the unevaluable JSON omits the `drift` key (unguarded consumers KeyError); a non-UTF-8 commit subject would crash with UnicodeDecodeError (exit 1 traceback) [INFERENCE — code path read, not exercised]; argparse errors exit 2 with usage text, not JSON.
