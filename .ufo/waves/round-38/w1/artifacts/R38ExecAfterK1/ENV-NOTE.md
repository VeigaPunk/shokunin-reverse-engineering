The earlier "no external extractor dependency" premise was wrong: unblob
26.6.4's `SquashFSExtractor` requires `sasquatch-v4be` on PATH for BE v4;
the dependency-gap before-arm reproduces when the home ~/.local/bin is absent
from PATH. The L1's earlier probes did not actually strip ~/.local/bin
(grep -v on PATH components matches directory names, and the binaries live
inside a directory whose name does not contain "sasquatch").

Correct claim shape: before receipts = REA runs with `sasquatch-v4be`
unavailable (expect missing-extractor-dependency [sasquatch-v4be], 0
published); after receipts = REA runs with `sasquatch-v4be` available
(expect full oracle publication, 0 gaps). Receipts below are regenerated by
the L1 at integration with explicit env control.
