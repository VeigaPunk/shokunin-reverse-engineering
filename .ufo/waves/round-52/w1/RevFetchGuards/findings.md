## Complete network and URL surface inventory

- **Spec origin:** `load_spec` (`round-50 :88–96`) reads local JSON or `git show`; no download subprocess. `external.url` passes unchanged from spec through `materialise :201` to `fetch`; no shell interpolation or script-side URL joining. `run :267–270` enumerates external carriers. CLI `main :439` is the production caller; selftest supplies a fake fetcher (`:326–353`), which explains the original coverage hole.
- **Initial URL:** `urlsplit` then exact scheme/hostname predicate (`:110–113`) precedes cache access and network. Reject file://, data:, ftp:, HTTP and scheme-relative URLs, including `file://download.avm.de/path` which isolates scheme despite matching hostname. Add userinfo host confusion (`https://download.avm.de@evil.example/`), subdomain suffix, malformed port/authority and CR/LF cases. No custom request headers exist in this script; header-injection safety must not be claimed merely from the two-component predicate.
- **Transport:** one global `urllib.request.build_opener(_AvmOnlyRedirect)` (`:107`) and one `.open(url, timeout=300)` (`:121`). Default opener includes ProxyHandler, HTTP(S), FTP, File and Data handlers (`/usr/lib/python3.14/urllib/request.py:537–565`). Scheme validation is what keeps alternate handlers unreachable. Default ProxyHandler reads environment proxy configuration (`:764–790`); the hostname guard pins URL hostname, not the actual socket peer or proxy. TLS/certificate behavior is inherited, not a custom guard tested here. HTTPS with `download.avm.de:8443` passes the current predicate: hostname pin is not strict origin/port pin. These are residual policy boundaries, not evidence of current frozen carrier failure (all frozen URLs use plain HTTPS authority).
- **Redirects:** `_AvmOnlyRedirect.redirect_request` (`round-50 :99–104`) rechecks scheme and host on every handled redirect. Stdlib resolves relative/scheme-relative Location using `urljoin` before invoking this hook (`request.py:660–697`), supports 301/302/303/307/308 (`:632`), and reopens the new request (`:718`). Test off-host and same-host HTTP downgrade independently, relative allowed redirects, protocol-relative foreign host, and a later bad hop. Merely calling the hook does not prove the opener installed it; an offline synthetic 302 through the opener is the stronger wiring witness.
- **Response and cache:** network read uses MAX_IMAGE+1 (`round-50 :123–125`), but image-cache read is unbounded (`:118`). Hash checks bind image, member and final carved carrier. Cache hits bypass networking only after URL validation and digest match. Tar and nested paths are in-memory lookups, not filesystem extraction or additional network sources.
