## Finding: semantic classes are substring heuristics, not complete exit semantics

`meaning_classes()` assigns each digit a class solely when a few regexes match. Its own supported language is narrow/inconsistent: success recognizes `met|clean|ok|green|pass|passed|verified|succeeded|wrote`; not-met recognizes `not met|violation|red|fail|failed|no verdict|refusal|refused|unresolved`; unevaluable recognizes `could-not-evaluate|unevaluable|could not evaluate|usage|error|absent|unreadable|refus`. This does not establish the exit's actual meaning for the row's tool. For example, source-backed registry row `tools/round-41/c1-run.sh` describes exit 0 as a probe successfully writing receipts (`ok`), which is not a success verdict about a target; exit 1 is an unguarded child status and not necessarily a not-met violation; exit 2 is usage/environment, but not necessarily an unevaluable tool verdict. Similarly `tools/round-46/gate.py` has no library entry point returning exit 1, so classifying a generic `1=not met` would assert a verdict that does not exist. These rows are presently outside the Round-48 census, but illustrate that a universal 0=success/1=not-met/2=unevaluable partition is not valid for every probe/library.

The new census does include diverse tools: `tools/round-48/census2.json` lists counters, probes, and `gate.py`; rows must distinguish probes that merely performed/wrote, tools with propagated child codes, and libraries with no standalone verdict. If the proposed cells merely use the regex vocabulary, they can pass without expressing the source-defined contract. In particular `SUCCESS` + absence of `NOTMET` accepts an exit-0 description that says “no control reached full score” or “no verdict” as success, while `NOTMET` can match incidental text anywhere in the cell. `UNEVAL` similarly matches generic `error` text without establishing that exit 2 actually means unevaluable.

## Third-state / partition issue

The three mandated classes presume all exit statuses have three distinct verdict meanings. Several census instruments are probes or libraries: a probe may return child status without interpreting it, and a library (`tools/round-46/gate.py`) has no standalone exit map. Such an instrument has no meaningful three-way verdict partition; labeling its exit 0 “success”, 1 “not met”, 2 “unevaluable” hides the real state (operation completion / propagated status / no verdict). The validator's three-class requirement should not be treated as evidence those meanings are true. The source semantics need row-specific accounting, and rows whose source has no three-way verdict must state that honestly rather than invent a verdict class.
