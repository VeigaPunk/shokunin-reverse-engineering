## Reconstructed C1 contract and implementation

### Intended meanings

- `R46-CL7` → `meaning`: each registry row's verdict map must actually describe the semantics of exits 0, 1, and 2 (success, not-met, unevaluable), in three distinct segments; merely putting digits before arbitrary text must not pass.
- `R47-CL10` → `floor`: the rule block must require a denominator/completeness floor rather than pass on a thin or tautological set; importantly the routed defect specifies the two block rows' arm assignment, so row identity must be paired with the expected arm, not just membership in the set of allowed arm names.

Observed implementation in `meanings.py`: `EXPECTED_ARM` encodes exactly that mapping (lines 45–47); hard scoring gathers routed IDs per row and checks one ID per row, exactly the two routed IDs once each, then checks `arm_by_id` against the mapping (351–370). Hard mode requires exact arm tokens from `meaning|floor` (376–382). Registry maps are parsed into 0/1/2 segments; class vocabulary checks exit 0 success, 1 not-met, 2 unevaluable, rejects placeholders, and demands distinct full segment texts (214–247). Registry path set/no duplicates and census re-derivation are checked (418–453). It pins mutation function source and interpreter bytes, citations and battery (384–417, 455–463). These source predicates appear directionally aligned with claims; this does not prove all adversarial inputs are rejected.

### Gaps / attack surface indicated by code inspection (not executed)

1. `table()` treats the first pipe row as header and skips separator-looking rows but does not enforce a separator, consistent row widths, or a unique parsed table. `score()` only sees all pipe-prefixed lines in the whole block (162–175, 327–345); an unrelated pipe table in prose can affect interpretation. It does enforce total parsed rows and width in hard mode, but table identity/placement remains permissive.
2. Routed ID extraction uses `ID.findall(r[0])` (352) and only checks each row contains exactly one recognized `R4[67]-CLn` match. It does not require trigger cell to contain *only* the exact routed identifier: surrounding/ambiguous prose, or an extra malformed ID outside the regex, can evade the intended “row names exactly one routed id” natural-language condition. Explicit `R46-CL7`/`R47-CL10` cardinality still closes the named permutation hole.
3. `arm_by_id` is a dict assignment (359–362); malformed duplicate row IDs overwrite, but the subsequent exact counts clause catches duplicates in hard mode. Thus no current demonstrated bypass, but evidence depends on the conjunction.
4. Registry parser binds rows to marker delimiters, but it does not check registry table header, semantic section title, or whether a different table is also present; only marker uniqueness and row shape/path set matter (182–197). Claims say marker-bound registry section and exact row set, so table-format tampering may remain accepted if extracted rows and class checks still line up.
5. `SEG` accepts digit markers anywhere and `_segments()` only requires marker order 0,1,2 (57, 214–224); arbitrary prefix text before first segment is ignored. Segment texts themselves are tested with permissive regexes, not full semantic grammar. Distinctness compares complete lowercased strings, so paraphrases sharing the right token pass; conversely proper prose containing conflicting class language may pass because the classifier only requires positive token presence. A2 correctly removed the over-strict negative-token guard for exit-0 false-red, but creates the general positive-substring classification boundary.
6. `SUCCESS` includes `wrote`; `NOTMET` and `UNEVAL` are substring/token heuristics. Their semantics are not a formal classifier. Distinctness of text does not establish mutually exclusive meanings.
7. `HARD_REF` permits line selectors, but cited references are counted as regex matches, so duplicate citation tokens can satisfy ≥5 references while only naming fewer than five distinct paths (255–274, 395–407). Claim text says ≥5 resolving path citations, plausibly allowing repeated references; quality is not measured beyond a minimum required lesson and knowledge path. The hard reference check exempts self path from resolving line bounds; separately the interpreter hash pins self bytes. Citation parser permits arbitrary suffix-like syntax limited by regex and does not validate evidence relevance.
8. `census_rederive()` executes frozen census tool source in-process with Python `exec` (290–299). If the claimed frozen source itself is adversarial, it can return an arbitrary `paths` list; comparison proves agreement with executable rule, not independent census correctness. This is an integrity limitation, not a claim of an observed exploit.
9. Battery uses mutations and scoring code both from current module, while `--rev` files are used as data. Mutation digest and interpreter pin are checked against current imported code's constants (`MUT_DIGEST`, `SELF`), not a separately loaded counter module from `--rev`. The caller invocation code is the current worktree; frozen-path integrity protects round-48 tree but not the counter implementation being executed if worktree differs. Claims explicitly pin interpreter bytes at `--rev`; this appears to be a serious current-code-vs-revision semantic question requiring executable differential test. `gate.freeze_state` does not itself establish what code Python invoked; inspect gate separately before deciding.
10. Battery is only run after the genuine artifact passes (`evaluate`, 541–548); a red genuine artifact skips the battery and reports skip, which is reasonable for target failure but means no mutation evidence from that invocation.

## Reconstructed C2 contract and implementation

### Intended meanings

- The round-47 atom oracle is the frozen semantic baseline, but must execute source bytes from requested revision, not mutable worktree. A consistent-but-empty pair of round sections is not complete evidence: each round needs seat atom or valid seats correction, path atom, revision atom, unique claim ID; Owned-axes requires at least two axis atoms.
- Corrections cannot be inert: all parsed corrections, including axes/quote, must truthfully re-derive. A quote number must match one of that section's cited receipts or be explicitly corrected to a receipt-backed value. The Owned-axes score number must agree with its displayed evidence fraction.

Observed implementation: `oracle()` reads the oracle path with `gate.show(root, rev, ORACLE)` and executes that committed body (62–73). It obtains last two sections via heading slicing (88–95), calls the oracle evaluator and rejects nonzero (180–205). Floor counts oracle `collect()` atoms, permits seats correction class, requires path/rev and one claim ID per section and uniqueness across those two (207–243). Corrections parse classes seats/window/path/rev/axes/quote (43–50, 98–111), invoke oracle `corrects()` for four old classes, own comparison for axes and quote, and reject absent/false corrections (245–270). Quote binding searches receipt paths inside section text, JSON-decodes them, compares typed integer/list-length values, and handles quote corrections (114–137, 159–177, 272–301). Axis score parser now takes first score-cell field and fraction in subsequent cells (140–156), then compares second score value to rounded 10*n/d (303–315), consistent with A1's disclosed fix.

### Gaps / attack surface indicated by code inspection (not executed)

1. Most concerning: `axis_scores(files)` ignores its `card` parameter and reads `files(CARD)` (140–144). For genuine evaluation the `files` closure points at `gate.show(root,rev,...)`, so this is same bytes; for mutation battery, `score(text, files, ...)` is passed the original `files` closure and mutated card text, so axes mutations can be measured against unmutated SCORECARD bytes. `axes-score-cell-off` modifies card text, but `axis_scores()` re-reads original card; this makes that mutation potentially invisible to the C1/C2 battery's score-cell test. This is a strong candidate falsification requiring exact command/receipt against an isolated fixture, not yet executed.
2. `_m_axes_cell_off()` finds first `AXIS_SCORE` in entire card, not necessarily Owned axes section (400–413). Battery may mutate an unrelated coverage/depth row or no-op, depending card structure. It only changes the second numeric match in score cell by -1.0; if formatting doesn't match, mutation no-ops and is counted as v2 green (457–460), masking weakness; battery's no-op is recorded but not failed explicitly beyond total and v2-green target.
3. `corrections_section()` returns `[]` if header absent and silently ignores nonmatching lines (98–111). C2 requires every line re-derives, but malformed correction-looking lines are invisible. Presence is implemented as `not corrs`, so one valid line can coexist with arbitrary malformed/forged correction lines undetected.
4. Corrections parser uses `.strip()` and regex matching; correction section existence is effectively proved only by at least one parsed correction, not by unique section header, and `card.split(CORR_HEAD,1)` accepts duplicate headings by selecting first. This differs from every-line/section uniqueness expectations.
5. `axes` correction check only searches first fraction in statement and compares to `axis_pairs`; it does not validate statement's prose, score-cell binding, or uniqueness. Duplicate valid corrections are accepted; extra junk after fraction is irrelevant. `quote` correction likewise searches first matching quote phrase, requires value absent from quoted list and some cited receipt backing it. A valid correction can bind a key even if it does not uniquely identify/repair a corresponding quote; quote fixes are dictionary overwritten by last valid correction.
6. Quoted numbers are recognized only by `QUOTE` words and decimals (46). Receipt extraction recognizes only exact `.ufo/waves/round-N/l1/scores/<name>.json` paths (47); malformed or alternative receipts/citation formats can be omitted. Receipt JSON that fails parsing is included as None; any single valid cited receipt can back a quote among multiple cited receipts, as contract says either a receipt that section cites. Booleans correctly excluded from integer values.
7. Quote correction can satisfy wrong quote if there is any receipt in section with correction value, and key is same; the criterion allows a correction by round/key, but it doesn't establish which quoted occurrence is corrected when multiple same-key numbers exist. All matching numbers are then considered corrected if they differ from correction value and receipt backs it (285–297); a single correction can excuse multiple unrelated wrong values.
8. Completeness floor uses claim regex and set uniqueness only across the last two sections. A claim ID can appear in prose; its substantive relation to that section is not validated. Regex recognizes `Rdd-Cd`, allowing arbitrary digits only one each. Floor says each section name a claim id; exact ID/routed claim-to-round relation is unspecified and unchecked.
9. `section_bodies()` accepts any `## Round N...` heading prefix and simply last two; does not verify consecutive rounds, unique headings, or distinct round numbers. Duplicate same-number sections could constitute two sections and the same string key in correction maps. Claims require last two sections; this is a possible ambiguity attack.
10. Oracle executes revision source via `exec`, appropriate for committed authority, but non-deterministic or malicious oracle source is not sandboxed. It also caches module by root+rev for process life. These are trust-boundary limitations, not proven outcomes.
11. The mutation battery checks totals but no-op mutations increment `forgeries_total` and `v2_green` by fiat; only v3 is not incremented, so a no-op can satisfy v3-green=0 and count as a forged success as long as v2 target remains. Battery receipt records mutation error but score doesn't fail on fixture-level no-op explicitly. This weakens mutation evidence if any mutation ceases changing artifact.
12. `score()` returns early on oracle exceptions/malformed structure, but `run_battery()` doesn't catch arbitrary exceptions around each mutation/score; `main_guard` behavior determines exit classification. Not a tested gap.
