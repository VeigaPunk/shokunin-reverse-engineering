# SentinelScope — round-74 instrument security review

Axes: path containment, environment confidentiality, executable provenance/process lifetime, scratch containment. Scope: the five `tools/round-74/*.py` instruments only; read-only source review, no remediation, no instrument execution, no offensive payloads. Findings below are source-established flows; exploit consequences are explicitly [INFERENCE], not live exploit receipts. No tools installed. This report does not certify other seats' filesystem activity or adjudicate the claims.

## 1. Path containment

**SS74-1 — MEDIUM, BLOCKING for a lane-containment claim: claim pin keys escape the worktree root.** `freeze-pins.py:39-44,52-56,75-82` joins untrusted claim keys to `root` and directly opens the result. Absolute keys override the root; `..` and symlinks can resolve outside it. The `--claims` container path itself has the same unchecked join. [INFERENCE] A supplied claims container can cause privileged checker reads of arbitrary readable files and publish their SHA-256/match result (not their raw bytes), including a known-value confirmation oracle. Smallest fix: reject absolute and traversal paths; resolve root and candidate and require candidate to remain inside root before every worktree open, including the container; use no-follow/open-relative handling if adversarial concurrent replacement is in scope. Fail unevaluable before reading any rejected path.

**SS74-2 — MEDIUM, BLOCKING for untrusted producer receipts: read-before-containment in A9.** `seam-probe.py:1058-1064` opens `child_env_observed.log` from a producer receipt before the containment predicate at `1071-1072`; that predicate is lexical (`104-108`) and does not resolve symlinks. [INFERENCE] A dishonest producer can direct a read outside the run/lane even when the final arm turns red; a false verdict does not undo the read. Fix: anchor the expected log to the instrument-created run directory, resolve/check before opening, and reject symlink escapes. Do not trust both `run_root` and `log` merely because their strings agree.

**No finding for record-audit path-token filesystem traversal:** `record-audit.py:64,83-88,140-141,344-346,460-468` passes capability tokens and claim pin keys as the path portion of one Git object expression, not to filesystem `open`; there is no shell. These paths select repository objects, not arbitrary host files. Receipt revisions at `156-159` still warrant canonical commit-ID validation and option termination as defensive input handling; no host-file exploit from those fields was executed or established here.

**No finding for receipt/claim-driven controls imports:** `controls.py:41,55-60,83-84` loads the two literal sibling names relative to `__file__`; rows do not supply a module path. These are trusted executable worktree files, not validated frozen bytes. Symlink replacement or editing those files remains a source-integrity trust boundary, not a demonstrated data-row import route.

Explicit caller paths are not sandboxed: all five accept arbitrary `--json-out` and open it directly (`seam-probe.py:1491-1493`, `probe-mutation.py:393-395`, `record-audit.py:605-607`, `freeze-pins.py:126-128`, `controls.py:155-157`). The three workload instruments also accept caller-selected existing `--work`. These are intentional CLI authority, not receipt-field injection, but a launcher must allowlist the lane receipt destination and the explicitly authorized scratch root; the tools themselves cannot certify lane-only writes.

## 2. Environment values

**SS74-3 — HIGH, BLOCKING against QUALITY row 128: A12 receipt still serializes complete shim environments.** New kernel samples are clean: `seam-probe.py:525-532` retains key names, canary presence and containment booleans, not environment values. However `_parse_shims` retains `"values": env` (`630-637`); genuine and forged subruns retain those dictionaries (`714-715,761-763`); `assemble_arm` and `kernel_witness_arm` carry them into the returned observation (`662-665,771-779`), which is attached to the probe arms (`1163-1166`) and finally JSON-serialized (`1490-1494`). [INFERENCE] A broken/hostile genuine checker that leaks a secret into its shim children makes the security probe publish that secret even if the arm fails. The lying forged shim also publishes HOME/PATH/TMPDIR values, though not the actual inherited dirty environment. Fix: after internal comparisons, return only key names, canary-presence and containment booleans from both shim branches; never return `values`. Raw `.environ` files are also deliberately written in scratch (`584-588`), so do not copy them into lane evidence and guarantee scratch cleanup.

**No direct environment-value dump in controls receipts:** `controls.py:95-98,113-117,122-126,138-148` records names, verdicts, counts and a stdout tail, not `os.environ`. Its child inherits the environment (`135`), so a modified/untrusted selftest can print secret values into `stdout_tail`; only execute trusted source and prefer parsed allowlisted output fields. Mutation's detector similarly inherits values (`probe-mutation.py:181-197`) and retains a stderr tail. This conditional source-trust risk is distinct from the unconditional A12 `values` serialization above. `record-audit.py` and `freeze-pins.py` do not enumerate or serialize environment values.

## 3. Subprocess construction, provenance and lifetime

**SS74-4 — HIGH, BLOCKING for hostile caller-made work paths: A11 Perl source interpolation.** `seam-probe.py:313,328-339` interpolates the scratch-derived record path directly into single-quoted Perl source, and also interpolates a host-tool path. [INFERENCE] A caller-controlled `--work` containing a quote can alter generated code when the checker launches the shim; no shell is needed. A12 already documents and uses the appropriate sidecar approach (`573-625`), but A11 does not. Smallest fix: reuse A12's fixed-source/sidecar shim writer for A11, keeping path text out of executable source. No quote-path payload was run.

**SS74-5 — HIGH when source is not already trusted: target pin checked only after execution.** `probe-mutation.py:239-247` loads the caller-selected revision's allowlisted tool and executes it and all copies through `score_text`/`run_detector` (`200-217,181-187`); only afterward are the expected and actual hashes compared (`255-258,270-271`). [INFERENCE] `--expect-target-sha256` cannot protect the caller's environment or filesystem from a substituted revision: the mismatch is reported after its Python already ran. Fix: compare a required supplied pin immediately after hashing and before `score_text`, and return exit 2 on mismatch without scratch writes or child execution. Fixed tool names (`236-238`) and list argv prevent path-name/shell injection, not execution of hostile blob contents.

Controls loads trusted sibling Python in-process (`55-60`) and executes a `record-audit.py` copy fetched from `--base-rev` with `sys.executable -I -B --selftest` (`129-135`), full caller environment plus TMPDIR; no source hash check precedes it. Treat that revision and the loaded siblings as executable authority; pin/check them before execution if callers may supply untrusted sources. Python `-I` isolates Python configuration, not OS permissions, environment access, or filesystem access.

Child inventory:
- `record-audit.py:75-88,157-159,452-454`: PATH-resolved `git`, inherited environment, captured output; no shell or explicit timeout.
- `freeze-pins.py:47-48,60-61`: the same Git boundary in revision mode; worktree mode uses direct reads.
- `probe-mutation.py:181-187,239-240,259-261`: inherited-env Git plus current-interpreter selftests; selftest environment adds TMPDIR and PYTHONDONTWRITEBYTECODE; 600-second detector timeout.
- `controls.py:63-65,89,109,129-135`: inherited-env Git, delegated mutation detector children, one current-interpreter audit selftest; the latter has no timeout.
- `seam-probe.py:130-146,279-295,668-715,737-760,1011-1051`: Git/blob imports and current-interpreter target/battery processes; general invocation passes PATH/LANG and optionally HOME/explicit extras, A9 uses PATH/LANG/HOME, A12 deliberately inherits caller values plus a canary. Generated Perl shims normally exec `/usr/bin/git` and `/usr/bin/readelf`, with PATH fallback only if absent (`612-615`); the dirty producer deliberately inherits its environment (`602-603`). Other Git lookups use PATH. Caller-selected `--tool`/`--battery` Git blobs reach import/exec (`809-831`), and a worktree `capsule_audit.py` sibling is copied without revision pinning (`139-146`). These are trusted-source interfaces, not a safe untrusted-code runner.

**SS74-6 — MEDIUM: child cleanup not exception-safe.** `seam-probe.py:698-713,742-760,1015-1051` starts Popen children/observer threads without a surrounding cleanup `finally`. [INFERENCE] A timeout or failure during startup/wait can leave children running and a witness alive until its own deadline; `wait` on piped forged children also does not drain their output. `controls.py:133-135` can wait indefinitely. Fix: bound waits; on any exit stop/join witnesses and terminate/kill/reap all owned processes (including descendants where needed), draining pipes with `communicate`. The mutation `subprocess.run` timeout handles its immediate child, not a general descendant tree. No hanging processes were spawned in this review.

## 4. Scratch discipline and literal /tmp grep

**No hardcoded `/tmp` allocation finding.** Exact literal `/tmp` search across all five files found only `seam-probe.py`: documentation (`29-30`), a forbidden-source-pattern string (`100`), a comment (`925`), a comparison (`931`), and synthetic `/r/tmp` / `/w/root/tmp` test data (`1269,1282`). The other four files have no `/tmp` match. None of these is a write destination.

`seam-probe.py:816,836,894,914,926,961,1011,1109` and A11/A12 (`313,729`) allocate under explicit `--work`; mutation uses `dir=work` (`203`); controls does too (`129,151`). The new seam selftest alone calls `mkdtemp` without `dir` (`1359`) and removes it in `finally` (`1441-1442`): it honors Python tempfile's TMPDIR selection, not `--work` (main returns to selftest before work validation at `1472-1473`). Mutation/controls explicitly set TMPDIR for detector/selftest copies (`probe-mutation.py:182-187`, `controls.py:133-135`).

**SS74-7 — LOW: scratch ownership is caller-cleaned except the selftest.** Workload `mkdtemp` trees are retained, and controls allocates an otherwise unused `ctl-` directory just to report its name (`150-152`). [INFERENCE] Interrupted or repeated callers can accumulate generated executable copies and raw environment logs. Smallest fix: remove the unused allocation and document/enforce one caller-owned parent cleaned in `finally`; preserve only sanitized receipts. A missing/invalid TMPDIR can make Python tempfile fall back to platform defaults for a directly invoked seam selftest; require a valid scratch root if fallback is forbidden.
