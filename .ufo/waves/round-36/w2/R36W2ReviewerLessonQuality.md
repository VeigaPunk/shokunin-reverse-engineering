## Findings (severity-ordered)

### F1 — QUALITY 78's provenance mechanism accepts the forgery it was written against (medium, calibration)

Row 78: "Provenance of a receipt that a claim rests on comes from an independent re-run by a non-author seat that compares the semantic payload **(here the published `(relative_path, sha256)` set and gap kinds)** …".

- The motivating attack, wave-1 `R36CriticC1Shortcut.md` F1, fabricates `after.json` with exactly one `{relative_path, sha256}` pair per **oracle** row and `extraction_gaps: []`. A genuine run publishes the same set (the oracle is the true content) with the same gap kinds. At the granularity 78 names, forgery ≡ genuine — the comparison cannot distinguish them, so a 78-conformant check **passes F1**. At that granularity the re-run adds nothing the counter doesn't already check (the counter itself compares the published set against the oracle).
- The actual wave-1 reproductions went far beyond the named minimum: `R36ExecReproK1.md` §7 compares the full normalized payload (258 leaf keys for `after`, 131 for `before`; only `evidence_id` differs after run-local substitution). That breadth catches F1's minimal forgery (it lacks `raw_result`, `chunks`, `coverage`, diagnostics) — but the criterion's letter does not require it.
- Even the broader practice cannot distinguish a determined forgery on these carriers: the cited critic's own §8 concedes "a determined fabricator can synthesize `raw_result` and `after-run.json` too, because they are the same kind of bytes", and §7 of the same report normalizes run-local fields before comparing. Row 78 drops that caveat and asserts provenance flatly.
- For the **real** receipts the reproductions do provide strong provenance (four independent non-author seats, positive verdicts: K1 "reproduces exactly", K2 "reproduces", K3/K4 "reproduces exactly"). The defect is in the criterion's guarantee for arbitrary receipts, not in this round's practice.
- Suggested repair (append a narrowing line, per the file's own convention): scope 78 to "the re-run attests the capability and payload reproducibility; the committed bytes' origin stays unauthenticated for oracle-derivable payloads; the comparison must cover fields a forgery cannot derive from the frozen oracle (e.g. `raw_result`, run records), and even then a determined fabricator remains outside its reach."
