## 4. Attacks / refutations attempted, with verdicts

- **A1 "no pip ⇒ venv infeasible" (the honest-stop hypothesis).** `python3 -m pip`
  fails, `which pip` fails — a shallow reading says the 3.14 venv cannot be seeded.
  **Verdict: refuted.** `ensurepip` ships a bundled pip 26.2.1 wheel and `venv`
  installs it automatically; demonstrated with a real scratch venv, pip version
  printed. The honest stop would have been premature.
- **A2 "requires_python is a formality — py3.14 will break at import/compile."**
  Metadata claiming `<4,>=3.10` does not prove the code runs on 3.14. **Verdict:
  refuted by execution** — a contract was compiled end-to-end in the EX-02 venv and
  selectors emitted (`Counter.vy` smoke above), plus EX-02's independent `Smoke.vy`
  compile. Not a metadata inference: an executed compile.
- **A3 "the one sdist dep will fail to build."** `immutables` 0.21 has no cp314
  wheel; many C extensions break on new interpreters. **Verdict: refuted by a
  bounded build-only probe** — builds cleanly on cp314 with the host toolchain.
  (Recorded as a real risk that was measured, not assumed away.)
- **A4 self-attack — "your census is a summary dressed as a transcript."** Every
  block in the artifact was produced by the command shown immediately above it, in
  the same shell invocation; §20 appends EX-02's independent receipt, which matches
  the pre-registered prediction 8/8. **Verdict: the artifact is checkable by a third
  party** (re-run any block; compare §19's prediction against EX-02's log), and the
  one block that could be mistaken for hindsight (§19's expectation) was written
  before the install landed — its content is falsifiable against EX-02's log and
  passed.
- **A5 "Path A (3.12) is the recommended route but EX-02 took Path B — does the
  census mislead?"** **Verdict: no — the census is what caught it.** §9–10 measured
  the cp314 gap before install, so when EX-02 took Path B the outcome was already
  pre-computed; the prediction table (§1) shows 8/8. Recommendation ranking stands
  (Path A is cheaper), but Path B is verified-viable, not a degraded fallback.
- **A6 "uv-managed interpreters are externally managed — maybe the whole uv path
  is blocked."** `uv pip install --python <managed-python>` errors ("managed by uv").
  **Verdict: refuted for the relevant route** — a venv created *from* a managed
  interpreter is fully writable; dry-run install into `/var/tmp/ex01-venv-demo`
  succeeded in ~1 ms. The error applies to writing the interpreter itself, which
  nothing needs.
