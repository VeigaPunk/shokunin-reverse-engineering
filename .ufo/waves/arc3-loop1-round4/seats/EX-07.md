- **3.1 Payload is the encoding-invariant identity.** Per family: one distinct
  payload across all legs, one distinct decoded `bytecode.sha256`; hex ≡ raw in
  every pin pair (all families). Creation blobs decode to the *creation* bytes

- **3.2 The `ev_` id is not.** 8 legs → 8 ids (CarrierV), 6 → 6, etc.; 0 id
  collisions between hex and raw at any pin. Payload equality holds while ids split
  — the r3 comparator advice (compare by decoded bytecode sha, not the id) is
  re-confirmed on a second compiler family.
- **3.3 Id domain (pre-registered, P1–P5 all held).** Same bytes at a different
  absolute path → different id (`ev_d3b50f8e…` vs `ev_d409bd50…`), same
  `subject.digest` (P1 ✓). Same bytes, same path, *different cwd / relative argv* →
  **same** id `ev_d409bd50…` and byte-identical envelope (P1/P5 ✓). Symlink input →
  typed refusal, `invalid_format`, "Expected a regular file without a symlink"
  (P2's expectation of a differing id was **wrong** — the tool refuses rather than
  hashing the link path; recorded as a corrected prediction, not a defect). raw on
  hex-text → exit 0, 0 functions, decoded sha == the hex file's own sha
  (`9a1fbfab…`), id differs (P3 ✓). bin-as-hex → typed refusal, "Hex carrier must be
  valid UTF-8" (P4 ✓, not the parsed-empty outcome). A bounded 900-combination hash
  sweep over path/encoding/bytecode-sha/subject-sha tuples found **0 hits** — the id
  formula stays underived; the honest-stop form stands.
- **3.4 Envelope delta is a 6.5.0 boundary, not 6.7.0-specific.** Across all six
  families: `relationship_coverage` absent at 6.4.0, present (`null`) at 6.5.0 and
  6.7.0; `limitations` 6 → 7 entries. The 6.5.0→6.7.0 envelopes are **byte-identical

- **3.5 Cross-round, cross-seat id re-derivation.** 4/10 same-path pairs are

- **3.6 Offset semantics is compiler-scoped.** solc carriers: 13/13, 13/13, 5/5
  offsets land on `0x5b` (JUMPDEST). Vyper carriers: **0/4, 0/15, 0/22, 0/9** land

  the reported offset, because Vyper dispatches through a codecopy'd table rather
  than a solc EQ/GT compare tree. The r3 entry's "offsets land on JUMPDEST" reading
