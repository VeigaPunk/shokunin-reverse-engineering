## 4. Attacks / refutations attempted, with verdicts

1. **Attack: does the recovered set merely echo the ABI I derived K from?** — Refuted as a
   defect concern: K was derived from *source text* with my own keccak, sealed pre-probe,
   and agrees with the compiler's `method_identifiers`. The probe read only the runtime
   hex, which carries no ABI. Verdict: independent; K/K is a real recovery result.
2. **Attack: are there false positives from non-dispatch PUSH4 constants?** — Measured:
   `CarrierV` carries 21 PUSH4 immediates / 16 distinct; the 16th is `08c379a0`
   (`Error(string)`), appearing 6×. The probe reported exactly the 15 planted selectors —
   **zero false positives**. Verdict: holds.
3. **Attack: does `__default__` (0x89402a72) appear as a function?** — Measured absent in
   both carriers' bytes entirely (`bytes.fromhex("89402a72") in code` → False for both
   `CarrierV` and `StewardToken`) and absent from the recovered sets. Vyper dispatches the
   fallback by fallthrough, so its inclusion in `method_identifiers` is a normalizer trap,
   not a recovery miss. Verdict: trap identified and documented.
4. **Attack: EX-03's K=23 vs recovered 22 — a missing selector?** — Refuted: three
   `method_identifiers` entries are leading-zero-dropped (`0x95ea7b3`, `0xc751377`,
   `0x6fdde03`); left-padding to 8 chars makes the comparison 22/22 MATCH. Verdict: second
   normalizer trap, measured, not a recovery failure.
5. **Attack: are the probe's `bytecode_offset`s dispatch targets?** — Refuted for this
   class: all 15 offsets are `entry_jumpdest + 12` (fall-through body entries), all
   preceded by `0x57` (JUMPI); **0/15 land on a JUMPDEST**, unlike r1/r3 solc carriers.
   I reconstructed the dispatcher at byte level and predicted all 15 offsets exactly:
   prologue `5f3560e01c`, `slot = selector % 13`, 13-entry uint16 table at `0x600`
   (all heads JUMPDESTs), per-entry `5b 63<sel> 81 18 61<next> 57`, body at +12. Verdict:
   the "offsets land on JUMPDEST" reading is **scoped to solc-convention carriers**;
   vyper's class differs.
6. **Attack: is `inferred_state_mutability` reliable on vyper?** — Refuted at this
   carrier. Agreement 7/15; the split is structural: **7/7 no-arg functions correct,
   8/8 arg-taking functions inferred `payable`** regardless of true mutability (view,
   pure, nonpayable all misread). Mechanism visible in bytes: no-arg bodies open with the
   bare guard `CALLVALUE PUSH2 JUMPI` (`346105fc57`), arg-taking bodies open with the
   combined `PUSH1 0x24 CALLDATASIZE LT CALLVALUE OR` guard (`602436103417`) — the latter
   does not separate value from size checking in the way the upstream inference expects.
   Also 3/15 `inferred_arguments` read `uint256` where the ABI declares `address`
   (arg *count* was correct 15/15). Verdict: selector recovery unaffected; inference
   degrades — recorded as a measured limit, not a recovery defect.
7. **Attack: is the raw-on-hex "parsed-and-empty" claim (r1/r3) reproducible on vyper?** —
   Confirmed: exit 0, 0 functions, decoded sha256 == the hex file's own sha256
   (`e0b1021c…`). Also confirmed the hex-on-bin trap is fail-closed (exit 1, typed
   `invalid_request` / `invalid_format`). Verdict: both traps reproduce on the new class.
8. **Attack: is the id path-sensitive (r3 reading) or content-addressed?** — Re-measured:
   same bytes + same request at the same path re-derive (`ev_d1792f57…` on rerun); the
   same bytes at a different absolute path mint a different id (my `ev_d1792f57…` vs
   EX-04's `ev_405e2a2a…`); shape variants (uppercase, `0x`) also mint fresh ids. Compare
   by decoded `bytecode.sha256`, never by id. Verdict: r3 reading holds for vyper too.
9. **Attack: do my envelopes actually agree with the sibling seat's independent probes?** —
   Normalized deep-diff against EX-04's `evidence/probe/probe-{6.4.0-hex,6.4.0-raw,6.7.0-hex}.json`:
   **0 content diffs** after stripping `evidence_id`/`local_path`/`name`/`parameters`/
   `locations`/`diagnostics`. Verdict: cross-seat agreement, independent capture.
10. **Attack: is the creation blob a dispatch carrier?** — Measured n=0 on
    `CarrierV` creation.hex; consistent with the r1 erratum (creation blobs do embed the
    runtime table) — tool scope, not byte-level absence. Verdict: parsed-and-empty.
