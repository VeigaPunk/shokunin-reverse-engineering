## Classification and re-dispatch protocol

**Observation:** All three committed artifact trees have 60 reports, and the same four IDs—E25, E26, E27, E28—are missing against the 64-ID round-1 baseline; no unexpected IDs appear. The aggregate round records claim 64 dispatches and 60 deliveries on one provider.

**Inference:** A systematic scope/roster/accounting boundary is the leading explanation: the same contiguous tail of E IDs disappears in three rounds. That is not proof. Repeated provider-side failure or a deterministic timeout boundary affecting those seats remains possible. The round-3 PE task’s 30-minute outer-cap cancellation (`SCORECARD.md:800-804`) is a different task outcome and is not evidence that E25–E28 timed out as dispatch seats.

**Unknown:** The committed round artifacts do not provide per-seat submission/acceptance IDs, provider terminal statuses, or per-seat timing/cancellation outcomes. They cannot distinguish “not in the dispatched scope” from “submitted but dropped/timed out” or “completed but report not persisted.” The 64-seat denominator for rounds 2–4 is stated by the records; the exact per-round manifest was not found in the inspected artifacts.

Recommended next-wave protocol:

1. Freeze a 64-row manifest before dispatch: unique seat ID, owner/task, provider, prompt digest, expected report path, and attempt number. Validate exactly 64 unique IDs against the intended roster before making the batch call.
2. Persist the raw batch receipt and one per-seat record (`not-submitted`, `accepted` + task ID, `provider-error`, `running`, `timed-out/cancelled`, or `completed`) at dispatch time. Do not use the provider’s aggregate “completed” count as a substitute for the ID map.
3. Reconcile manifest IDs against accepted task IDs, terminal results, and report files. Compute `missing = manifest IDs - completed report IDs`; classify each missing ID from its receipt. A missing file alone means unresolved, not provider failure or timeout.
4. For accepted/running IDs, poll status and wait for a terminal outcome before retrying. Recover completed output by task ID where possible. Re-dispatch only unresolved IDs, preserving the original seat ID and adding an attempt suffix; use the same provider first. Provider substitution requires the operator’s authorization. Keep the first attempt’s receipt and result/error alongside the replacement.
5. Close only at 64/64 unique reports, or list every unresolved ID with its evidence-based disposition as named debt. Never call 60/64 complete because the claims converged elsewhere.
