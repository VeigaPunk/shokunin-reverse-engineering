The scorecard records the same run and the native-worker/JVM memory split (`SCORECARD.md:894-901`). These are recorded R4 measurements; this report did not repeat the live run.

**Adjudication:** no accepted outcome demonstrates `HELD`; retaining `INCONCLUSIVE` is the calibrated call. The old next-step shorthand “contained, >5400s, deadline-only” is insufficient: R4’s 7200-second attempt hit memory first. A future attempt should first reduce analyzer-worker memory use (R4 identifies ten native workers as the dominant working-set component), or consider a larger memory cap only under an explicit host-safety limit; it still needs an outer wall limit that permits the intended REA deadline to fire. More time alone is not a justified fix.
