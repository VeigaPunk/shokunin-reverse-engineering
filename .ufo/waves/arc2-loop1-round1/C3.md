## 3. Verbatim text for the parent (fenced blocks; land as-is)

### 3.1 The gate — save to `/tmp/arc2-l1r1-C3-gate.sh` (rehearsed bytes; `check_append_only` checks the STAGED blob, i.e. exactly what `git commit` writes)

```bash
# arc2-l1r1 C3 append-only gate. Usage: . /tmp/arc2-l1r1-C3-gate.sh
#        check_append_only <path> [base-rev]      (base-rev defaults to HEAD)
check_append_only() {
  p="$1"; base="${2:-HEAD}"
  old=$(git rev-parse "$base:$p" 2>/dev/null) || { echo "FAIL $p: not in $base"; return 1; }
  size=$(git cat-file -s "$old")
  oldlines=$(git show "$old" | wc -l)
  ns=$(git diff --cached --numstat "$base" -- "$p")
  if [ -z "$ns" ]; then echo "FAIL $p: nothing staged vs $base (run: git add -- $p)"; return 1; fi
  added=$(printf '%s' "$ns" | awk '{print $1}'); deleted=$(printf '%s' "$ns" | awk '{print $2}')
  new=$(git rev-parse ":$p" 2>/dev/null) || { echo "FAIL $p: not in index"; return 1; }
  newsize=$(git cat-file -s "$new")
  hdr=$(git diff --cached -U0 "$base" -- "$p" | grep '^@@' || true)
  hunkcount=$(printf '%s\n' "$hdr" | grep -c '^@@' || true)
  pre=$(git show "$new" | head -c "$size" | git hash-object --stdin)
  echo "  $p: $old ($size B, $oldlines L) -> $new ($newsize B) +$added -$deleted hunks=$hunkcount"
  echo "  hunk: $hdr"
  [ "$deleted" = 0 ]         || { echo "FAIL $p: deletions present"; return 1; }
  [ "$hunkcount" = 1 ]       || { echo "FAIL $p: not exactly one hunk"; return 1; }
  [ "$newsize" -gt "$size" ] || { echo "FAIL $p: not strictly growing"; return 1; }
  [ "$pre" = "$old" ]        || { echo "FAIL $p: prefix not byte-identical"; return 1; }
  printf '%s' "$hdr" | grep -qE "^@@ -${oldlines},0 \+$((oldlines+1))," || { echo "FAIL $p: not EOF-anchored"; return 1; }
  echo "OK $p: EOF append, prefix byte-identical vs $base"
}
```

Equivalent one-liners if the parent prefers no script file:

```bash

[ "$(git show :<path> | head -c $size | git hash-object --stdin)" = "$old" ] && echo PREFIX-OK
```

## 4. Failure modes — reasoning (why each check is necessary and sufficient where claimed)

1. **In-place "correction" (the tempting edit: rewriting `:60`/`:136`).** Caught by `deleted != 0` and, independently, by `hunkcount != 1` (rehearsal D: `+4 -1 hunks=2`). This is the whole point of append-only: the historical bytes stay intact and the qualification is an addition.
2. **Mid-file insert (e.g. note placed beside the loci instead of at EOF).** Numstat is *clean* here — `+1 -0 hunks=1` (rehearsal E) — so deletions/hunk-count cannot catch it. **Prefix-identity is the only check that does** (`head -c old_size` of the new blob hashes differently). This is why prefix-identity is mandatory even when the diff "looks" additive.
3. **Insert before the final line (not EOF-anchored).** Caught by the `@@ -<oldL>,0 +<oldL+1>,N @@` anchor regex; also fails prefix-identity.
4. **Missing leading blank line.** Shape gate cannot see it (still one EOF hunk). Consequence: the note renders glued to the previous line ("…closed.- **Safety-verdict…"). Guard: the appended region's first byte must be `\n` (§3.2 step 6, `od -c`).
5. **CR/CRLF contamination from an editor.** Gate is byte-shape-blind inside the appended region. Guard: `grep -c $'\r'` over the appended region (rehearsed: 0). Risk is low here — autocrlf unset, no `.gitattributes`, no filters.
6. **Stale index / late edits.** If the parent edits the worktree after `git add`, the gate still passes on the stale staged blob. Guard: worktree==index (`git diff --quiet` per path, rc=0) plus, immediately before commit, `git rev-parse HEAD:<path>` vs `:<path>` identity after commit. Re-run the gate after **any** further `git add`.
7. **Duplicate append.** If the sequence is run twice (or after a partial earlier attempt), the second append is still a clean single EOF hunk and the gate **passes** (rehearsed). Guard: pre-flight marker count == 0 and post-stage count == 1 (§3.2 steps 0/6). The task instruction "If your own report file exists from the interrupted first attempt, overwrite it wholly" applies to reports, not to these files — but the same interrupted-wave reality makes the marker check essential.
8. **Committing unrelated staged content.** Guard: `git diff --cached --name-only HEAD` must list exactly the two paths, plus the repo-wide deletion sweep (any unrelated staged deletion would also surface there).
9. **Hooks/filters/autocrlf rewriting on commit.** Verified absent (no `.gitattributes`, autocrlf/eol unset, no active hooks, LFS configured but no patterns). Even so, the post-commit re-verify against `HEAD^` closes the loop: it proves the committed blob is an EOF-append of the base blob, whatever ran in between.
10. **File without trailing LF.** `wc -l` would undercount and the anchor regex could mis-fire; git would in fact render the last line as a `-`/`+` replacement → deletions catch it. Precondition verified: both files end `\n` at HEAD, so the gate's arithmetic holds.
11. **Binary misclassification.** If git treated either file as binary, numstat shows `-`/`-` → `deleted != 0` → FAIL (safe default). Not applicable: both are UTF-8 text (read in full this session).
