## Proposed rule #17

> **Evidence-ID field sensitivity belongs to an exact semantic-projection pointer, not a field name or a verb-wide constant.** For each operation, package version, and request shape, derive the actual Evidence projection. Test a candidate pointer with a same-path repeat, a same-byte alternate-path control, and (when claiming causality) a one-pointer-only mutation. Report exactly which projection pointers change the ID and which do not. If path-bearing fields co-vary in a copy control, report them as correlated until isolated. Distinguish display metadata at the outer envelope from the same-named value nested inside `normalized_result`; do not transfer a sensitivity result from one pointer, operation, or version to another.

This sharpens rule #15: a bare “path-sensitive” label is not enough to state *which* path field participates. The `inspect_artifact` measurement demonstrates why: the outer `subject.local_path` mutation is ignored, while a nested `normalized_result.substeps[0].evidence.subject.local_path` mutation changes the ID. In the EVM and Rust controls, the parameter, normalized-result, and location paths co-vary with alternate input paths, so their individual causality should not be claimed without isolation.
