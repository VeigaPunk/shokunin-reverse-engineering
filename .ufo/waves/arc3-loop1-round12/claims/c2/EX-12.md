## Proposed rule #17 — Path sensitivity is a semantic-projection property

Do not infer an Evidence ID's path sensitivity from the `ev_` prefix, another verb, or a domain-wide label. For the exact verb and call shape, inspect the Evidence semantic projection and the verb's evidence constructor; then compare a same-path repeat with a same-byte copy at another path, holding the package version and all non-path inputs fixed. Recompute IDs from the complete envelopes. Mutate candidate fields individually in memory to distinguish excluded display fields from path-bearing semantic fields, including fields nested inside `normalized_result`. Classify the result only for the tested verb, version, input class, and invocation shape. If a path-bearing field participates in that projection, treat IDs as path/invocation-specific and compare substantive results using the stable artifact digest and the relevant normalized payload; if only excluded display fields vary, do not call that path sensitivity. Leave untested shapes unknown.

**Why this adds depth to the existing rule:** `SKILL.md:86-107` already warns against substituting Evidence IDs across invocation shapes and calls identity verb-family-specific; `SKILL.md:383-397` also rejects a universal formula. This draft supplies the missing operational decision procedure: locate the path in the concrete projection, isolate it with controlled changes, and distinguish top-level display fields from nested semantic content. The three measured verbs below demonstrate why that distinction matters.
