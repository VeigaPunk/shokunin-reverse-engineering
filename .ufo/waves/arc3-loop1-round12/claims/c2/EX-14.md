## Proposed rule #17 (draft)

- **Derive field sensitivity from the exact outer Evidence projection, not from a field name or domain label.** When identity, correlation, or cache reuse depends on an input value (for example, path, version, or scope), trace that value into the operation's returned Evidence and record its exact JSON path in the outer semantic projection. Compare a same-path repeat with a same-byte alternate-path or controlled one-field probe, independently recompute the emitted ID with the pinned package canonicalizer, and include a negative control for fields excluded from that projection. Treat nested Evidence inside `normalized_result` as outer-projection data: a display field omitted from a nested Evidence ID can still affect its wrapper's ID. Do not transfer a sensitivity result to another operation, release, or invocation shape without re-deriving its projection. Earned by the distinct `inspect_evm_interface`, `inspect_rust_binary`, and `inspect_artifact` projections and path controls (`corpus/knowledge/2026-10-19-arc3-r7-evm-evidence-id-domain.md:17-22`; `corpus/knowledge/2026-10-19-arc3-r10-rust-evidence-id-domain.md:13-21`; `corpus/knowledge/2026-10-19-arc3-r11-inspect-artifact-evidence-id-domain.md:17-19`).

This addresses the C2 candidate that per-verb sensitivity is a projection property. The measured variation here is path sensitivity; version and scope sensitivity are not measured by this seat.
