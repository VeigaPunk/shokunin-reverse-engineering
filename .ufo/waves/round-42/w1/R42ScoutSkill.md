## 10. Defects and drift found (routed for the L1; none fixed here)

1. **Draft R41-CL4 wording.** The draft (:11-12) says the v3 table "sends every SquashFS v1–v3 chunk to `no-squashfs-chunk`". The v3 interpreter does not: row `no-squashfs-chunk` has handler `none`, which fails whenever the feature set H is non-empty (`sqfs-triage-v3.py:666-669`), and a v1–v3 chunk matches no `squashfs_v4_*` row, so the pair is `unclassified/none`. That is exactly what `corpus/knowledge/2026-10-26-r41-sqfs-triage-v3.md:22-25` and the routed row R41-CL4 say ("diverge"). `CTL-C2-0b` is written "`no-squashfs-chunk` or `unclassified`", which is consistent; the first sentence of the claim is not. `[INFERENCE]` the v3 **table** (before the interpreter) is also textually at fault: its `cause` cell says a v1–v3 chunk "is not a v4 chunk", which is the step-2 reading.
2. **Draft step 3 / `dep-missing-*` naming, from source** (`unblob/handlers/filesystem/squashfs.py:24-70`): `SquashFSExtractor.get_dependencies()` returns **both** `sasquatch` and `sasquatch-v4be` for every SquashFS handler; the spawned `Command` uses `sasquatch` for every handler **except** big-endian v4 (`sasquatch-v4be`); `get_endian` (`unblob/file_utils.py:350-361`) returns BIG only when the first four bytes equal the handler's big-endian magic (v3 `sqsh` 0x73717368, line 75; DD-WRT `tqsh` 0x74717368, line 323; Broadcom `qshs`, line 368; nonstandard `sqlz`, line 414), so any image starting with that magic (a DD-WRT `tqsh` image included) is read big-endian and a big-endian non-v4 chunk gets `-be`, a little-endian v1–v3 chunk gets `-le`, and both resolve plain `sasquatch`. So a missing `sasquatch` on a BE v3 chunk reads `D = {sasquatch}` and the draft's `dep-missing-le` wording would be a misnomer for it (the label states endianness the dependency name does not carry). The draft already flags "label wording may change"; this is the reason. The handler names in H for the family are: `squashfs_v1`, `squashfs_v2`, `squashfs_v2_nonstandard`, `squashfs_v3`, `squashfs_v3_ddwrt`, `squashfs_v3_broadcom`, `squashfs_v3_nonstandard`, `squashfs_v4_le`, `squashfs_v4_be`, `squashfs_v4_broadcom` (10; `squashfs.py` lines 102, 159, 200, 245, 319, 364, 410, 455, 514, 549).
