## Proposed `gap-rule.json` (r41 schema; file `C1GapRule/gap-rule.json`)

```json
{"claim":"R50-C1",
 "allowed":{"symlink":["unpublished-entry"],"char-device":["unpublished-entry"],"block-device":[],"fifo":["unpublished-entry"],"socket":["unpublished-entry"],"dir":[]},
 "required":{"symlink":true,"char-device":true,"block-device":false,"fifo":false,"socket":false,"dir":false},
 "removed":{"diagnostic":"MaliciousSymlinkRemoved","kinds":["symlink"],"disposition":"exclusive","silent":{"char-device":["247:0"]}},
 "structural":{"depth-limited":1,"unknown-chunk-handler":0}}
```
Deltas vs `.ufo/waves/round-41/c1/gap-rule.json`: (1) `claim` string (the r41 counter hard-fails on anything but `R41-C1`, `c1-counter.py:504` — the port must change it; my checker patches it in memory); (2) `char-device` goes from `allowed [] / required false` to `allowed [unpublished-entry] / required true / silent {"char-device":["247:0"]}`: the r41 rule accepts the real unprivileged tree too (checked) but (a) **false-fails a privileged run** where sasquatch does create the node and REA lists it as `special` (battery: "round-41 rule REJECTS a privileged-run device gap"), and (b) accepts a device row with *any* detail silently (battery: "ACCEPTS a device row with unlisted detail"); the proposal accepts exactly the observed silent row and the gapped alternative and nothing else. `silent` matches the exact `major:minor` the table holds (`silent_detail_matches`, counter `:1022-1037`); if `c6490`/`a7590` carry other devices the label list must grow before the freeze. (3) all other kinds are r41 parity because they were **not observed** in either carrier; I do not freeze claims about unseen kinds [INFERENCE only]. (4) `removed.silent.symlink` deliberately absent (no empty-target link exists; see table). (5) `structural.unknown-chunk-handler` is the F3 switch.
