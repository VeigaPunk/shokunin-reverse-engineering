- **Observation (`-O gas`, default — modulo-indexed jump table, the r4 class, re-derived on a second carrier):** head `5f3560e01c 6002 600e 82 06 6001 1b 61<06e2> 01 601e 39 5f 51 56` — `bucket = selector % 14`, table address `0x6e2 + 2·bucket`, two bytes copied to memory `0x1e`, `MLOAD`, `JUMP`. The 14-entry uint16 table occupies `0x6e2..0x6fe` (exactly the runtime tail; runtime end `0x6fe`); every entry is a JUMPDEST; 8 buckets are occupied and 6 carry the sentinel `0x6da` = `5b 5f 5f fd` (`JUMPDEST PUSH0 PUSH0 REVERT`). Each bucket opens a chain of `PUSH4 sel; DUP2; XOR; PUSH2 next; JUMPI` at a strict 11-byte stride; non-final legs jump to the next leg's JUMPDEST, the final leg jumps to the sentinel. 13 selectors over 14 buckets produce 5 collision buckets: 0 (`read_total`,`is_marked`), 3 (`withdraw`,`read_balance`), 4 (`read_fee`,`scale`), 8 (`deposit`,`mark`), 12 (`sweep`,`unpause`); all 13 chains re-walked selector-by-selector (`evidence/default-buckets.json`). - **Observation (`-O codesize` — a different class: perfect-hash bucket headers, 7-byte records, no selector immediates):** head `5f3560e01c 6005 61<0632> 601b 39 5f 51 …` copies a 5-byte header from `0x632` and computes a table index from it; the runtime tail from `0x632` to EOF is the dispatch data — a 5-byte header `a5 4e 06 37 0d` (`mask 0xa54e`, `bucket-table pointer 0x0637`, `count 13`) followed by **13 seven-byte records** `[selector 4B][handler target 2B][flag 1B]`; `0x637 + 13·7 = 0x692` = runtime end exactly (`evidence/codesize-table.json`). All 13 record selectors are the compiled set, all 13 targets are JUMPDESTs (true per-selector handler entries: e.g. `deposit→0x005b`, `pause→0x02e8`, `sweep→0x024f`). The flag byte tracks the ABI's arity/mutability classes exactly: `0x04` zero-arg payable (`deposit`), `0x05` zero-arg nonpayable/view/pure (4 functions), `0x25` one-arg (7), `0x45` two-arg (`scale`) — a dispatch metadata byte, measured, not inferred. So on this form the offset field has no per-function meaning; `push4_pc + 11` is not merely wrong here — there is no push4 site to apply it to. paris-codesize reproduces the same structure with `PUSH1 0`-for-`PUSH0` and shared offset 68.
