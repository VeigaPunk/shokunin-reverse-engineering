## 4. Attacks / refutations attempted, with verdicts

1. **"The extractor is a naive PUSH4-constant sweep."** Built an attack carrier whose
   source declares and uses two custom errors (`src/attack/CarrierBErr.sol`), so the
   optimized runtime embeds `245aecd3` (`NotOwner(address)`) directly and `1182d3d5` =
   `2305a7aa >> 1` — the halved form the compiler emits for the 2-arg error, with
   `(0x1182d3d5 << 225) == (0x2305a7aa << 224) = 0x2305a7aa000…0` verified numerically,
   and the unoptimized build carrying plain `2305a7aa` and no halved form
   (`attack/unopt-consistency.txt`). Verdict: **hypothesis refuted** — the probe reports
   8/8 with zero extras (`ev_bdc1db67…`), i.e. it does not read arbitrary 4-byte constants
   as functions. Residual: the compiler's reason for emitting the halved+`SHL 0xe1`
   gadget is not identified (cause unmeasured; the arithmetic identity is).
2. **"The optimizer is what changes the dispatch shape" (the round's framing risk).**
   Measured r1's 11-selector carrier compiled with the optimizer OFF: already GT-root
   binary. Boundary scan N = 4…12 in both modes: 6 → linear, 7 → binary, identical in
   both modes. Verdict: **refuted as an optimizer effect** — the topology is selector-count
   driven; the optimizer's measured effect is size and jump-destination width (PUSH1 vs
   PUSH2 dests). The freeze's honest-stop branch on "prologue class differs from r1's
   recorded classes" does not fire: every r3 carrier carries the r1 `5f3560e01c` idiom and
   the `60043610` guard.

   setting are the same object."** A/B diff: creation differs in exactly 30 bytes, all
   inside the metadata tail; code region identical; feeding the JS API the CLI's source
   unit name reproduces the CLI's bytes exactly (`ebb9121d…`). Verdict: **partially
   refuted** — code parity holds, but creation/runtime sha256 are unit-name-dependent;
   round receipts must state the unit name. This affects every compile receipt in this
   round, including EX-04's (their receipt states the pins but the unit name is visible
   only in their `solc-input-*.json`).
4. **Self-check on my own claim table.** Re-derived extras/missing/dispatch/bytecode
