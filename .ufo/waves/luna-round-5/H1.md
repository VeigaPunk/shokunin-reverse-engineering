## CLAIM
Audit all hexadecimal byte-size conversions in the assigned r4u-01, r2-firmware-probe, and r5-01 knowledge files; identify errors not already claimed by C05.

## METHOD
Read-only review and literal scan of the three files. Arithmetic command: `python3 -c 'values=[("0x1c01dc8",0x1c01dc8),("0x505b000",0x505b000),("0x1000",0x1000),("0x8000",0x8000),("0xff00",0xff00),("0xbc0000-0x400000",0xbc0000-0x400000)]; [print(f"{h} = {v:,} B") for h,v in values]; print(f"entropy span = {(0xbc0000-0x400000)/2**20:.2f} MiB")'` → `0x1c01dc8 = 29,367,752 B; 0x505b000 = 84,258,816 B; 0x1000 = 4,096 B; 0x8000 = 32,768 B; 0xff00 = 65,280 B; 0xbc0000-0x400000 = 8,126,464 B; entropy span = 7.75 MiB`. r2 scan `python3 -c 'import pathlib,re; p=pathlib.Path("corpus/knowledge/2026-10-13-r2-firmware-probe.md"); print(re.findall(r"0x[0-9a-fA-F]+", p.read_text()))'` → `[]`.

## FINDINGS
- `corpus/knowledge/2026-10-13-r4u-01-firmware-deep.md:41` misstates both `.fwimage` sizes: 29,358,536 should be 29,367,752 B; 84,242,432 should be 84,258,816 B. Both were already claimed by C05 (`.ufo/waves/luna-round-4/C05.md:5,9`), not additional.
- Other conversions check: `0x1000` signature blocks = 4,096 B (`r4u-01-firmware-deep.md:41,45`); entropy span `0x400000–0xbc0000` = 7.75 MiB, consistent with “~8 MiB” (`:71,73`); `0x8000` = 32,768 B (`r5-01-riscv-bypass.md:26,43`). `0xff00` = 65,280 B and has no decimal counterpart (`r5-01-riscv-bypass.md:76,78,94`). r2 lists no hex literals.

## THREATS
Textual arithmetic audit only; no firmware binaries or live REA probes were run. This verifies conversions, not source measurements.

## VERDICT
